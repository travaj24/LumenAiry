### Documentation drift made true

#### D3 — NumPy `through_focus_scan` H-hoist actually implemented

v4.12.0 release notes claimed the NumPy `through_focus_scan` hoisted input FFT, kx/ky, propagating mask, and target dtype outside the z-loop. The source code did not — it called `angular_spectrum_propagate` per z in a Python loop. v4.12.0's 4.7× speedup came from the underlying pyFFTW MEASURE auto-promote (Tracks #1+#2) inherited via `angular_spectrum_propagate`, not from any per-z hoisting.

**v4.12.2 makes the claim true.** Per-z work reduces to `H_z = where(propagating, exp(1j*kz_safe*z), 0) * bl_mask_z` then `fftshift(ifft2(ifftshift(E_fft_shifted * H_z)))`. Band-limit masks remain per-z (cached via the existing `_get_or_make_bandlimit`). Now both speedups stack.

Pinning tests use `unittest.mock` to assert `_fft2` is called exactly once across the entire scan (was `n_z` pre-fix). All 13 pre-existing bit-near-exact pins still pass.

#### D4 — `through_focus_scan_jax` JIT cache actually implemented

v4.12.0 release notes claimed `through_focus_scan_jax` jit-caches the inner ASM kernel. Source code had no `@jax.jit` wrap and no module-scope cache; every Python call re-traced.

**v4.12.2 makes the claim true.** Factored the inner `_asm_one_z` kernel out of the closure into `_build_through_focus_scan_jax_kernel(Ny, Nx, dx, wavelength, bandlimit, dtype_str)` which wraps `jax.vmap(_asm_one_z, in_axes=(None, 0))` with `jax.jit`. Module-scope `_THROUGH_FOCUS_SCAN_JAX_CACHE: OrderedDict` (LRU `maxsize=32`) caches the compiled kernel per signature. `clear_through_focus_scan_jax_cache()` exported.

Benchmark numbers (complex128, 7 z-planes):
- **N=64**: first **153 ms** → warm **1.97 ms** = **~77×** speedup.
- **N=128**: first **128 ms** → warm **4.95 ms** = **~26×** speedup.

#### 878× → ~300× warm-call `trace_jax` benchmark reconciliation

v4.12.1 release notes claimed `trace_jax` warm-call: **878×** at 127 ms → 0.40 ms. Those don't reconcile — `127/0.40 = 317×`, not 878×. Fresh measurement on a stable system state (1001-ray AC254-100-C-equivalent doublet, median of 20 warm calls, 5 passes):

- First call: **140 ms**
- Warm call: **0.47 ms**
- Speedup: **~300×** (range 293–314×)

Updated in `CHANGELOG.md`, `README.md`, `.release_notes_v4.12.1.md`, and the wiki `Release-Notes.md`. Regression-pin threshold in `tests/unit/test_audit_fixes_v4_12_1_trace_jax_cache.py::TestCacheWarmSpeedup` renamed and tightened from `>= 100×` to `>= 200×` to catch a regression sooner.
