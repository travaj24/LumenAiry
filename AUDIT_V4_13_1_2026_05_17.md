# Lumenairy v4.13.1 — Audit Report

**Date:** 2026-05-17
**Library state:** v4.13.1 tagged in git; v4.12.2 currently on PyPI.
**Scope:** Two-part audit:
- **Part A (Verification):** Confirm all 22 findings from `AUDIT_V4_13_0_2026_05_17.md` (7 P1 + 9 P2 + 6 P3) were actually closed in v4.13.1, and check the 12 documentation-drift items were retroactively fixed.
- **Part B (Forward-looking):** Find NEW issues — performance opportunities, API inconsistencies, fresh-eye bugs/physics, code-organization smells, test-coverage gaps, and under-audited modules.

**Methodology:** 9 parallel single-domain audit agents — 3 verification (V1/V2/V3) + 6 forward-looking (A/B/C/D/E/F) — with non-overlapping scope and explicit "do not re-find issues from `AUDIT_V4_13_0_2026_05_17.md`" instructions for the forward streams.

## TL;DR

**Verification: 22/22 audit findings closed.** 3 closures have minor PARTIAL caveats (P1-F: missing old-JAX guard in `RandomState.choice`; P2-3: `dual_annealing` callback not wired into cancellation protocol; P1-C: `Source.fiber_mode` carries dead `dy=` code path because `create_fiber_mode` doesn't accept it). The closures use the right pattern — parametrized dispatcher-level pins over every reachable variant — which structurally guards against repeats of the L4a meta-finding within those specific function families.

**Forward-looking: 12 new P1 findings.** Most importantly:

- **5 NEW sibling-gap recurrences** in modules that prior audits hadn't deep-dived — same "fix swept N sites, missed N+1" pattern as L4a, but in different code areas:
  - `vectorial_hfpi.py:399` is the unfixed sibling of v4.11.2's scalar HFPI RNG-correlation fix
  - `subaperture.py:299-309` is the unfixed sibling of v4.11.2's `hf.py` `decompose_lg(E_in, ...)` fix
  - `field.py:1095-1097` (`petzval_radius`) is the unfixed sibling of v4.11.2's Welford-mirror fix in `seidel_coefficients`
  - `jax_trace.py:649-669` is the unfixed sibling of v4.13.1's P1-A `apply_real_lens` mirror guard (only checks `is_mirror=True`, not `glass_after='MIRROR'`)
  - `apply_real_lens_traced_jax` / `apply_real_lens_maslov_jax` are the unfixed siblings of v4.13.0's L3 `dy` threading (no `dy=` kwarg)

- **5 fresh-eyes P1 bugs** that don't fit the sibling-gap pattern:
  - `apply_mirror` propagates NaN from out-of-domain sag to every pixel (no equivalent of `apply_real_lens:704-705` guard)
  - `_zero_C_air_gap` silently returns the placeholder thickness on degenerate ABCD
  - `propagate_to_plane` produces `inf`/`NaN` positions for grazing rays; downstream code reading `paths.positions` without masking by `alive` is poisoned
  - `RandomState.choice` int32/int64 mismatch across NumPy and JAX backends
  - `trace_prescription` mutates shared `Surface.thickness` in place when `image_distance=` is supplied

- **2 partial-closure follow-ups** also at P1 level: P1-F missing old-JAX guard; P2-3 `dual_annealing` callback not wired into cancellation protocol.

**17 forward-looking performance opportunities** found (top three: modal asymptotic per-pixel loop 20-100×; multi-merit meshgrid cache 5-10×; phase-retrieval `np.angle`/`np.exp` round-trip 2-4×) — all distinct from the 3 deferred candidates the v4.13.1 CHANGELOG already listed.

**12 API consistency findings, 22 structural recommendations, 14 priority new tests** identified. Bottom line for organization: the library is 80K LOC with 365 symbols in `__all__`, no unit-test CI job, no ruff/mypy gate, 8 active back-compat shims, 14 audit `.md` files in repo root, and 6 files over 2000 LOC each. Architectural housekeeping is the dominant follow-up class.

**P0 (silently-wrong physics): NONE FOUND across all 9 streams.** Sign conventions, Maslov branch tracking, Seidel σ-scaling, the new Shack-Hartmann H-build, and `apply_mirror`'s new xp-native inline-sag branch all verified mathematically. After 10 audit rounds the obvious sign errors are gone — what remains are conditional failures on edge inputs and sibling-gap recurrences.

**Verdict:** v4.13.1 is **stable and correct on the default paths**, but should not be tagged for PyPI until at least the 12 new P1s are triaged. Tier-0 fix surface estimate: ~130 LOC code + ~15 short tests (most of the 12 P1s are 1-15 LOC each with clear correctness pin sketches).

## Part 2 — New P1 findings (forward-looking)

12 new P1 findings across Streams V1, V2, V3 (residual partials), C, and F.

### 2.1 Sibling-gap P1 recurrences (5)

The audit-meta-finding from prior rounds — "fix swept N sites, missed N+1" — recurs in 5 new places.

#### P1-NEW-A — `vectorial_hfpi.py:399` — RNG-correlation, sibling of v4.11.2 scalar fix

`propagate_vector_hfpi_freespace_aperture` passes the SAME `rng` to both `init_vector_paths_from_field` AND `apply_vector_aperture_diffraction` without going through `_spawn_rng`. **The identical bug v4.11.2 fixed in scalar `propagate_hfpi_freespace_aperture` — the vectorial sibling was missed.** Cascaded aperture re-emissions are perfectly correlated with source-init draws, biasing the Monte Carlo result.

**Fix:** Port `_spawn_rng` from scalar HFPI. ~5 LOC. Add a test parametrized over `(scalar, vectorial)` for RNG-independence.

#### P1-NEW-B — `subaperture.py:299-309` — silent ignore of structured input, sibling of v4.11.2 hf.py fix

`propagate_subaperture_asymptotic` always passes `source_amplitudes={(0,0): 1.0+0.0j}` to `propagate_modal_asymptotic`. The input `E_in` is essentially ignored beyond `beam_d4sigma` waist estimation. Every patch gets identical plane-wave-equivalent unit fundamental. **Same bug v4.11.2 fixed in `hf.py` (added `source_lg = decompose_lg(E_in, ...)`); the subaperture sibling was missed.** Function is **functionally wrong for any non-trivial input** (off-axis Gaussian, vortex, Airy, etc.).

**Fix:** Port `decompose_lg(E_in, ...)` per-patch. Add a test that subaperture output of a non-trivial `E_in` is not equivalent to the identical-everywhere unit-amplitude case.

#### P1-NEW-C — `field.py:1095-1097` — `petzval_radius` silently drops mirrors

`petzval_radius` skips surfaces where `n1 == n2`. But `surfaces_from_prescription` returns mirrors with `glass_after == glass_before`, so `n1 == n2` and the function silently drops every mirror's Petzval contribution. **`seidel_coefficients` was fixed in v4.11.2 (Welford `n2 = -n1` convention); `petzval_radius` was not.** Wrong by 100% for catadioptric / Cassegrain designs where mirrors dominate Petzval.

**Fix:** Apply the same Welford-mirror convention. Add a regression test using a Cassegrain prescription comparing `petzval_radius` against the analytic value.

#### P1-NEW-D — `jax_trace.py:649-669` — `_build_jax_prescription` missing `glass_after='MIRROR'` guard

Refuses `is_mirror=True` correctly but does NOT check `surfaces[i].get('glass_after', '').upper() == 'MIRROR'`. Hand-built prescriptions with the Welford-style mirror-via-glass-string form slip past this guard and silently get traced as refractive air→air surfaces. **The v4.13.1 P1-A fix to `apply_real_lens` added BOTH guards together — the JAX prescription builder only got one.**

**Fix:** Add the case-insensitive `glass_after` check. Update the `TestL4aMirrorGuardDispatcherPin` parametrize list to include `_build_jax_prescription` (or add a new dispatcher pin for the JAX-prescription builder family).

#### P1-NEW-E — `apply_real_lens_traced_jax` / `apply_real_lens_maslov_jax` lack `dy=None`

The two NumPy `apply_real_lens` variants and the NumPy `apply_real_lens_maslov` accept `dy=None`; the JAX twins do not. An anamorphic prescription that round-trips through `Source.dy → propagate_through_system → apply_real_lens_traced_jax` silently drops the y-pitch at the JAX boundary. **The v4.13.0 L3 sweep added `dy` everywhere in NumPy paths but missed the JAX twins.**

**Fix:** Add `dy: Optional[float] = None` to both JAX variants. The JAX path enforces square grid via `raise ValueError` at `_lens_jax.py:444` — this contract is currently undocumented; either accept `dy != dx` or document the limitation clearly. Add a `Source.gaussian(dy != dx) → propagate_through_system_jax → apply_real_lens_traced_jax` test asserting dy preservation OR clear ValueError.

### 2.2 Fresh-eyes P1 findings (5)

Bugs that don't fit the sibling-gap pattern.

#### P1-NEW-F — `apply_mirror` propagates NaN from out-of-domain sag to every pixel

`elements/elements.py:180-195`. For a curved mirror with conic such that `(1+k)*h²/R² >= 0.9999`, sag = NaN → phase = NaN → exp(1j*NaN) = NaN → `E *= NaN`. NaN propagates to every pixel during the subsequent ASM step — there is no aperture mask in `apply_mirror`. **`apply_real_lens:704-705` has the equivalent NaN-zeroing guard; `apply_mirror` does not.** Trigger: a hyperbolic mirror with `conic < -1` at `h ≈ R/sqrt(|1+k|)`.

**Fix:** Add `if bool(xp.any(xp.isnan(opd))): opd = xp.where(xp.isnan(opd), 0.0, opd)` after the sag computation, matching `apply_real_lens`. ~3 LOC. Add a test using a hyperbolic mirror prescription that hits the domain boundary.

#### P1-NEW-G — `_zero_C_air_gap` silently returns placeholder for degenerate ABCD

`optimize/multiconfig.py:206-207`. When `abs(C1 - C0) < 1e-30`, the function returns `g1` — the **placeholder thickness from the input prescription**, not an afocal solution. Callers (`beam_expander_prescription`, `keplerian_telescope`) catch only specific exceptions; this no-exception fallback silently produces a non-afocal beam expander. Failure mode: two lens groups with zero combined power yields the user's input "first-guess" gap regardless.

**Fix:** Raise `RuntimeError("afocal gap solve is degenerate; ABCD's C element is field-independent in this geometry")` so the caller's `except RuntimeError:` actually fires. ~2 LOC.

#### P1-NEW-H — `propagate_to_plane` produces inf/NaN positions for grazing rays

`propagators/hfpi.py:215-219` and `vectorial_hfpi.py:177-179`. For `Nz ≈ 0` and `z_target ≠ z_curr`, the divisor is `1e-30` → `t ≈ 1e30` → `new_positions += 1e30 * direction = inf`. The alive-mask correctly tags these dead, **but `paths.positions` still contains inf/NaN**. Downstream code reading positions without masking by `alive` is poisoned. `_hfpi_segment_trace:875` is such a site (does `pos_h = np.asarray(paths.positions ...)`).

**Fix:** `t = xp.where(new_alive, t, 0.0)` before computing new positions, OR overwrite inf/NaN with the pre-step value on dead rays. ~3 LOC.

#### P1-NEW-I — `RandomState.choice` int dtype mismatch JAX vs NumPy

`backend/random.py:153-155`. JAX path returns `int32` (default for `jax.random.randint`); NumPy path returns `int64`. Downstream `array[choice_result]` may dtype-mismatch in vector ops on JAX → NumPy crossings.

**Fix:** Pass `dtype=jnp.int64` to `jax.random.randint`, OR align both branches on `int64`. ~1 LOC.

#### P1-NEW-J — `trace_prescription` mutates shared `Surface.thickness`

`raytrace/core.py:2096-2105`. When `image_distance=` is supplied, `trace_prescription` does `surfaces[-1].thickness = image_distance` in place. The `Surface` dataclass is not frozen and is shared with `surfaces_from_prescription`; downstream calls reuse a corrupted thickness. Compare to `lens_abcd` which correctly uses `_surface_copy_with(...)`.

**Fix:** Use `surfaces[-1] = _surface_copy_with(surfaces[-1], thickness=image_distance)`. ~2 LOC. Add a regression test where the same prescription is used twice with different `image_distance` arguments and the second call's result is not contaminated by the first.

### 2.3 Partial-closure follow-ups (2)

#### P1-NEW-K — P1-F missing old-JAX guard (carryover from verification)

`backend/random.py:150-155`. Per V2 above: code correctly handles JAX 0.10.0+ but lacks the `try/except`-around-`jax.random.choice(..., replace=False, p=None)` safety net the CHANGELOG implies. Pre-0.4.x JAX would raise.

**Fix:** Wrap the call in `try: ... except TypeError:` with a clear error message naming the JAX version requirement. ~3 LOC.

#### P1-NEW-L — P2-3 dual_annealing callback unwired (carryover from verification)

`optimize/core.py:3213-3217`. Per V3 above: unnamed inline lambda doesn't poll `is_cancelled(progress)`. Cancellation latency unbounded for `dual_annealing`.

**Fix:** Replace the inline lambda with a named callback matching the pattern at `:3125-3145`. ~5 LOC.

## Part 3 — Performance opportunities (Stream A)

17 new perf opportunities, distinct from the 3 deferred candidates already in the v4.13.1 CHANGELOG.

### High-impact (>5× expected on the hot path)

#### Opportunity #1 — `propagate_modal_asymptotic` per-pixel Python loop

`propagators/asymptotic.py:1937-2057`. N×N iterations (256² = 65,536 pixels) each performing Newton solve + 2×2 det/inv + `gaussian_moment_table_2d` + nested polynomial loops in Python.

**Approach:** Vectorise the per-pixel `_compute_M_b` and Newton solve across all valid output pixels at once. 2×2 `M`/`M_inv`/`det_M` trivially batches as `(N², 2, 2)`. Moment-table calls collapse to a single `(N², 2, 2)` linalg.inv. Maslov branch tracking stays as a Python scan over `arg(det_M)` (the only sequential dependency).

**Expected speedup:** 20-100× on N=128² grids in single-LG-mode case. 5-10× on large mode dictionaries.

**Correctness pin:** Hand-build a 4-mode LG_{0,0..2,0} prescription; per-pixel reference vs vectorised < 1e-12 rel; existing `aberration_tensor_lg00_jax matches NumPy` cross-backend pin still holds.

#### Opportunity #2 — `MultiWavelengthMerit/MultiFieldMerit/ToleranceAwareMerit` per-trial meshgrid rebuild

`optimize/core.py:2005-2018, :2112-2125, :2406-2408`. Each call rebuilds `np.indices((N,N))` / `meshgrid` / aperture mask / Y-tilt phase base. For 5-wavelength × 5-field × 40-FD-eval at N=512 that's 1000 N×N meshgrids per opt step.

**Approach:** Cache on `(N, dx, aperture)`. Per-leg work reduces to `np.exp(1j * k0 * sin_a * Y) * aperture_mask`.

**Expected speedup:** 1.5-3× per leg, 5-10× under FD-gradient pattern.

**Correctness pin:** Pure caching of pure functions; identity-equal across optimization run.

#### Opportunity #3 — NumPy phase-retrieval `np.angle` / `np.exp(1j*angle)` round-trip

`analysis/phase_retrieval.py:193-214` (GS), `:358-373` (ER), `:518-533` (HIO). Per iteration: `F = ...; far_phase = np.angle(F); far_field = target_scaled * np.exp(1j * far_phase)` — two transcendentals (atan2, cos+sin) per pixel per iteration. 200-iter × N=512² × 4 trig ops eliminated.

**Approach:** Replace with `F * (target_scaled / np.where(abs(F) > 1e-30, abs(F), 1.0))`. Algebraic identity. Already JAX-fused on the JAX path; NumPy lacks the optimization.

**Expected speedup:** 2-4× on NumPy GS/ER/HIO.

#### Opportunity #4 — `coating_reflectance` wavelength loop

`elements/coatings.py:95-263`. After v4.13.0 the per-layer matrix tournament reduction is vectorised, but the outer Python loop over wavelengths rebuilds the entire `(n_layers, 2, 2)` Mj stack per wavelength. 50 layers × 200 wavelengths = 200 builds.

**Approach:** Add wavelength batch axis to `delta_list` / `eta_list` as `(n_wv, n_layers)`; build `Mj` as `(n_wv, n_layers, 2, 2)`; tournament reduction collapses over layer axis → `(n_wv, 2, 2)`.

**Expected speedup:** 5-15× for broadband sweeps.

#### Opportunity #5 — `decompose_lg`/`decompose_hg` per-mode rebuild

`propagators/asymptotic.py:2110-2114, :2142-2146`. Per-mode `evaluate_lg_mode` rebuilds the entire (p, ell) mode and integrates. 28 full N×N rebuilds for (p_max=4, ell_max=3); shared `exp(-(X²+Y²)/w²)` Gaussian envelope discarded between modes.

**Approach:** Build `(N_modes, Ny, Nx)` mode stack once per `(w, cx, cy)` signature; single `np.einsum('mny,xy->m', modes_conj, field) * da` reduction. Envelope shared; only polynomial factors vary.

**Expected speedup:** 3-8× on typical decompositions.

#### Opportunity #7 — Shack-Hartmann measurement-pass gather loop

`analysis/detector.py:451-457`. K-iteration Python loop over `E_batch[k] = E[r0:r0+sa_pixels, c0:c0+sa_pixels]`. At K=4096 sa=8, that's 4096 array slices each copying 64 elements.

**Approach:** Vectorised gather via fancy indexing: `rows = r0_grid[iy_idx, None, None] + np.arange(sa_pixels)[None, :, None]`; `cols = c0_grid[ix_idx, None, None] + np.arange(sa_pixels)[None, None, :]`; `E[rows, cols]` is the entire `(K, sa, sa)` batch in one call.

**Expected speedup:** 5-15× on the gather step. At K=4096 reduces ~20ms to ~1.5ms.

#### Opportunity #8 — `_evaluate_polynomial_4d_and_grad34` Python loop

`elements/lenses.py:860-893`. M=70+ basis-term Python loop computing fused multiply-add over the evaluation grid. Used inside `apply_real_lens_maslov` Newton iterations.

**Approach:** Same vectorised pattern as sibling `_evaluate_polynomial_4d` at `:820-857`. Three `np.tensordot(coeffs, basis_*, axes=([0], [0]))` calls.

**Expected speedup:** 3-5× on Maslov stationary-phase iterations.

### Mid-impact (2-5×)

## Part 9 — Final verdict

**v4.13.1 closes its scoped audit objectives correctly.** 22/22 v4.13.0 findings closed; the closures use the right structural pattern (parametrized dispatcher-level pins) which guards against future recurrence within each fix family. 3 closures have minor PARTIAL caveats (P1-F missing old-JAX guard; P2-3 dual_annealing callback unwired; P1-C fiber_mode dead-dy-code-path) but none materially break the headline closure claims. The library passes 654 unit tests + 314 validation tests.

**Forward-looking, v4.13.1 has 12 new P1 findings** — five of which are sibling-gap recurrences in modules prior audits hadn't deep-dived (vectorial_hfpi, subaperture, petzval_radius, JaxPrescription mirror guard, JAX lens-twin dy). The audit-meta-finding that "fix sweeps almost always miss one site" continues to hold across the codebase, not just within recently-touched modules. The right counter-measure scales the parametrized dispatcher-pin idea outward: write one pin per fix that runs over every reachable variant, on every fix.

**P0 (silently-wrong physics) findings: 0 across all 9 audit streams.** The fundamental physics is correct; sign conventions hold end-to-end; Maslov branch tracking is preserved; the new Shack-Hartmann H-build matches the canonical propagator bit-for-bit; the v4.13.0 Seidel σ-scaling is mathematically sound. After 10 audit rounds the obvious physics bugs have all been caught.

**The next investment should be process gates, not more audit rounds.** The remaining issues are organizational (oversized files, missing CI lint/type-check, 8 active back-compat shims, public API surface > 365 symbols) and structural (3 sibling-family classes that need parametrized dispatcher pins). All addressable through pre-commit hooks, ruff/mypy CI, and a v5.0 cleanup pass — not through another fresh-eyes audit.

**Tagging recommendation:** Hold v4.13.1 → v4.13.2 PyPI tag for ~1 day to close Tier-0 (12 P1s, ~62 LOC + 12 tests). Push Tier-1 perf wins to v4.14.0. Push Tier-2/3/4 organizational + infrastructure work to v5.0 with a coordinated breaking-change announcement. **v4.13.1 is safe for users running from git clone**; PyPI tag should wait for the Tier-0 closures.

The fundamental engineering remains solid. The remaining work is well-scoped, mostly small per-item, and aimed at last-mile completeness rather than core correctness.
