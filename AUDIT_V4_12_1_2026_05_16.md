**Date:** 2026-05-16
**Scope:** Combined audit covering (a) all round-5 v4.12.0 pre-PyPI findings (A1-A5, D1-D4, S1-S3, L1-L8) with their original evidence AND their v4.12.1 closure status, plus (b) v4.12.1-specific verification of the three v4.12.0 deferred-item closures (Newton spherical fast-path, B1-10 grid unification, `trace_jax` cache via `JaxPrescription`), 14 round-4 coverage-gap tests, performance-claim verification, and weak-test strengthens.

**Method:**

- v4.12.1 source: 6 parallel single-domain agents on the v4.12.0 → v4.12.1 diff.
- Wrong-reason test rate trajectory: 33% (round 3) → 22% (round 4) → 3% (round 5) → unchanged in v4.12.1.

## TL;DR

**v4.12.1 closes its three v4.12.0 deferrals correctly and ships 21 coverage-gap regression tests, two genuine weak-test strengthens, and a clean validation-harness bare-except removal.** Newton spherical fast-path, B1-10 half-pixel grid unification, and `trace_jax` cache via `JaxPrescription` all do what the release notes claim, with pinning tests that match the documented critical values. 453/453 unit tests pass. The physics correctness work is solid.

**However, v4.12.1 leaves 4 of 5 round-5 pre-PyPI release blockers unfixed**, plus all 3 silent-data-loss bugs (S1-S3), plus all 8 latent/structural items (L1-L8), and **A5 has been actively regressed** by the new unbounded `_TRACE_JAX_CACHE` that follows the same anti-pattern round-5 flagged for `_PROPAGATE_SYSTEM_JAX_CACHE`. Two of the four documentation-drift items (D3, D4) also still ship false claims; D1 (B1-10) is partially closed by v4.12.1 finally shipping the documented fixes.

**One arithmetic inconsistency in the v4.12.1 release notes**: the headline `878×` warm-call `trace_jax` speedup doesn't reconcile with the documented absolute timings (`127 ms → 0.40 ms = 317.5×`, not 878×). The regression pin asserts only `≥100×` so it does not disambiguate.

**Verdict:** v4.12.1 is **safe to use** on its scoped objectives but is **NOT yet ready for the PyPI tag**. Round-5 A1/A2/A3/A5 remain (~30 min of fixes), the new cache regresses A5 further, and the 878× headline needs reconciliation.

### 1.1 Newton spherical fast-path — `lumenairy/raytrace/core.py` (+83 lines)

**Verdict: CLEAN. ✅**

The v4.12.0 revert was driven by a `1.17e-3` NumPy↔JAX drift on `aberration_tensor_lg00_jax` traced to the analytic-normal change. v4.12.1 keeps only the Newton-skip portion (the main cost saving) and reverts the analytic normal back to the legacy numerical-radial-derivative-based `_surface_normal`.

**Sibling check:** ✅ The JAX twin `_intersect_jax` was already pure-quadratic on the spherical branch (since v4.7.0) and is unchanged. The always-differentiable `_intersect_jax_param` retains Newton (deliberate choice for grad flow) with a documented ~10% overhead.

**Trade-off:** 1.50× vs the 1.64× v4.12.0 attempted. The remaining ~0.14× from the analytic-normal change is permanently sacrificed for cross-backend rounding stability — correct trade per the discipline lesson from C-LR-1 (round-3).

### 1.3 `trace_jax` cache + `JaxPrescription` pytree — `lumenairy/raytrace/jax_trace.py` (+481 lines)

**Verdict: CORRECT ON CRITICAL CORRECTNESS AXES, with 5 follow-up items. ✅ with caveats**

#### What's correct

- **Pytree registration is sound.** `JaxPrescription` (line 534) is registered via `jax.tree_util.register_pytree_node` with numeric leaves (radii, conics, thicknesses, asph coeffs) flowing through tree-flatten/unflatten, and categorical aux (glass names, surface flags, asph powers) forming a hashable cache key. `tree_flatten/tree_unflatten` are symmetric — round-trip preserves structure.
- **Registration is idempotent and JAX-availability-gated.** `_register_jaxprescription_pytree` (lines 602-617) catches `ValueError` for hot-reload double-registration and no-ops when JAX is unavailable.
- **Tracer-bypass guard is correct.** `_running_under_trace` walks every leaf of the pytree (not just the root) via `jax.tree_util.tree_leaves` and checks `isinstance(x, jax.core.Tracer)`. When any leaf is a tracer, the function bypasses `_TRACE_JAX_CACHE` entirely and calls `_trace_body_traced` directly. This preserves v4.11.2 grad semantics — the calling transform owns the trace.
- **JAX-bug hypothesis verified.** v4.12.0's NaN was traced to a JAX bug: `jax.jit` wrapping `trace_jax` + downstream `jnp.linalg.lstsq` backward produces NaN in `dot_general` for near-rank-deficient matrices (the canonical-poly 4-D Chebyshev basis triggers it). The v4.12.1 design (concrete-leaves cached path + tracer-bypass path) sidesteps this without losing the cache speedup on the static-prescription case.
- **Critical regression pin lands.** `test_grad_finite_v4_12_0_regression` (line 103-144) asserts `1e2 < |grad| < 1e6` on the `jax.grad(fit_canonical_polynomials_jax)` output — the v4.12.0 NaN failure mode cannot recur silently. The release-note value `grad = 1.0274e+04` sits in the middle of the assertion range.

#### Follow-up items

1. ❌ **`_TRACE_JAX_CACHE` is unbounded** (line 861: `Dict[Any, Any] = {}`). Same anti-pattern round-5 flagged as L1 for `_PROPAGATE_SYSTEM_JAX_CACHE`. An optimizer that iterates over different prescriptions (e.g. tolerance Monte-Carlo) creates a new entry per iteration → 1000-trial MC accumulates 1000 compiled XLA binaries. Should be `OrderedDict` with LRU eviction and a max-size cap.

2. ❌ **`_TRACE_JAX_CACHE` is NOT cleared by `clear_asm_caches()`** (`propagators/propagation.py:665-672` only clears `_FREQ_GRID_CACHE`, `_BANDLIMIT_CACHE`, `_H_CACHE`). No public `clear_trace_jax_cache()` is exported. Users must reach into the private `_TRACE_JAX_CACHE` symbol to clear it.

3. ❌ **`lumenairy_context(clear_caches_on_exit=True)` does NOT clear the new cache** (`_context.py:235-237` only calls `clear_asm_caches()`).

4. 📝 **`trace_jax_with_params` does not use `JaxPrescription`** (lines 1210-1347 walk the prescription inline per call). This is **intentional** — `trace_jax_with_params` is the always-differentiable path. But it's not documented in the release notes; a user expecting the `878×` speedup to extend to the param path will be disappointed.

5. 📝 **`JaxPrescription` not re-exported from `lumenairy.__init__`**. Release notes use the submodule path `from lumenairy.raytrace.jax_trace import JaxPrescription` so this is internally consistent, but `import lumenairy as la; la.JaxPrescription` raises `AttributeError`. Minor UX papercut for a cache-knob class.

**Test count:** 16/16 tests in `tests/unit/test_audit_fixes_v4_12_1_trace_jax_cache.py` pass.

### S2. `io/codegen.py` aperture-stop drop + 1.31µm wavelength default

**Round-5 evidence:** Docstring at line 275 promises `type='aperture'` step emission and the generation paths handle it (lines 616-623, 775-778) — but `_decompose_prescription` **never emits one**. Zemax prescriptions with `STOP` or zero-thickness aperture surfaces will lose the stop in the generated script → wrong simulation downstream. **High-traffic codepath** for the "import-from-Zemax" workflow that the README cookbook advertises.

Plus `io/codegen.py` silently defaults `wavelength = 1.31e-6` (1310 nm) with no warning when neither user nor prescription supplies one. Users converting visible-band Zemax files get NIR scripts.

## Part 5 — Round-5 latent/structural concerns (L1-L8) with v4.12.1 status

### L1. `_PROPAGATE_SYSTEM_JAX_CACHE` unbounded `Dict` — will leak under iterative optimization

**Round-5 evidence:** `system.py:495` — plain `Dict`, no eviction, no cap, no public `clear_*` function. Key is `(sigs_tuple, wavelength, dx, dy)` where `sigs_tuple` carries floats. An optimizer that varies any of `z`, `f`, `xc`, `yc`, `wavelength`, `dx`, `dy` per iteration creates a new cache entry per iteration → **1000-iter Newton loop accumulates 1000 compiled XLA binaries.**

Release notes claim "Module-scope **OrderedDict** caches" — these are plain `dict`. Fix: convert to OrderedDict + `_MAX_CACHE_SIZE = 32` LRU eviction; add `clear_jax_caches()` public function; wire into `clear_caches_on_exit=True`.

**v4.12.1 status:** ❌ **Untouched and replicated.** `system.py:495` still plain `Dict[Any, Any]`. **v4.12.1 adds `_TRACE_JAX_CACHE` following the same anti-pattern (`raytrace/jax_trace.py:861`).**

### L2. `set_default_complex_dtype` silently ignored on JAX path

**Round-5 evidence:** `system.py:833` hard-casts `jnp.asarray(E_in, dtype=jnp.complex64)`. `phase_retrieval.py:600` does `.astype(jnp.complex64)`. User running `set_default_complex_dtype(np.complex128)` then calling a JAX path gets float32-precision answers with no warning.
