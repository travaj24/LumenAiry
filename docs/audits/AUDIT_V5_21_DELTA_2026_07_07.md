## 1. Executive Summary

The v5.21 batch is a **faithful, high-quality implementation of the 2026-07-02
audit ledgers** — every P1/P2 item verified landed, most with adversarial-review
hardening beyond what the audits asked for — plus a large amount of new
capability (Levin quadrature, multibranch caustic traced, analytic differential
ray tracing, carrier-referenced traced, CSP/vector/coated GBD, conical PMM,
pure 2-D PMM stack, Li-2003 tensor FFF).  Highlights:

* **All Maslov fixes verified**: input-NA chart sizing with measured-spectrum
  auto + coverage/NaN/horizon guards (N3); linear-OPD re-application split
  exactly into an in-integral v₂ part and an exact output post-multiply with
  prism-tilt Nyquist handling (N4); banded **and** Kronecker-factorized
  quadrature (F2/M-P2, `_QUAD_ROW_BAND`/`_QUAD_FACTORIZE`); auto `n_v2` and
  `integration_method='auto'` driven by the fitted v₂-oscillation bound (N2/A1);
  suite progress protocol (F3); numba + CuPy kernels (M-P4); Gram-Cholesky
  stacked-RHS fits with sweep reuse (M-P5); `roi=` + `output_plane_distance`
  composed free-space leg (M-P6); `poly_order='auto'` on a held-out ray split.
* **Carrier-referenced traced landed** (companion-review §5.1): `carrier=`
  (conjugate float / wavefront array / `'auto'` curl-free intensity-weighted
  potential fit), the `on_noncollimated={'warn','delegate','off'}` guard using
  the **carrier-residual** discriminator, and a segmented multi-carrier sum —
  plus a separate **multibranch** (through-focus/caustic) traced solver with
  KMAH counting and Ludwig uniform-fold handling.
* **A real bug my 2026-07-02 PMM/RCWA audit missed was found and fixed by the
  team's own oblique oracle**: the staggered 2-D far-field projection kernel
  used `e^{-imGx}` with no Bloch shift — a **mirror** (physical order −m
  deposited into slot m; exact at normal incidence, wrong per-order kz flux at
  oblique) — root cause of the historical "A|B multilayer blows up" defect.
  Fixed with the α₀-shifted conjugate kernel + pinned oracle test (§3.1).
  Recorded here for audit-process honesty.
* **New findings in the new code**: the conical PMM entries **and**
  `PMMStack._solve_conical` skip the suite-standard incidence/grazing guards
  (D1); the GBD per-surface path can pass NaN beamlets from FD-Jacobian

  multibranch KMAH parity closure is mod-2 only — an even in-glass caustic
  count yields a π branch error while the docstring claims closure (D3); the
  berreman JAX twin routes traced OOP tensors to the ~2%-off native cascade,
  the opposite of the (correct) traced-routing fix rcwa got this release
  (D12); plus smaller items (D4–D11, D13–D15).
* **Key math independently re-verified this pass**: the Li-2003 successive
  tensor factorization (`_li_axis_tensor` / `_li_convolutions_2d_tensor(_full)`)

  all-plus sign convention differs from the textbook form in two places that
  **cancel exactly** on reassembly, and the diagonal limit reduces to
  inverse-rule-normal / direct-rule-tangent as required; the berreman
  OOP-oblique reroute's conjugation bridges and flux bookkeeping (longitudinal
  `rz/tz` from div D = 0, `einc²` normalization) check out.
* **No regressions found** in the remediation code itself; the
  `symmetry='auto'` default flip is defensible (documented ~1e-12
  non-bit-identity, bit-identical fallback on any failed precondition), and
  the sweep threading is race-clean (private clones, lock-guarded caches,
  thread-local BLAS caps, JAX forced serial).

## 3. Corrections to the prior audit record

### 3.1 Staggered far-field kernel mirror (missed on 2026-07-02)
`twod_staggered._stag_fourier_projection` used the kernel `e^{-imGx}` with no
Bloch shift.  Against the τ-glued Bloch basis this is a **projection mirror**:
physical order −m lands in slot m and each |m|>0 order gets the other order's
kz flux factor.  Exact at normal incidence and for reflection-symmetric cells
(why it survived every existing test — and my full read of the file), several-%
energy error at oblique on asymmetric cells, and the root cause of the
historical "pure-stack A|B blows up" defect (previously mis-attributed to
interface mode sorting).  v5.21 fixes the kernel to `e^{+i(mG+α₀)x}`
(`07ca820`), pins it with an asymmetric-cell oblique oracle, and unlocks
`PMM2DStackPure` multilayers.  My 2026-07-02 audit read this function and
flagged only the dead `xb[seg]` statement — the sign/mirror escaped both the
audit and the pre-existing test suite; only a per-order oblique oracle caught
it.  Lesson recorded: far-field/projection kernels need per-order oblique
asymmetric-cell oracles as a standing test pattern, not symmetric normal-
incidence checks.

### 3.2 The Maslov "quadrature is unusable" framing
v5.21's data confirms the companion review's assessment: with auto-`n_v2` and
the factorized/banded evaluation, uniform quadrature is now the *robust
default* below the oscillation cap (it is exact and caustic-safe), with the
asymptotic evaluators auto-selected only in the very-oscillatory regime.

## 4. New findings (this delta)

### D1 (P2) — `pmm/conical.py` entries skip the suite-standard guards
Neither `pmm_jones_1d_conical` nor `pmm_jones_1d_conical_tensor` calls
`_require_propagating_incidence` or `_grazing_safe_wavelength` (every other
PMM/RCWA entry point has both; cf. `twod._pmm2d_solve_core:627-631`).  A
wavelength on an exact Rayleigh cutoff, or a gain/evanescent superstrate,
re-opens the audited kz_inc→0 / negated-efficiency failure modes on exactly
these new entries.  **Confirmed to extend to `PMMStack._solve_conical`**: it
has excellent order-cap / resolvability / energy-tripwire guards of its own,
but no incidence/grazing guards either — and its `phi != 0` dispatch returns
*before* the classical solve body, so the guards there are bypassed.  **Fix**:
add both guards to the two functional entries and `_solve_conical` (five lines
each, copy the 2-D core's pattern); consider `_propagation_star` while there
(the conical cascade still uses the generic star + explicit propagation
S-matrix — correct, mildly slower).

### D2 (P2) — GBD per-surface path: NaN beamlets from FD-companion deaths
`raytrace/differential.ray_transfer_jacobian` (the FD backend) computes 9N
central-difference companions with **no companion-alive masking and no NaN
scrub** — a live base ray whose ±h companion vignettes/TIRs at a rim yields NaN
Jacobian rows while `alive=True`.  The analytic backend scrubs
(`nan_to_num`, `differential.py:517`) and the world-plane consumer filters
(`gbd.py:2971`), but the **local-frame branch** of
`apply_prescription_persurface_to_beamlets` (`gbd.py:2893-2901`) masks only on
`dt.alive` — NaN Q/amp rows pass into the coherent reconstruction (a localized
NaN patch under the windowed path; full-field NaN under the dense path).
Reachable exactly where FD is the auto-fallback: aspheric/freeform surfaces
with rim-adjacent beamlets.  **Fix**: add the same
`isfinite(Q).all + isfinite(amp)` mask the world branch has (2 lines), and/or
AND companion-aliveness into `DifferentialTransfer.alive` in the FD backend.

### D3 (P2-physics) — multibranch KMAH parity closure is mod-2 only
`_lens_traced_multibranch._kmah_free_leg` counts exit-leg fold crossings
analytically (exact quadratic — correct, including double roots at point foci)
and then "closes" in-glass crossings by a **sign-parity** check
(`:194-199`), which can only detect an **odd** miss.  An even number of
in-glass crossings (e.g. a full internal focus inside a multi-element
prescription = 2 fold crossings) leaves the branch's Maslov index short by 2 —
an `e^{-iπ}` **sign error** on that branch's contribution — while the module
docstring says the parity assertion "closes the in-glass caustic count"
(overclaim).  **Fix**: count in-glass crossings per glass leg with the same
quadratic `det Q(z)` method — `raytrace.differential.ray_transfer_jacobian(...,
per_surface=True)` already provides the per-leg Q/Q̇ blocks — or scope the
docstring to "no internal focus inside the prescription" and warn when the
exit-leg count plus parity disagree with a per-leg estimate.

### D4 (P3) — multibranch: `output_plane_n ≠ 1` breaks the intrapolation slopes
The Kraaijpoel second-order OPL intrapolation uses `p = (L, M)` ("in air",
`:484`) but the eikonal gradient in an index-n output space is `n·(L, M)`; the
OPL advance itself uses `n·t` correctly (`:131`).  For immersed output planes
the interpolated phase is subtly wrong.  **Fix**: multiply the slope terms by
`output_plane_n`, or validate `output_plane_n == 1`.

### D5 (P3) — multibranch: Ludwig pair-picker can misclassify axial-focus pairs
The caustic band swaps the **closest-eikonal** branch pair for the fold-uniform
field (`:529-548`).  At an axial point focus, symmetric branch pairs have
ΔS ≈ 0 without being fold-coalescent — the correct uniform function there is
Bessel/Pearcey, not Airy.  The swap still regularizes (finite where the plain
sum diverges), so this is an accuracy note, not a blow-up: document, and
consider a `det Q̇`-based fold-vs-point discriminator later.

### D6 (P3) — multibranch: `input_carrier` is linear-tilt only
`L0/M0` are scalars, so a diverging source still launches collimated (the
carrier machinery in `_lens_traced._compute_carrier` returns a per-position
`grad_fn` that could feed per-node launch directions).  The docstring scope is
honest; noting the natural extension so the two carrier implementations
converge.

### D7 (P3) — `_math/levin.py` polish items
(a) `fmax` is computed/threaded but never used (dead parameter, 33 wasted
f-evals per 1-D call); (b) the `levin2d` docstring still describes the paper's
parent-vs-children acceptance while the implementation (correctly) uses the
residual-bound priority queue the module header describes; (c) the "rigorous
bound" ∫|r| is estimated as an **unweighted mean over Chebyshev-clustered fine
nodes** × area — edge-weighted, so the returned bound is an estimate, not a
certified bound; Clenshaw–Curtis weights would make the claim exact at no
cost.

### D8 (P3) — residual of B1: `max_nodal_dof` still ignored on the JAX cell path
`_jax_twod._static_prep_cell` is now factorized (the dense N×N kron from B1 is
gone) but still never calls `_validate_cell_cost`, and
`pmm_efficiency_2d_cell(max_nodal_dof=...)` remains silently ignored on the
JAX branch — the (Nf, N) projector pair is the remaining unguarded
allocation.  The new `pmm/_jax_twod_jones.py` twin has the same gap.  Fix is
one call plus one kwarg forward per module.

### D9 (P3) — API: bare `PMM2DStack` name is scheduled to be repointed
The rename to `PMM2DStackHybrid` with the transitional alias is clean, but the
stated plan to repoint the bare name to the **pure** stack later
(`stack2d.py:1128-1139`) is a silent *results* change for any caller using the
bare name (floor vs no-floor, different knobs).  Recommend: a
`DeprecationWarning` phase on the bare alias *before* the cutover, and a
changelog gate.

### D10 (info) — GBD vector/Jones scope couplings
`propagate_gbd_vector_through_prescription` scatters Jones-mixed samples onto
zero-filled full grids and relies on `decompose_field_to_beamlets` re-sampling
the identical pixel set (same `sample_step` phase) — correct today, fragile if
the decomposition sampling convention ever changes; an assertion or a direct
bundle-amplitude path would decouple it.  `_fresnel_jones_matrix_per_beamlet`
is axial-launch by contract (documented) — polarization is evaluated for the
axial congruence only.

### D11 (P3) — `_berreman_jax` twin asymmetries vs the NumPy entry
Three divergences from the NumPy path found in the full read:
(a) `_layer_M_gen_jax` calls `bool(is_iso)` on a value-dependent comparison —
a stack that routes to the generalized path (one concrete OOP layer) but also
contains a **traced** spacer eps works under `jax.grad` yet raises a
ConcretizationTypeError under `jit` (cryptic for the user; guard with a
concrete-inspection try/except like the router, falling back to the tensor
branch); (b) `_offplane_solve_jax` drops the NumPy path's `Re(kzrf) > 0`
clamp and the `|kz| > 1e-12` grazing guards on `rz/tz` — NaN/negative-R at
exactly-grazing edge cases the NumPy entry handles; (c) the JAX
`retain_internal` guard rejects OOP tensors at **any** incidence (message says
"OBLIQUE") while the NumPy path serves OOP-at-normal internal fields — an
over-restriction plus a misleading message.

### D12 (P3) — berreman traced-OOP routing is the opposite of rcwa's fix
`berreman_jones_1d`'s JAX dispatch cannot inspect a **traced** eps tensor and
falls through to the native cascade — silently ~2% off for a traced OOP tensor
at oblique incidence (documented only in a code comment).  The rcwa 1-D/2-D/
stack paths made the opposite (correct) call in this same release: a tracer
routes to the **general** path, which is exact for in-plane tensors too, so
forward and gradient share one branch (`_tensor_offplane_or_traced`,
`_select_forward_flux_jax`).  **Fix**: port that pattern — route berreman
tracers to `_offplane_solve_jax` and make `_layer_M_gen_jax` trace-safe
(subsumes D11a); at minimum, emit a runtime warning when a traced `(3,3)` layer
is present at oblique incidence instead of a code comment.

### D13 (P4) — `formulation='fff_nv'` now means three different algorithms
On `rcwa_efficiency_2d` it is the normal-vector (Popov–Nevière projector) FFF;
on `rcwa_jones_2d` the Li-2003 successive full-tensor `L2 L1` factorization;
on `pmm_jones_2d` the separable-only Popov–Nevière reduction (raises on
crossed cells).  Each docstring is individually honest, but the shared token
invites wrong cross-entry assumptions (e.g. "fff_nv works on my crossed cell"
— true on `rcwa_jones_2d`, a raise on `pmm_jones_2d`).  Consider a distinct
token for the Li-2003 successive rule (accepting the old one as an alias), or
at least a cross-reference table in CONVENTIONS.md.

### D14 (P4) — geo-eig cache is per-wavelength at oblique incidence
`_core._uniform_geo_eig` keys the LRU on the assembled operator bytes, which
bake in the **absolute** kx0 = n·sinθ·k0 — always *correct*, but at fixed
oblique angle a wavelength sweep changes kx0 every point, so the cache misses
throughout (cross-wavelength reuse exists only at normal incidence).  The
"k0-INDEPENDENT (geometry + angle)" comment at `_core.py:1165` holds only
given fixed kx0; fix the comment (the eig itself cannot be made
angle-normalized without operator rescaling).

### D15 (P4) — traced-segmented nits
`apply_real_lens_traced_segmented`: the `max_segments` cap pops the
last-listed (highest-frequency) cut while the comment says "drop the
shallowest cuts first" — sort candidate cuts by valley depth before capping,
or fix the comment; `wavelength` is a dead parameter of
`_segment_field_by_angle`.  The partition math itself is verified correct
(flat-top `sin²/cos²` edges form an exact partition of unity; unimodal spectra
degenerate to plain traced; exact reconstruction at `min_segment_power=0`).
