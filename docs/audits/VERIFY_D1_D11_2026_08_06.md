## 1. D2 -- derived standoff

### My oracle

`scratchpad/oracle.py`: a separable matrix-DFT evaluation of the Fresnel
integral over the same sampled pupil the readout is handed --

```
E_out(u) = e^{ikz}/(i lam z) e^{i k u^2/(2z)} dx dy
           SUM_mn env[m,n] e^{i k r_mn^2 (1/R + 1/z)/2} e^{-i k (u.r_mn)/z}
```

No lumenairy code, no chirp-z, no library grid helpers.  Metric: relative L2 of
`|F|` after L2-normalising both (so an overall scale convention cannot bias the
comparison), and FWHM by linear interpolation through the peak row.

Geometry: lam = 1 um, converging carrier `R = -5 mm`, target at the geometric
focus, `N = 256`, `N_out = 192`, readout window 6 `w0` unless stated.  NA is
`w_env/|R|`; `ext` is the grid half-width in beam amplitude radii.

### 2.2 DEFECT V3 (HIGH) -- the guard is `centre_out`-blind

`_check_readout_replica` compares `N_out*dx_out` against the period and never
looks at `centre_out`.  The reconstruction is periodic in ABSOLUTE output
coordinate, so the faithful zone is centred on the field's own origin, not on
wherever the caller points the window.

NA 0.10, ext 3.0, default standoff.  Period 33.0797 um.  Window = 25.4648 um =
**0.7698 periods** -- comfortably under the bar, so the guard is silent by
construction:

```

   0.00 per    1.570252e+02   1.570727e+02    9.997e-01       0      5.259e-04
   0.25 per    1.569911e+02   1.570386e+02    9.997e-01       0      5.505e-04
   0.50 per    3.758130e+01   3.755931e+01    1.001e+00       0      6.599e-01
   1.00 per    1.570252e+02   1.499920e-03    1.047e+05       0      1.022e+00
   2.00 per    1.570252e+02   6.502293e-04    2.415e+05       0      9.980e-01
   3.00 per    1.570252e+02   4.245897e-04    3.698e+05       0      9.924e-01
```

At `centre_out` = one period the readout returns a spot whose peak is
**bit-identical to the on-axis peak** (1.570252e+02 both) where the truth is
1.5e-03.  Zero warnings.  No refusal.  This is precisely the failure the guard's
own docstring exists for -- "the CORE of the spot is untouched, so a width or a
peak still reads perfectly" -- reproduced with the guard installed.

Worse, the refusal message asserts:

> "Everything beyond +/-period/2 of centre_out is filled with PERIODIC REPLICAS"

which is false and actively misleading: it tells the reader the replica-free
zone travels with `centre_out`.  The same sentence is in
`mft._warn_mft_output_window`, so the error is inherited, but D3 re-asserted it
in new code.

The correct condition is `2*|centre_out| + N_out*dx_out <= period` per axis;
the shipped condition is `N_out*dx_out <= period`.  Breakdown is already total
at `centre_out = 0.5 period` (relL2 0.66) and benign at 0.25 (5.5e-04).

Scope actually probed: the DIRECT public API, which is what D3 claims to have
covered ("`on_replica` on BOTH public readouts").  Through
`propagate_traced_carrier_chain` the tilted path re-references `centre_out` to
the chief ray (`carrier.py:7418-7419`) and the multi centres each tile on the
congruence (`carrier.py:8960`), so the residual offset is normally small; I did
NOT construct a chain configuration that trips it and do not claim one exists.

  ```
    ... (all six passes identical)
  ```
  `_note_pool_deferral` restarts the sample count on a worker-count change, so
  the pool is never created and no teardown/respawn cycle occurs.  Each switch
  discards a valid measurement, which is a small waste, not a thrash.
* **Alternating point counts across the warm bar: no reset.**  Sub-8k calls are
  correctly excluded from the measurement (the deferral timer is guarded on
  `_POOL_MIN_PIXELS_WARM`, not on `_min_px`), so they cannot poison the sample.
