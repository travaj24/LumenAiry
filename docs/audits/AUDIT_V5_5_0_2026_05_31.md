## Part 0 — TL;DR

The adversarial mandate paid off. RCWA is the canonical bug-nest of computational EM, and hammering it against analytic references + the grcwa oracle + physical invariants surfaced **two genuine P1 correctness bugs that the shipped test suite cannot see because both conserve energy** (S-matrix unitarity is automatic, so energy conservation does NOT validate the diffraction-order split or the cached modes).

### The 2 P1 bugs (both energy-masked, both in the flagship RCWA module)

**P1-A — Oblique-TM multi-order diffraction split is systematically wrong** (`rcwa.py` `_layer_eigenmodes`/`_layer_Q_matrix`, ~lines 207-287). Found by R1 with the **grcwa 0.1.2 oracle** (confirmed installed; TE validated to 8.5e-6). For TM at oblique incidence once multiple orders propagate, power is distributed among orders incorrectly:
- Test grating (Λ=1.2µm, λ=0.55µm, n=2.5/1.0, d=0.4µm, dc=0.4, θ=15°): **lumen TM Rtot=0.5309 vs grcwa=0.5624** — 3.6e-2 total, **up to 5.2e-2 per order**. The CHANGELOG claims "<2e-3 per order" — this is **26× over the claimed bound**.
- Both solvers *converge* (lumen monotonically to 0.5313, grcwa to 0.5737) — to **different limits**. Not under-truncation.
- **Error scales with index contrast** (the fingerprint of a Fourier-factorization / TM-eigenvector error): ~5e-2/order at n=2.5, ~2e-3/order at n=1.8.
- **Vanishes** in the uniform/single-order limit (uniform slab oblique-TM matches Airy to 1e-16). So the bug is specifically in the **multi-order TM mode coupling** — TM eigenvalues are correct (energy + uniform-limit pass) but the eigenvectors used for interface field-matching are mis-factorized (likely the Li inverse-rule matrix `[[1/ε]]⁻¹` applied on the wrong side vs the canonical Li-1996 1-D TM operator).
- **TE is correct** (lumen ≡ grcwa to 8.5e-6). This is a TM-specific factorization bug.

**P1-B — Substrate homogeneous-mode cache returns WRONG modes (key collision)** (`rcwa.py:1779-1784`). Found by R5 (the "make the cache return wrong modes" probe). The substrate cache key omits `n_superstrate`, but substrate modes depend on it via `kx0 = Re(√εsup)·sinθ·cosφ` at oblique incidence:
- Two stacks, same `n_substrate=1.5`, θ=30°, different `n_superstrate` (1.0 then 2.2): the second silently reuses the first's substrate modes → **max|ΔT|=0.088, R+T=1.338 (33.8% spurious energy GAIN)**.
- Bites exactly in the sweep-acceleration scenario the cache exists for. R5 added 2 strict-xfail regression pins and verified the one-line fix (`max|ΔT|→0`, energy→1.0).

### The 3 P2 bugs

## Part 1 — P1-A: Oblique-TM multi-order diffraction split (R1, grcwa-oracle-confirmed)

**This is the headline finding** — a real physics error in the flagship solver, masked by energy conservation.

**Reproducer** (Λ=1.2µm, λ=0.55µm, n_ridge=2.5, n_groove=1.0, sub=sup=1.0, d=0.4µm, dc=0.4, θ=15°):

| | lumen | grcwa | inkstone |
|---|---|---|---|
| **TE** Rtot | 0.385951 | 0.385959 | 0.382995 |
| **TM** Rtot | 0.530909 | 0.562408 | 0.308560 |

- **TE: lumen ≡ grcwa to 8.5e-6** (per-order ≤9e-5) — proves the grcwa 1-D setup is correct and the oracle is trustworthy.
- **TM: lumen vs grcwa differ by 3.6e-2 total, up to 5.2e-2 per order** (m=0 transmitted: lumen 0.2534 vs grcwa 0.2015). CHANGELOG claims `<2e-3 per order` → **26× over**.
- **Convergence rules out truncation**: lumen N=15→51 monotonic 0.5184→0.5313; grcwa 0.5737 (Ly-invariant, bit-identical for Ly=1e-3·Px and 1e-2·Px — rules out a 2-D-coercion artifact). Two solvers converge to *different* limits.
- **Contrast scaling** (Fourier-factorization fingerprint): n=2.5 → ~5e-2/order TM error; n=1.8 → ~2e-3/order; TE in the same geometry → 3.3e-5.
- **Uniform/single-order limit is exact**: uniform slab oblique-TM matches Airy to 1e-16; subwavelength (single propagating order) oblique-TM matches the analytic uniform-slab limit and interpolates smoothly with duty cycle.

**Diagnosis**: TM eigenVALUES are correct (energy + uniform-limit pass), but the eigenVECTORS used for interface field-matching are mis-factorized. The Li inverse-rule matrix `EPS_xx = [[1/ε]]⁻¹` is likely applied on the wrong side vs the canonical Li-1996 1-D TM operator, corrupting `W` (and `V = Q·W·diag(1/λ)`) and hence per-order coupling. inkstone is an unreliable oracle here (it warns it rotates the non-uniform axis; gave 0.31); **grcwa is the trustworthy oracle** and pins the bug.

**Why it shipped**: `validation/elements/test_rcwa.py` tests TM only via uniform-slab Airy + energy conservation (both of which lumen passes); its header concedes the grcwa/inkstone cross-checks live in an **uncommitted "developer scratch suite."** No committed test cross-checks a real multi-order oblique-TM grating against any oracle. This is the exact gap that let P1-A through.

**Severity P1**: TM + oblique + multi-order is a core regime for polarization-sensitive gratings/metasurfaces. Getting the order split wrong (while energy conserves) silently corrupts every such design. **Must fix before RCWA can be trusted for oblique-TM work.**

## Part 2 — P1-B: Substrate mode-cache key collision (R5, verified + xfail-pinned)

**File**: `rcwa.py:1779-1784`. The substrate cache key is `("sub", n_substrate) + (nox, noy, wl, theta, phi, period_x, period_y)` — it **omits `n_superstrate`**. But substrate eigenmodes derive from `Kx/Ky` whose diagonal `kx = kx0 + m·λ/Λ` uses `kx0 = Re(√εsup)·sinθ·cosφ` (lines 1772-1776). So at oblique incidence the substrate modes depend on `n_superstrate`, which is absent from the key. `_HOMOG_CACHE` is module-global, shared across all stacks.

**Reproducer (verified N=25 and N=81)**: two stacks, same `n_substrate=1.5`, θ=30°, differing `n_superstrate` (1.0 then 2.2). Stack B hits A's `('sub',1.5,…)` entry:
- `max|ΔT|=0.088`, `max|ΔR|=0.036` vs the cache-cleared reference
- **R+T=1.338 (33.8% spurious energy gain)** for one polarization
- Cache-key dump: after B, a new `('sup',2.2,…)` key appears but **no new `('sub',…)` key** — B silently reused A's substrate modes. The superstrate side is correctly keyed (control: `max|ΔR|=0.0`).

**Fix (verified to fully resolve)**: fold `n_superstrate` into the shared geom tuple, or key on the actual eigenproblem input (eps + Kx/Ky diagonals). `max|ΔT|→0`, energy→1.0. R5 added `test_stack_homog_cache_substrate_key_collision_oblique` (strict-xfail) which flips to unexpected-pass on fix.

**Severity P1**: silently wrong physics with energy >1, in the exact multi-config sweep the cache is built to accelerate. The concurrency lock (`_HOMOG_LOCK`) is correct (6× concurrent θ-only sweeps matched serial to 1e-10) — the bug is the key, not the locking.

## Part 3 — P2 findings (RCWA)

### P2-A — Layer-grazing crash (R1)
`rcwa.py` ~492-501. The "Wood-anomaly nudge [that] keeps every matrix invertible" guards only `eps_sup`/`eps_sub`, NOT the layer index. When a diffracted order grazes inside the grating layer (kz_layer→0 ⇒ modal λ→0 ⇒ degenerate `V` columns ⇒ `_interface_smatrix` `solve(Vb,Va)` singular), it crashes with `LinAlgError`. Razor reproducer: `rcwa_efficiency_1d(0.25e-6, 2.2, 2.2, 1.5, 1.0, 0.18e-6, 0.5, 0.55e-6, polarization='tm', n_orders=11)` (n_layer=2.2 = λ/period exactly) → CRASH; 2.1999/2.2001 → fine. Reachable in subwavelength-layer spectral sweeps. **Fix**: extend the grazing nudge to layer modal eigenvalues, or floor |λ| in `_interface_smatrix`.

### P2-B — Non-propagating superstrate silent garbage (R3)
`rcwa.py:557,562,564` + entry points + `RCWAStack.solve:1819`. `kz_inc = Re(√(εsup − kx0²))` → 0 when Re(εsup) ≤ kx0²; the efficiency normalization divides by it. n_sup=0.5+2j → R+T=−5.79 (finite NEGATIVE, no exception — the dangerous case, since an `isfinite` check accepts it); via RCWAStack → nan. **Fix**: validate the incidence half-space is propagating (raise on Re(εsup) ≤ kx0²). Spawn-chip filed by R3.

### P2-C — apply_reflection mutates input JonesField (R5)
`rcwa.py:1633-1635` → `polarization.py:574-575`. `apply_reflection` → `apply_jones_matrix` does `field.Ex = Ex_new; field.Ey = Ey_new` and returns the same object (`out is jf`). The incident field is destroyed. **Fix**: operate on `jones_field.copy()`, or document the in-place contract. R5 added `test_stack_apply_reflection_does_not_mutate_input` (strict-xfail).

## Part 10 — Verdict + remediation

**NOT SHIP-CLEAN for RCWA.** The module is a strong, well-architected, well-conventioned solver — but it has **two real P1 correctness bugs that the shipped tests structurally cannot see** (both conserve energy), plus three P2s. The adversarial mandate was the right call: a non-adversarial "verify the closures" pass would have rubber-stamped a flagship feature with a 26×-over-spec TM physics error and a cache that returns 33%-energy-gain garbage on oblique sweeps.

### Must-fix before RCWA is trustworthy

1. **P1-A — oblique-TM multi-order factorization** (`_layer_eigenmodes`/`_layer_Q_matrix`). The TM eigenvector / Li-inverse-rule placement. Add a committed grcwa (or analytic multi-order) oblique-TM cross-check at the library's correctness bar — the missing test is what let it ship.
