## TL;DR

**v4.15.2 successfully closes the v4.15.1 audit at the core level** — the 1 P0 (Schell `DeprecationWarning`) + all 9 Tier-0 P1s (FourierTransform 3-stage rewrite, from_prescription flat-mirror parity, FreeSpace `dy` threading, cdf-placement pixelwise fix, 10 defensive guards on propagator entry points, breaking-changes subhead, rays_from_field short-return warning, ROADMAP refresh, Magnify/`rays_from_field` docstring fixes) all show shipping code matching the documented fix, mostly with non-tautological pins. V1 ran the new 87 v4.15.2 audit-closure tests; all pass. 1735 pytest-collected (+3 from v4.15.1's reported 1732 in CHANGELOG; sibling discrepancies below).

**However, this audit identifies 1 NEW P0 + 4 NEW P1s + ~6 P2 + ~4 P3.** The new findings cluster again around the same meta-pattern that has now recurred in **every** audit round v4.13.0 → v4.15.2: the v4.15.2 closure was scoped to **10 entry points** identified by v4.15.1's audit; F2 found **9 additional sibling entry points** of the same type accepting the same arguments that were missed — i.e., the closure fix N missed N+1, just like every prior round.

**Headline new findings (sorted by severity):**

1. **🔴 P0-NEW-F2-1: 9 unguarded propagator/lens entry points** (F2). The v4.15.2 P1-NEW-E/F closure added defensive guards (`isinstance(E, PartialCoherenceMCF)` + `E.ndim == 2`) at 10 sites in `system.py`, `propagators/dispatch.py`, top-level `propagators/propagation.py` 5 paths, `elements/_lens_thin.py`, `elements/_lens_real.py`. **But 9 additional public entry points accept the same E and are unguarded:** `angular_spectrum_propagate_tilted`, `angular_spectrum_propagate_mft`, `fresnel_propagate_mft`, `fraunhofer_propagate_mft`, `apply_spherical_lens`, `apply_aspheric_lens`, `apply_grin_lens`, `apply_axicon`, `apply_real_lens_traced`, `apply_real_lens_maslov`. Same cryptic `AttributeError: 'PartialCoherenceMCF' object has no attribute 'copy'` as the original v4.15.1 finding — only the call paths differ.

2. **🔴 P1-NEW-F1-1: `FreeSpace._apply` SAS-anamorphic crash** (F1). v4.15.2 P1-NEW-C closure (FreeSpace `dy` threading) at `algebra/primitives.py:127-137` forwards `dy` only when `dy != dx`. But when `self.method == 'auto'` (the default), the dispatcher routes to **SAS** in far-field regime (`Q > 1`), and SAS does NOT accept `dy` — kernel raises `TypeError`. Forcing `method = 'asm'` would solve it, but the closure didn't account for the dispatcher's regime-dependent kernel pick.

3. **🔴 P1-NEW-F1-2: Schell `DeprecationWarning` stacklevel one short** (F1, V1 partial). At `sources/core.py:1721` the warning chain uses `stacklevel=4`, but the call chain is: user code → factory → `_warn_schell_return_kind_default` → `warn_deprecated_signature` → `warnings.warn`. That's **5 frames**, not 4. The warning currently points one frame INSIDE the library rather than at user code, defeating the purpose of `stacklevel` for IDE/notebook display.

4. **🔴 P1-NEW-F1-3: 3 optimize/core sentinels are dead code** (V2 + F1 2-way confirm). v4.15.2 P2 closure for "sentinel proliferation in optimize/core.py" defined `_InvalidFocalLengthSentinel`, `_FailedScanStrehlSentinel`, `_PerturbedABCDFallbackSentinel` at `optimize/core.py:2044-2144`. **Callsites at `:2374, :2632, :2873, :2936` were NOT updated** — they still use raw values (`-1.0`, NaN strings, etc.). Sentinels are unreachable. CHANGELOG bullet asserts the migration was completed; in fact only the class definitions were added.

5. **🔴 P1-NEW-F1-4: `Source.gaussian_schell`/`schell_model` classmethods bypass `DeprecationWarning`** (V1 + F1 2-way confirm). The v4.15.2 P0 closure adds `_warn_schell_return_kind_default` to the 3 top-level Schell factories. But `Source.gaussian_schell` (`:2789-2809`) and `Source.schell_model` (`:2829-2839`) hardcode `return_kind: str = 'ensemble'` (the v4.15.1 4-tuple), bypassing the sentinel path entirely. Pre-v4.15.0 callers using these classmethods get a 4-tuple silently with no warning. **Additionally** the 4-tuple is unpacked and the Source object's `E` becomes 3-D — every other `Source.*` produces 2-D `E` — uncovered downstream API mismatch (carryover from v4.15.1 P2 finding).

**Verdict:** v4.15.2's audit closure is genuinely clean at the **fixed** sites — V1 verifies all 10 P1 + P0 closures with non-tautological pins; the FourierTransform 3-stage rewrite is correct; from_prescription mirror parity is properly conditional; 10 defensive guards are real (not test-time-only). The new findings cluster in **sibling-gap recurrence**: F2's P0 is textbook "fix scoped to obvious N functions, missed the broader class of N+1 functions accepting same input type". The `FreeSpace` SAS crash (F1's P1-NEW-F1-1) is a subtler form of the same — the closure threaded `dy` but didn't reason about dispatcher-driven kernel selection.

**Tier-0 v4.15.3 patch (~120 LOC, ~4 hours)** would close all 5 new findings plus the F2-recommended meta-pin extension. The fundamental engineering remains strong.

### P1 findings (4)

**P1-NEW-F1-1 — `FreeSpace._apply` crashes anamorphic in far-field with `method='auto'`** (F1)

- File: `lumenairy/algebra/primitives.py:127-137`
- v4.15.2 P1-NEW-C closure (the FreeSpace `dy` fix) added: `if dy is not None and float(dy) != float(dx): kw['dy'] = float(dy)`. Correct for kernels that accept `dy`.
- But `self.method` defaults to `'auto'`. The dispatcher in `propagators/dispatch.py` routes to **SAS** for the far-field regime (`Q = N·dx² / (λ·z) > 1`). SAS's signature is `sas_propagate(E, z, wavelength, dx, ...)` — NO `dy` parameter.
- Failure mode: `TypeError: sas_propagate() got an unexpected keyword argument 'dy'`. Reproducible with any anamorphic algebra chain (`Magnify(a_x, a_y) * FreeSpace(d)` with `d` far enough to push into SAS regime).
- `FourierTransform._apply` (`:543, :553-580`) hardcodes `method='auto'` internally and is equally exposed.
- **Fix candidates:**
  1. When `dy != dx`, force `method='asm'` (or any kernel that accepts `dy`) regardless of `self.method`. Cleanest — keeps `auto` as a hint, not a contract.
  2. Add SAS-anamorphic dispatcher routing (would require a SAS kernel that accepts non-square grids — out of scope for a patch release).
  3. Detect ahead of dispatch and raise `NotImplementedError("anamorphic SAS not yet supported; pass method='asm'")`.

**P1-NEW-F1-2 — Schell `DeprecationWarning` stacklevel one short** (F1)

- File: `lumenairy/sources/core.py:1721` (`stacklevel=4` passed to `warn_deprecated_signature`)
- Frame stack when warning fires:
  1. `warnings.warn(...)` (innermost)
  2. `warn_deprecated_signature` (`_deprecation.py`)
  3. `_warn_schell_return_kind_default` (`sources/core.py`)
  4. Factory body (e.g., `create_gaussian_schell_source`)
  5. **User code** ← target of `stacklevel`
- `stacklevel=4` lands on (4) the factory body — one frame inside the library.
- Correct value is `stacklevel=5`. Bug is consistent with most-recently-written `_warn_*` helpers across the library; **not user-visible at error level** (warning still emits), but Jupyter "show source" and IDE links point to the wrong file.

**P1-NEW-F1-3 — 3 optimize/core sentinels are unwired dead code** (V2 + F1 2-way confirm)

- File: `lumenairy/optimize/core.py`
- v4.15.2 P2 closure ostensibly migrated `optimize/core.py` raw-value sentinels to typed `_Sentinel` subclasses. Sentinels DEFINED at `:2044-2144`:
  - `_InvalidFocalLengthSentinel`
  - `_FailedScanStrehlSentinel`
  - `_PerturbedABCDFallbackSentinel`
- **Callsites at `:2374, :2632, :2873, :2936` UNCHANGED** — still use raw `-1.0` / `float('nan')` / `np.eye(2)`. The sentinel classes are unreachable.
- CHANGELOG bullet asserts "consolidated 3 sentinels in optimize/core.py per audit P2"; in fact only the class definitions landed.
- **Severity P1** because (a) CHANGELOG materially overstates closure scope, and (b) the v4.16+ work that depends on these sentinels (pickle round-trip safety, distinguishability vs raw NaN in downstream code) is silently absent.
- **Fix:** either wire the callsites (replace `-1.0` returns with `_InvalidFocalLengthSentinel()`) OR amend CHANGELOG to say "scaffolding added; callsite migration deferred to v4.16+".

**P1-NEW-F1-4 — `Source.gaussian_schell`/`schell_model` silent return-type change** (V1 + F1 2-way confirm)

- File: `lumenairy/sources/core.py:2789-2809` (`gaussian_schell`), `:2829-2839` (`schell_model`)
- The 3 top-level factories at `:1903-1904`, `:2024-2025`, `:2143-2144` use the `_RETURN_KIND_UNSET` sentinel; v4.15.2 P0 closure wires `_warn_schell_return_kind_default` on these.
- **The two `Source.*` classmethod entry points hardcode `return_kind: str = 'ensemble'`** as a literal argument default, bypassing the sentinel.
- Pre-v4.15.0 callers like `src = Source.gaussian_schell(...)` get:
  - **No `DeprecationWarning`** (sentinel path not exercised)
  - **A `Source` object whose `E` attribute is 3-D** (every other `Source.*` factory produces 2-D `E`)
- Downstream consumers calling `src.intensity()` get a 3-D intensity array (incoherent sum over realizations not folded). `src.E.shape == (M, Ny, Nx)`. `src + other_src` broadcasts unexpectedly. **AttributeError-free** (the 3-D `E` propagates through `numpy` operations), so the breakage manifests as wrong physics, not a clean crash.
- **Fix:** route `Source.gaussian_schell`/`schell_model` through the same `_RETURN_KIND_UNSET` sentinel logic. Optionally — collapse the 3-D ensemble to a per-realization iterator behind `Source.realizations()` and return a single 2-D `E` (the ensemble mean intensity, say) so `Source` invariants hold.
