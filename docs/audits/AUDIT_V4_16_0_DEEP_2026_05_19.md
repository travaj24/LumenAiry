## Part 0 — TL;DR

**The library is in much better shape than the previous audit found bugs to characterize.** Across 11 single-domain auditors, the deep sweep produced **0 P0 + ~14 P1 + ~50 P2 + ~30 P3** findings. The substantive physics is largely correct — every audit-history pin from v4.13 → v4.15.5 verifies intact at v4.16.0 HEAD, and all five diffraction propagator kernels, ray-trace + Forbes Q + Sellmeier, and Schell-coherence + polarization + image-quality metrics check clean against first-principles math. **No wrong-physics bugs found.** Sellmeier coefficients for the 8-glass cross-check (N-BK7 / N-SF10 / N-LASF40 / N-LASF9 / F2 / SF2 / S-LAH64 / S-LAH79 / sampled CDGM) match the published Schott TIE-29 / Ohara / refractiveindex.info forms bit-for-bit.

**However**, the deep sweep surfaced **substantial polish-quality and second-order correctness issues that the previous audit's verification-style scope missed**:

1. **A real correctness bug**: `MultiWavelengthMerit.evaluate` SUMS rather than averages while its docstring and both sibling classes (`MultiFieldMerit`, `ToleranceAwareMerit`) document and implement averaging — adding a 3rd wavelength silently triples merit weight.
2. **A real correctness bug**: `shack_hartmann` wavefront reconstruction uses the requested `lenslet_pitch` instead of the on-grid quantized `int(round(lenslet_pitch/dx))*dx` — for `lenslet_pitch/dx = 1.7`, reconstructed wavefront is off by ~18% in amplitude.
3. **A real correctness bug**: `_detect_backend` in `io/storage.py` misclassifies any pre-existing directory as Zarr (`path.endswith('.zarr') or os.path.isdir(path)`). Stale Zarr directory in HDF5's intended path silently re-routes backend.
4. **The Schell-model propagation workflow is half-shipped**: default `DeprecationWarning` on every call; no `propagate_ensemble` helper; `PartialCoherenceMCF` path is explicitly rejected by every downstream propagator with a "v4.16+" deferral message — and the version IS 4.16.0.
5. **JAX-traceable ray-trace silently diverges from NumPy at high NA**: `_transfer_jax` uses paraxial `t ≈ thickness` instead of the math-correct `t = (thickness - z)/N`. Per-surface transverse error ~`thickness·NA²/2`. Documented as a NaN-gradient workaround.
6. **JAX-traceable `propagate_through_system_jax` breaks under `jax.jit`/`jax.grad`** because `np.asarray(E_in)` raises `TracerArrayConversionError`. The function's own docstring tells users to do exactly that.
7. **Vector-returning `Constraint.fun` crashes the pymoo wrapper** despite the dataclass docstring permitting `f(x) -> scalar | ndarray`.
8. **Multi-way convergent finding**: 4 stale `n_d` inline comments in the CDGM glass block (H-ZK9B claims 1.613750 vs computed 1.62042; H-ZF12 claims 1.673 vs computed 1.762 — 6% off). **Coefficients are correct; only comments lie.** Caught by V5 + DEEP-3 + F1 + PHYS-2 (**4-way convergent**).
9. **The `_TARGET_PACKAGES` scope of the v4.16.0 dispatcher walker leaves new sibling-gap surfaces** that the 9 V-walkers don't catch: GLASS_VALIDITY ↔ GLASS_REGISTRY matching keys; `@lru_cache` ↔ `_cache_registry` enrollment coverage (already documented in prior audit Part 6 P1-NEW-F2-1 + P1-NEW-F2-2).
10. **Library namespace bloat**: `len(la.__all__) == 523` flat. Backend internals (`is_numpy_array`, `RandomState`, `set_fft_threads`, `PYMOO_AVAILABLE`), memory infra (`available_cpus`, `bytes_per_element`), cache helpers (18 `clear_*_cache` names), and ray-status sentinels (`RAY_OK`, `RAY_TIR`) all flat at `la.<TAB>`.
11. **One genuine documentation-vs-code contradiction in CHANGELOG carried forward**: SAS-anamorphic "regardless of self.method" wording (fixed in v4.15.5 retroactively in v4.15.3 entry but a similar mismatch exists in the v4.16.0 entry).
12. **Code-quality grade B+**: 14 large modules missing `__all__`; 8 god modules past 2000 LOC (3 past 4000); zero `npt.NDArray` annotations; ~60% function annotation coverage; `eps = 1e-30` magic numbers scattered in 7 sites.

**No P0 findings.** Highest-severity items (the 14 P1s) are real but bounded — none break a propagated field's physics; the substantive misbehavior is in (a) the optimization workflow, (b) the wave-to-ray JAX path, (c) one detector reconstruction, (d) one backend-detection auto-router, and (e) one user-discoverability cliff.

**Recommended v4.16.1 patch (~250 LOC, ~6-8 hours)** would close the 14 P1s + the highest-value P2s. The library remains exceptionally strong as a **mature internal tool** but has user-onboarding and standardization debt that compounds.

## Part 6 — Subsystem deep dives

### DEEP-1: `optimize/` subsystem

**P1 findings (4):**

- **P1-1 (real correctness bug)**: `MultiWavelengthMerit.evaluate` SUMS (`return self.weight * total`) while docstring says "average" and both sibling classes (`MultiFieldMerit:2693`, `ToleranceAwareMerit:2995`) divide by `len(...)`. **Adding a 3rd wavelength silently triples the chromatic merit's weight contribution.** Fix: `return self.weight * total / max(len(self.wavelengths), 1)`.

- **P1-2 (real correctness bug)**: LM `if b else -inf` bounds parsing at `core.py:4057-4058`. `b` is always truthy (non-empty tuple); `b[0]` may be `None` for "no lower bound" pair → silently passed to `np.array` producing object array → scipy chokes.

- **P1-3**: `multi_objective.py:269,273` rejects vector-returning `Constraint.fun` despite dataclass docstring permitting `f(x) -> scalar | ndarray`. `float(_f(xv))` raises `TypeError: only length-1 arrays can be converted to Python scalars` for ndarrays.

## Part 10 — Final verdict

**v4.16.0 is a mature, physically-correct, ambitiously-engineered optical propagation library.** Across 11 deep auditors, the physics in every kernel (5 scalar diffraction propagators + Richards-Wolf vectorial + ray-trace + Forbes Q + Sellmeier dispersion + Schell coherence + Wolf SVD modal decomposition + Jones polarization + Strehl/M²/D4σ/PSF→OTF→MTF chain + resolution metrics) verified correct. The 9-walker dispatcher meta-pin infrastructure represents real structural progress. The 4-bucket v4.16.0 rollup (V4 walkers, multi-process storage, optimization framework, glass catalogues + cache registry) is each independently substantive and well-tested. The audit-history bug pattern across v4.13 → v4.15.5 is fully fixed at v4.16.0 HEAD.

**The deep sweep nonetheless surfaced ~14 P1 + ~50 P2 + ~30 P3 findings the verification-style prior audit didn't.** Highest-impact items are:
- **4 real correctness bugs** (`MultiWavelengthMerit` sum-vs-avg; `shack_hartmann` wavefront pitch; `_detect_backend` directory misclassification; LM bounds parsing). None break a propagated field's physics, but each is a real silent-wrong-answer at user-relevant configurations.
- **A half-shipped feature** (Schell ensemble propagation has no helper; MCF path is rejected with a "v4.16+" deferral message at version 4.16.0).
- **Two JAX-path issues** (`_transfer_jax` paraxial drift at high NA; `propagate_through_system_jax` breaks under jit/grad despite its name).
- **A real sibling-gap recurrence inside the very release shipped to retire the pattern** (carry-forward from prior audit: GLASS_VALIDITY ↔ GLASS_REGISTRY keys; `@lru_cache` ↔ `_cache_registry` enrollment).
- **A user-onboarding cliff** (523-name flat namespace; README mostly release notes; no Zemax example; key cross-references missing).

The 4-way convergent finding (4 stale `n_d` inline comments in the CDGM glass block) is a vivid illustration of the deep-search payoff: the coefficients are correct, the catalog cross-checks pass, but reading the source reveals comments that contradict the math by up to 6%. A future maintainer relying on the comment for context would be misled.

**Bottom line**: v4.16.0 is **ready to use in research** (the substantive physics is correct, the audit-history regressions are fully fixed, and the test suite is comprehensive). v4.16.1 patch closing the 14 P1s + the high-value P2s would bring it to **ready to publish / pip-install** quality. The v5.0 ROADMAP item list correctly identifies the architectural debt (file splits, CI gates, namespace cleanup, deprecated-shim removal) — the current state is well-understood by the maintainer.

**Recommendation**: ship v4.16.1 with items #1-19 above. Defer the architectural cleanup items to v5.0 per the existing ROADMAP. The library's fundamental engineering remains exceptionally strong; the remaining work is targeted, well-scoped, and primarily hygiene/ergonomic rather than core-physics.
