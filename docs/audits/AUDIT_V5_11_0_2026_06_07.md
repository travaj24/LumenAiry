## Part 1 — P1 findings

### P1-A — `fff_nv` mis-splits absorption ~50% on curved metal walls (lossless-trap failure) — VERIFIED

`rcwa_efficiency_2d(formulation='fff_nv')` (v5.11.0, commit `a9c9156`) is the Schuster-2007 normal-vector Fast Fourier Factorization — the exact technique I recommended as **priority #1** in `AUDIT_RCWA_CONVERGENCE_ACCELERATION`. The previously-flagged mandatory test (a **curved/disk** inclusion, where the NV cross-term `Nxy≠0` is genuinely exercised — it is ~0 for axis-aligned squares) now **fails**:

- **Lossy metal disk** (eps=−15+3j, P=0.7µm): converged absorptance from three independent oracles agrees — `laurent`(M=13)=0.0943, `li`(M=12)=0.0963, analytic-shape disk(M=12)=0.0951 — i.e. **A≈0.094-0.096**. `fff_nv` gives **A=0.046-0.077** (M=10..13), **~50% low and not converging** toward consensus.
- It's a **textbook lossless trap**: R+T+A=1 closes (energy gate passes) but the per-channel split is wrong.
- **Not a transpose/operator-order slip**: sweeping all four `{Δ@N, N@Δ} × {EZZ=Einv, EZZ=E}` variants gives A∈{0.0489, 0.0465, 0.0549, 0.0540} — all clustered near *half* the truth, none recovering it. The NV **tensor formulation itself** is wrong on curved walls.
- **Scope of correctness (real wins preserved):** `fff_nv` is correct on a lossless dielectric disk (tracks `li` to 4e-3) and on a **separable** axis-aligned metal stripe (absorptance matches the rigorous 1-D-Li oracle to 6e-5, genuinely beating 2-D li/laurent). So the separable-reduction NV win is real; only the curved cross-term is broken.
- **Test gap:** `test_fff_nv_disk_tracks_analytic_reference` asserts only on R00 within a self-admitted ~1e-2 "staircase band" and **never checks absorptance** — which is why the ~50% A error shipped green. (`@ rcwa.py:2272-2312` `_nv_convolutions_2d` → 2548-2551; test `@ test_v5_11_0_rcwa_fff_nv_2d.py:204-250`.)
- **`laurent`/`li` remain bit-identical** after the fff_nv integration (verified, np.array_equal).

**Remediation:** treat `fff_nv` as **not validated for curved/non-separable geometry** — gate it to separable patterns or warn, until the cross-term factorization is corrected; and add an **absorptance** assertion (vs the analytic-shape or high-M laurent oracle) to the disk test. The NV separable-stripe path is a keeper.

### P1-B — `RCWAStack.solve(stabilize=True)` silently returns a worse answer on under-resolved cells — CONFIRMED (mechanism)

`stabilize=True` (v5.11.0, commit `348c6fb`) scans a **downward-only** window `{n, n-1, … n-W+1}`, clusters the zero-order efficiencies, and returns `min(cluster)` (highest-n consensus); if no cluster forms it warns "under-resolved." Reading the code (`rcwa.py:5114-5138`) confirms the finder's defect:

- The design *assumes* "the spikes are isolated, so the remaining counts form the consensus cluster" (comment line 5116) — i.e. it's built for an **isolated resonance at one n_orders** surrounded by converged solves.
- When the cell is simply **under-resolved** (not converged anywhere in the window), the low-order solves are biased the **same direction**, so they **cluster** → `len(cluster) ≥ 2` → the under-resolved warning is **suppressed** → `chosen = min(cluster)` returns a confidently-wrong value. The warning fires only in the *safe* (no-cluster) case.
- Finder's reproduced numbers (metal square inclusion, P=0.5µm): converged truth T0≈0.21 (n=20-23); requested n=9 → window {9,8,7,6,5}, low orders cluster ≈0.41; `stab@9`=0.409 (err 0.199) vs `plain@9`=0.175 (err 0.034) = **5.8× worse, `warned=False`.**
- **Scope:** opt-in; `stabilize=False` is the default and is **byte-identical** to the prior single solve (verified). No-harm is confirmed on genuinely-converged stacks (|stab−plain|=0.0).

*Lead note:* my own quick numerical repro used an invalid 1-D setup (the cell didn't converge in-range and `stabilize` didn't engage) — consistent with my known unreliability on fast RCWA repros — so I confirm this via the **code mechanism** + the finder's detailed reproduction rather than my own numbers.

**Remediation:** the warning logic must also flag a **monotone / same-direction** cluster as under-resolved (a true plateau is flat, not trending); consider a symmetric or upward probe. Until then, document that `stabilize=True` assumes the requested n_orders is already near convergence.

## Part 2 — P2 findings (all verified)

**P2-A — Non-reciprocal asymmetric off-plane tensor crashes the selector at oblique.** For lossless **non-reciprocal** media (eps_xz≠eps_zx), the GAP7 generator has eigenvalues with *both* nonzero Re and Im; `_select_forward_flux` (`rcwa.py:2802`) uses a binary `|Re(γ)|<1e-7` propagating/evanescent split that misclassifies them → **Singular matrix** crash at oblique incidence (25/28 scanned cases), where Berreman solves fine. **Scoped:** the documented use case — *reciprocal* tilted-director LC (eps_xz=eps_zx) — is unaffected (0/45). Repro: `rcwa_jones_1d(..., eps=[[2.25,0,0.5],[0,2.25,0],[0.1,0,2.40]], angle=30°, n_orders=1)` → LinAlgError. Fix: a flux-magnitude (not Re-sign) forward criterion, as GAP7 already uses for the all-harmonic Poynting selector elsewhere.

**P2-B — `jax.hessian` wrt permittivity is unsupported but advertised.** v5.10.5 ("autodiff completeness — validated Hessians, W1/W6") only validated Hessians wrt **depth/geometry**. `jax.hessian` of a loss wrt **cell permittivity** raises `NotImplementedError: The derivatives of non-symmetric eigenvectors are not supported` (the `_eig_raw` custom_vjp defines no eigenvector 2nd-derivative, `rcwa.py:3971-3997`). First-order eps gradients are fine; only the Hessian wrt eps fails. Fix: scope the docs/CHANGELOG claim to depth/geometry Hessians, or implement the degenerate-safe eigenvector second derivative.

**P2-C — V20 cross-backend parity walker blind to the PMM-JAX surface.** `_discover_jax_twins()` returns 14 twins, **zero** containing `pmm`; `lumenairy.elements.pmm` is not in `_JAX_TWIN_MODULES` and the PMM JAX twin is private, so the new differentiable PMM path is structurally invisible to the parity walker (all 5 V20 tests still pass). Third consecutive cycle the V20 allowlist lags a new JAX surface (RCWA was the prior gap). Fix: add the PMM JAX twin to the discovery allowlist.

## Part 3 — P3 findings (selected; ~10 total, mostly doc/hygiene)

- **Doc overclaims (all honest in the per-test/softened docstrings, overstated in CHANGELOG/module prose):** circular truncation "~30% fewer harmonics" is geometry-dependent and **non-monotone — sometimes worse than rectangular** on sharp metal corners; ASR "~10×@12 orders" measured **2.8×** on a gold-TM cell (the 5.7.1 docstring already walks this back); `fff_nv` module docstring "lands closer than 2-D li" is true only for axis-aligned features (worse on curved walls — see P1-A).
- **Stale docstrings:** `pmm_jones_1d:1312-1318` describes out-of-plane+slant as "guarded: conserves energy but per-order WRONG" when the code actually **raises** `ValueError` (the guard is correct; the prose is stale).
- **`rcwa_extrapolate(method='shanks')`** leaks a spurious "invalid value encountered in divide" RuntimeWarning (`rcwa.py:2075-2076` computes `num/den` for all elements before masking) — returned value is correct.
- **PMM `stabilize=False`** exposes energy-inflating discrete resonances (GOLD TM degree=20 → sumR+T=1.0175, +1.75% spurious power); `stabilize=True` removes them (the documented fix).
- **Import latency:** eager `jax`(68s cumulative) + `numba`(27s) imports dominate the ~9.5s cold start (the "103.8s" seen earlier was 11× contention inflation; quiet-box = 9.5s) — both are deferrable (see Part 5).
- **`fff_nv` normal-vector field** assumes the (0,0) corner pixel is background (`eps.flat[0]`, `rcwa.py:2244`) — breaks if a shape wraps the cell corner.
- **`layer_absorption`** sum-closure is enforced by renormalization (`rcwa.py:4733`), so the `row.sum()==absorptance()` test can't detect a per-layer mis-distribution (only the total).
- **PMM out-of-plane+slant coupled-tensor** has a documented per-order floor ~1-3e-3 (wall-normal factorization limit; not a corruption) and emits cosmetic large-|Re q| spurious evanescent modes that grow with slant but carry no observable error.
- **JAX Jones d/d(angle) at exactly normal incidence** has a ~5e-5 AD artifact vs the symmetry-protected true zero (observables are gauge-invariant; gated to oblique).

## Part 5 — Speed + cross-connect (the standing asks)

**Speed (top levers):**
1. **Defer `jax`+`numba` imports** — the single highest-leverage, lowest-risk win. importtime cumulative: jax 68s, numba 27s, scipy.linalg 24s, all triggered at `import lumenairy` by two module-load lines (`lenses.py:75-82` numba; `raytrace/jax_trace.py` jax). numba has pure-NumPy fallbacks; jax is only needed on the differentiable path. Lazy-loading these would cut the cold import dramatically.
2. **Dense non-Hermitian eig is the dominant compute** (cubic: 2N=62→221ms, 122→996ms, 202→5580ms), recomputed per-layer **and per-wavelength** (a 5-λ sweep = 7× a single solve, no cross-λ reuse since Kx/eps change).
3. **Symmetry-halving (4.1×) is normal-incidence + scalar only** — absent for oblique, fff_nv, full-tensor out-of-plane, and **all of PMM**. eig-reuse exists in `RCWAStack.solve` but not the PMM stack.
4. asm.py fftshift fold is bit-exact; its wall-clock win is small (~20-27% of one FFT-pair) and can't be trusted under contention.

**Cross-connect (ranked, mostly wiring existing pieces):**
1. **Consolidate PMM↔RCWA S-matrix infra** — PMM already imports RCWA's `_*_general` helpers, and its **local** `_interface/_propagation/_redheffer_star` copies are **byte-identical (0.0 diff)** to RCWA's (just np-hardcoded vs array-namespace-generic). Safe to de-duplicate.
2. **Register RCWA/PMM as wave-propagator merits** — the optimize driver already has the registry + `needs_ray=False` decoupling + `register_wave_propagator`; RCWA/PMM aren't registered despite the differentiable PMM being ideal for inverse design.
3. **PMM stack eig dedup** — `RCWAStack.solve` dedups identical layers via a content-keyed mode cache; the PMM stack has no analog (recomputes every layer — costly for DBR-like repeated supercells).
4. RCWA/PMM → coherence/Köhler (per-angle Jones); internal-field → absorption-based design FOM; the new `reflective_outcoupling` cross-port FOM → optimize merit.
