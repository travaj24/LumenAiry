## Part 5 — F1: Fresh-eyes findings (1 P1 + 1 P2 + 4 P3)

### P1 — `_intersect_surface` backward-ray bug confirmed (CONVERGENT across V5+F3+F1)

**File**: `lumenairy/raytrace/intersection.py:133` (fast path) + `:181-183` (Newton initial guess) — both branches use direction-blind `t = t1 if R > 0 else t2`.

**F1 Reproducer 1 (unit)**: Single backward ray (N=-1) at (x=0.05, y=0, z=0) hitting R=-1m sphere:
- Library result: `z = -1.99875` (FAR root, ~2m past vertex)
- Expected NEAR root: `z = -0.00125`

**F1 Reproducer 2 (`trace()` end-to-end)**: Off-axis chief ray through 2-mirror Cassegrain-like system. After secondary mirror (R=-0.3m, vertex 40cm behind primary), ray lands at `z=-0.596m` in global frame — **almost 20cm PAST the secondary vertex on the wrong side of the sphere**. Ray is `alive=True` so trace silently produces garbage rather than vignetting.

**Impact**: Any geometric raytrace through a mirror that flips ray direction silently produces wrong intersections. Affects `trace()`, `trace_world()`, `raytrace_system()`, `trace_prescription()`, `seidel_coefficients` (calls trace internally for chief/marginal rays), and all GUI docks exercising these (footprint, distortion, spot-vs-field, etc.) when the prescription includes a mirror.

**Test coverage gap (F1)**: NO unit test in the entire suite exercises `trace()` / `raytrace_system()` with `is_mirror=True` on a curved surface (verified via Grep). Mirror-related tests at `test_audit_raytrace.py:103-185` only exercise `seidel_coefficients` and `system_abcd` which use paraxial ABCD matrices (not `_intersect_surface`). **The `_ghost_intersect` workaround in `analysis/ghost.py:560-686` is the only correct path; the original library remains broken NOW for any non-ghost mirror use.**

**Severity**: P1 (was forecasted as v5.5 candidate, but F1's empirical confirmation that this silently produces wrong-side-of-sphere results in a regular Cassegrain trace justifies treating as P1 — a silent garbage bug that has been latent for the entire v5.x line).

**Fix options**:
- (a) Promote `_ghost_intersect` fix into `_intersect_surface` immediately (a v5.4.1 patch)
- (b) Add a guard that raises `NotImplementedError` if any ray enters `_intersect_surface` with `N < 0`, converting silent-garbage to loud error
- (c) Both

### P2 NEW — TiO2 / Ta2O5 Sellmeier return NaN at λ = 1.0 µm

**File**: `lumenairy/elements/coatings.py:403-414`

The TiO2 and Ta2O5 Sellmeier coefficients use dummy poles `C2 = C3 = 1.0 µm²` to fill the 3-pole template for what is really a 1-term Sellmeier:
```python
'TiO2':  { ...  'sellmeier': ((4.99048, 0.0, 0.0), (0.19086**2, 1.0, 1.0)), 'range': (400e-9, 5000e-9) }
'Ta2O5': { ...  'sellmeier': ((3.5820,  0.0, 0.0), (0.16986**2, 1.0, 1.0)), 'range': (350e-9, 8000e-9) }
```

In `_coating_sellmeier()` at `:473-477`, evaluating at λ = 1.0 µm gives `lam2 = 1.0`, `lam2 - C2 = 0`, `B2/(lam2-C2) = 0/0 = NaN`. The numerator-zero doesn't win — NumPy still produces NaN.

**F1 Reproducer**:
```python
>>> get_coating_material_index('TiO2', 1.0e-6)
nan
>>> get_coating_material_index('Ta2O5', 1.0e-6)
nan
>>> get_coating_material_index('TiO2', np.arange(400e-9, 1600e-9, 100e-9))
# NaN at index for 1000 nm
```

**Severity**: P2 — INSIDE documented validity (400-5000nm TiO2, 350-8000nm Ta2O5). Test coverage `test_v5_4_coating_materials.py:172` samples only 500-700nm. Realistic 100nm-step vis-NIR sweeps hit λ=1000nm exactly.

**Fix**: Replace `(1.0, 1.0)` with `(0.0, 0.0)` (then `lam2 - C = lam2 > 0` for all positive λ), OR add a `B == 0` short-circuit in `_coating_sellmeier`.
