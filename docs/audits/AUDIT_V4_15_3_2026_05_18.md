**Date:** 2026-05-18
**Library state:** v4.15.3 at HEAD `7808107`.

## TL;DR

**v4.15.3 closes the v4.15.2 audit at the core level** — all 1 P0 + 4 P1 closures VERIFIED with non-tautological pins (V1); 6 of 8 P2/P3 fully verified (V3). The structural counter-measure (`_validation.py` helper + AST-walking dispatcher meta-pin) is a genuinely strong piece of engineering: 102 LOC of clean helper code, 7 dispatcher-pin tests + 30 sibling-guard tests all pass, lazy import correctly dodges a documented circular-dependency risk, error messages are actionable (cite `v4.16+`, name the function, include copy-pasteable ensemble-iteration snippet). All 5 dispatcher meta-pins (cache-clears, cache↔lock, 0+0j, `_validate_grid_params`, and the new `_check_2d_scalar_field`) remain clean across the 1822-test suite. All 6 v4.16+ deferrals verified intact (no stealth implementation).

**However, this audit identifies 1 NEW P1 + 6 NEW P2 + 5 NEW P3** — and the **most important meta-finding is that the very release shipped to retire the sibling-gap meta-pattern itself contains a sibling-gap recurrence**. The dispatcher meta-pin scopes to `lumenairy/propagators/` + `lumenairy/elements/` only, missing four public entry points that accept 2-D scalar fields: `system.py::propagate_through_system_jax` (an unguarded sibling of the v4.15.2-guarded `propagate_through_system` in the **same file**), `analysis/ao.py::apply_dm`, `analysis/detector.py::apply_detector`, `analysis/through_focus.py::apply_perturbations`. **Three independent agents (V2 HIGH, F1 P1, F2 P2) converged on this finding without coordination.** The walker is correct in its declared scope; the scope itself is the new sibling gap.

**Headline new findings (sorted by severity):**

1. **🔴 P1-NEW-3WAY-1: `propagate_through_system_jax` is an unguarded sibling outside walker scope** (V2 + F1 + F2 3-way confirm). The structural counter-measure was scoped to `('lumenairy/propagators', 'lumenairy/elements')`. `system.py` lives at the package root. v4.15.2 guarded `propagate_through_system` (at `system.py:275`) but the JAX sibling at `system.py:1043` has no guard and is invisible to the walker. **A user passing `PartialCoherenceMCF` or 3-D ensemble to `propagate_through_system_jax` gets a confusing JAX-tracer error or silent wrong-axis broadcast** — exactly the failure mode the structural counter-measure was supposed to eliminate, recurring inside the release that ships it.

2. **🔴 P2-NEW-3WAY-2: `apply_dm`, `apply_detector`, `apply_perturbations` in `lumenairy/analysis/` are unguarded** (V2 + F1 + F2 3-way confirm). Three more public `apply_*` entry points outside walker scope, all accepting 2-D scalar fields. Same root cause as P1-NEW-3WAY-1 (`_TARGET_PACKAGES` choice), one severity tier lower because `analysis/` is less likely to be on a Schell-source data path than `system.py`.

3. **🔴 P2-NEW-F1-A: CHANGELOG line 80-83 contradicts the SAS-anamorphic fix** (F1). CHANGELOG says: *"v4.15.3 forces `method='asm'` regardless of `self.method` when `dy != dx`"*. The actual code (`algebra/primitives.py:148-150`) only forces `method='asm'` when `self.method == 'auto'`. Explicit `method='sas'` on anamorphic input still crashes. The in-code comment correctly documents this as intentional ("explicit `method=` choice is the user's responsibility"); only the CHANGELOG misstates the scope.

4. **🔴 P2-NEW-V2-1: Walker name regex misses `richards_wolf_focus`, `debye_wolf_psf`** (V2). Both in `propagators/vector_diffraction.py` accept 2-D scalar pupils. The walker IS in the right package, but the name regex (`apply_*` / `*_propagate*` / `propagate`) doesn't match. An `__all__`-based discovery (or augmented name list) would catch these.

5. **🔴 P2-NEW-V3-3: ROADMAP.md stale** (V3 + F2 2-way confirm). CHANGELOG line 155-156 explicitly claims *"ROADMAP '~1700' → updated to the v4.15.3 baseline 1822"*; ROADMAP.md line 32 still says *"post-v4.15.3 unit-test count is expected to land at ~1750"*. The ROADMAP update CHANGELOG claims wasn't actually done. Plus: AUDIT_V4_15_2 missing from ROADMAP's closed-audits list (line 38-41); ROADMAP line 50 says "3 of 5 meta-pins" (should be 4 of 5 with the new `_check_2d_scalar_field`).

6. **🔴 P2-NEW-F1-D: `_validation.py` lazy import is unnecessary** (F1). The comment at line 55 claims the lazy import avoids a circular dependency from `sources.core`, but `sources.core` doesn't import from `_validation` (grep-verified). The circular import risk is hypothetical. The lazy import runs `sys.modules` lookup once per propagator call, adding ~1 μs/call (1-10 ms wasted per merit eval in optimization loops). Hoist to module scope.

**Verdict:** v4.15.3 is **the cleanest closure release in the v4.15.x series** — only 1 P1 finding (and it's the meta-pattern recurrence itself, not a novel bug class). The structural counter-measure is genuinely valuable engineering; the new P1 finding actually *reinforces* the value of the helper by showing how easy it is to forget to extend the walker scope. **Tier-0 v4.15.4 patch (~80 LOC, ~3 hours)** would extend `_TARGET_PACKAGES`, broaden the name discovery (or use `__all__` membership), guard the 4 newly-found siblings, fix the CHANGELOG-vs-code wording, hoist the lazy import, refresh ROADMAP, and add a fake-violation counter-pin for the new dispatcher meta-pin.

## Part 2 — New findings (P0/P1/P2/P3)

### P1 findings (1)

**P1-NEW-3WAY-1 — `propagate_through_system_jax` unguarded sibling outside walker scope** (V2 + F1 + F2 3-way confirm)

- File: `lumenairy/system.py:1043`
- Sibling guarded site: `lumenairy/system.py:275` (`propagate_through_system`)
- Walker scope: `tests/unit/test_v4_15_3_dispatcher_pin_2d_scalar_field.py:39` — `_TARGET_PACKAGES = ('lumenairy/propagators', 'lumenairy/elements')`
- **Root cause:** the walker's package scope was chosen to match the v4.15.2 audit's listed entry points; `system.py` (which is at package root, not under `propagators/` or `elements/`) was missed. Function name `propagate_through_system_jax` contains `propagate`, so it WOULD match the walker's name filter if the walker visited `system.py`.
- **User-facing failure mode:** identical to the v4.15.1 `PartialCoherenceMCF` confusion that the structural counter-measure was supposed to eliminate. JAX tracer error or silent wrong-axis broadcast depending on the first non-traceable op.
- **Severity P1** (not P0): the entry point is named `_jax`, which signals "advanced/specialized" — a user pulling Schell ensembles into JAX-traced optimization is the most likely victim, but they're typically a more experienced user. Still: textbook "fix N, miss N+1" recurrence in the release that ships the structural counter-measure.

### P2 findings (6)

**P2-NEW-3WAY-2 — 3 unguarded `apply_*` siblings in `lumenairy/analysis/`** (V2 + F1 + F2 3-way confirm)

- `lumenairy/analysis/ao.py:314` `apply_dm(E_in, dm, scale)`
- `lumenairy/analysis/detector.py:32` `apply_detector(E, ...)`
- `lumenairy/analysis/through_focus.py:635` `apply_perturbations(...)`
- Same root cause as P1-NEW-3WAY-1 (walker scope choice). `analysis/` package outside `_TARGET_PACKAGES`. Function names match the walker filter; would be discovered if walker visited.
- Severity P2 (vs P1 above) because `analysis/` is downstream of propagation and less likely to be the first contact point for a Schell-source data path. But the gap exists.

**P2-NEW-V2-1 — Walker name regex misses `richards_wolf_focus`, `debye_wolf_psf`** (V2)

- File: `lumenairy/propagators/vector_diffraction.py:30, 267`
- Walker IS in the right package (`propagators/`) but name regex (`apply_*` / `*_propagate*` / `propagate`) doesn't match `richards_wolf_focus` or `debye_wolf_psf`.
- Both accept 2-D scalar pupils per docstring.
- **Fix:** either augment the walker's name list explicitly OR walk `__all__` membership of each module (more robust).

**P2-NEW-F1-A — CHANGELOG line 80-83 contradicts the SAS-anamorphic fix** (F1)

- File: `CHANGELOG.md:80-83` vs `lumenairy/algebra/primitives.py:148-150`
- CHANGELOG says: *"v4.15.3 forces `method='asm'` regardless of `self.method` when `dy != dx`"*

- Explicit `method='sas'` on anamorphic input still crashes with `TypeError: scalable_angular_spectrum_propagate() got an unexpected keyword argument 'dy'`.
- The in-code comment (lines 142-147) correctly documents the gating; only the CHANGELOG misstates scope.
- **Fix:** CHANGELOG line 82 should read *"v4.15.3 forces `method='asm'` when `self.method == 'auto'` and `dy != dx`. Explicit `method='sas'` on anamorphic grids still crashes (user's responsibility)."*

**P2-NEW-F1-D — `_validation.py` lazy import is unnecessary, adds per-call overhead** (F1)

- File: `lumenairy/_validation.py:56`
- Lazy `from lumenairy.sources.core import PartialCoherenceMCF as _MCF` inside the function body
- Comment at line 55: *"Lazy import avoids a circular dependency from `sources.core`"* — but `sources.core` doesn't import from `_validation` (grep-verified). Circular import is hypothetical.
- Cost: each propagator call does `sys.modules` lookup + module-attribute lookup. ~1 μs/call; in optimization loops calling `propagate()` 1000s of times per merit eval, 1-10 ms wasted per eval.
- **Fix:** hoist `from .sources.core import PartialCoherenceMCF as _MCF` to module scope. If a future circular import is detected, use `TYPE_CHECKING` import + duck-typed predicate.

**P2-NEW-F1-B — `_PerturbedABCDFallbackSentinel` "dead code" marker is informational-only** (F1)

- File: `lumenairy/optimize/core.py:2130-2185`
- `_v4_15_3_dead_code: bool = True` is a class attribute. No static analyzer (mypy, ruff) honors this as a real dead-code marker — it's data.

The narrowing is real — from 9 missed siblings in v4.15.2 to 4 in v4.15.3. But the meta-pattern itself remains alive at one level of indirection (package-level rather than function-level).
