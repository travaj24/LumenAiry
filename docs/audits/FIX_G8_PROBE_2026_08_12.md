## 1. THE DEFECT -- "held out" was held out of one arm only

G8 as shipped (`BUILD_INVERSE_MAP_2026_08_11` S3.1):

1. hold out the launch nodes with `i % 3 == 1 and j % 3 == 1`;
2. fit the model on the rest;
3. score it at those nodes against the exact traced `(x_in, y_in, OPL)`;
4. score the INCUMBENT at the same points;
5. refuse unless the model wins on max, rms and entrance position.

Step 4 is where it breaks.  The incumbent is not a second model of the
landings -- it is the element's own `_invert_newton` on the element's own
forward fits, and what those fits ARE depends on `newton_fit`:

| basis | forward fit | error at a launch node |
|---|---|---|
| `polynomial` | global total-degree least squares | genuine residual -- its production error |
| `spline` | `RectBivariateSpline(..., s=0)` | **zero by construction** (it interpolates) |

So on the spline basis the number G8 read at its probe points was the Newton
loop's leftover residual against a reference that is exact there.  The model,
which has no lattice structure at all, was scored honestly.  A comparison
between an arm measured at its one exact point and an arm measured everywhere
is not a comparison.

`tests/unit/test_fix_d5_fit_domain_basis.py::
test_a_node_probe_cannot_measure_an_interpolating_incumbent` pins this at the
level it lives -- the two bases, no element call in the way: a smooth
non-separable map on a 41 x 41 lattice, `RectBivariateSpline` exact at its
knots to `< 1e-6` of its own midpoint error, a total-degree-6 least-squares
fit equally (in)accurate at both.

## 3. THE RE-ARCHITECTURE

### 3.1 Where the probe goes

`_probe_entrance_points(xs_in, census)` -- deterministic, basis-free, and it
reads only the launch lattice and a boolean mask:

* **one probe per launch CELL** `[i, i+1] x [j, j+1]`, eligible only when all
  FOUR corners are census nodes.  So no probe sits on the boundary of the
  region the guard judges, and every probe is surrounded by traced rays rather
  than by extrapolation;
* **placed INSIDE the cell by the R2 low-discrepancy sequence**
  (`_IMAP_PROBE_R2`, the plastic number).  NOT the cell centre: a bicubic's
  error is maximal at the centre and zero at the corners, so centre-probing
  would read the incumbent's worst case and hand the model an easier bar than
  production.  Exit pixels land uniformly, so the honest offset distribution
  is uniform over the cell -- and R2 gives that with no seed, no randomness
  and nothing to tune;
* **strided, not truncated**, to a budget of `_IMAP_PROBE_MAX = 1024` rays
  with the leftover split between the two edges, so the probe set stays
  centred on the census and spread across it.  1 024 rays is 2.0 % of design
  121's 52 441-ray trace and 3.1 % of the C6 fixture's 32 761;
* **refuses below `_IMAP_PROBE_MIN = 32`** -- the same floor the node probe
  used.  A comparative bar decided on fewer samples than that is decided by
  one ray.

Because the inputs are the launch lattice and the census mask, and both are
basis-independent after fix D5, **the two `newton_fit` backends are compared
at bit-identical points** -- asserted, and measured at 632 points on the C6
fixture.

### 3.2 Where the truth comes from

`build_inverse_map` gained one parameter, `probe_trace(x_in, y_in) ->
(x_out, y_out, opl)`: the element's own trace of the element's own launch
congruence at arbitrary entrance points.  The guard chooses the points; the
element supplies only the congruence.  Without it the build REFUSES, with the
same posture as a build with no `parity_invert` -- a comparative bar whose
ground truth one of the arms defines is not a bar, and falling back to the
lattice is precisely the defect.

`_imap_probe_trace` in `apply_real_lens_traced` reproduces the lattice trace
term for term and from the same objects: the launch directions (including
niche C6's `grad(a_fit)` augmentation), the exit-vertex correction, the H6
carrier eikonal, the C6 residual eikonal, and the SAME on-axis reference
`_opl_ref`.  **It is pinned BIT-IDENTICAL**: handed the launch lattice it
reproduces `x_out_grid` / `y_out_grid` / `opl_grid` exactly (0.0 on both
bases, `test_the_probe_trace_is_the_element_s_own_lattice_trace`).  A probe
trace that merely agreed closely would be a second model of the element rather
than the element.

It does not touch `_resid_eik.diag`: the launch diagnostic belongs to the
lattice trace, and a probe that overwrote it would be reporting itself.

### 3.3 What did NOT change

* **The bar.**  `_IMAP_PARITY_FACTOR` is still `1.0`, still a RATIO and not a
  wave tolerance, and still all three channels.
* **THE ENVELOPE RULE.**  All three channels must hold, each of them a WORST
  CASE over the same probe set: a model that is typically better and
  occasionally worse is not at parity, and neither is one that wins on OPL
  while losing entrance position -- the channel the ray-density amplitude and
  the C8 taper both read.  Measured value: on the C15 fixture a degree-6 model
  WINS the OPL channel at 0.60x and is refused anyway, at 1.49x on position.
* **The scoring region.**  Still the constrained region, for the reason G2's
  census is: outside the ray-fit disc both arms extrapolate, `|E_in|` is
  negligible, and a max-over-samples comparison of two extrapolations decides
  the bar by coin flip.  The probe points inherit it by construction now
  (a cell is eligible only if all four corners are in it), so the second
  restriction the node probe applied at scoring time is gone.
* **No new tuned constant.**  `_IMAP_PROBE_MAX` / `_IMAP_PROBE_MIN` are a cost
  bound and a sample floor, not accuracy thresholds; `_IMAP_PROBE_R2` is the
  plastic number.

### 3.4 One simplification fell out

The model is no longer refitted for the probe.  The node probe had to solve
twice -- once without the held-out nodes to score, once on everything to ship
-- so the arm on trial was a DIFFERENT polynomial from the one the caller
gets.  An off-lattice probe withholds nothing, so `_solve()` runs once and G8
scores the shipped coefficients.  `test_the_guard_scores_the_coefficients_
that_ship` re-derives the recorded numbers from outside the guard, by
evaluating the RETURNED model at independently recomputed probe points.

Three, all in `test_fix_d5_fit_domain_basis.py`, all the same mechanism: they

| test | change |
|---|---|
| `test_the_arbiter_is_announced_when_the_basis_cannot_honour_it` | scores with `inverse_map=False` |
| `test_an_inert_fit_domain_knob_is_announced_not_silent[fit_radius_beam_factor]` | scores with `inverse_map=False` |
| `test_an_inert_fit_domain_knob_is_announced_not_silent[decentred_fit_poly_order]` | scores with `inverse_map=False` |

**The claim they make is unchanged and it is the one the code makes**: fix D5

Both are in the niche-C6 suites, and both are the same shape as S6.1: a knob
or a defect that lives in the FORWARD fit stops being observable in the

## 9. WHAT IS NOT CLOSED

1. **The two bases disagree at exit degrees 10 and 12** (S4.2).  Not a defect
   -- the bar is the incumbent's own error and the two incumbents differ by
   134x off-lattice -- but it means "both bases engage" is a property of the
   SHIPPED degree, measured, not a structural guarantee.  A future degree
   change must re-measure it on both bases.
2. **The S6.5b fail-before is expressible only on the DECENTRED branch.**  On
   a concentric NaN-masked branch the pre-restriction landings never reach the
   builder, so that arm reports "not expressible" rather than a number.  The
   mechanism is the same on both branches; only the reproduction is not.
3. **The probe costs rays.**  Up to 1 024 per build, 2-3 % of a trace the
   element has already paid for.  It is inside the build, so it is cached with
   it and a repeated identical call pays once -- but a caller that rebuilds
   many small maps pays it every time.
4. **`_IMAP_PROBE_MAX = 1024` is a cost bound that has not been convergence
   tested.**  The C6 fixture's census (632 cells) is under it, so that
   measurement is at full density; design 121's is strided at 3.  Nothing here
   measures how the guard's verdict moves with the probe count.
5. **Nothing here was run on GPU or through
   `apply_real_lens_traced_multi`'s prepared-screen reuse.**  `use_gpu=True`
   forces `newton_fit='polynomial'` and is excluded from the map's own gate,
   so the probe is unreachable there by construction -- an argument, not a
   measurement.
6. **The acceptance line in `focus_scan_121.py` is NOT edited by this work.**
   The re-baseline is the orchestrator's to apply at merge; S7 reports the
   numbers that are its case.

## 10. FILES AND REPRODUCTION

```
# the c6 backend spread, flag off and on
python scripts/_d5_probe.py

# the probe trace vs the lattice trace, the probe points on both bases,
# and G8's record arm by arm
python scripts/_g8_probe.py

# the exit-degree ladder and the unrestricted model, both bases
python scripts/_g8_failbefore.py

# design 121: the shipped arm, the S6.5b pre-restriction arm, the underfit
# (this driver imports lumenairy itself, before _d121_common can redirect it)
cd validation/repro_traced_carrier_121
G8_NFC=4096 python g8_probe_121.py

# the shipping banner, one arm per invocation.  PYTHONPATH IS REQUIRED here:
# imap_banner_arm.py is a shipped driver and is not modified by this fix, so
# the worktree has to be put on the path from outside it.
cd validation/repro_traced_carrier_121
PYTHONPATH=<repo root> ARM_IMAP=0 python imap_banner_arm.py
PYTHONPATH=<repo root> ARM_IMAP=1 python imap_banner_arm.py
```

Every script inserts the REPOSITORY ROOT at `sys.path[0]` before importing
`lumenairy`; without it a driver silently measures the INSTALLED tree instead
of the working one.  **It bit once during this fix and it is worth recording
how it looked**, because the failure is silent by construction: the design-121
arms were first run from `validation/repro_traced_carrier_121/`, whose own
directory is `sys.path[0]`, so `import lumenairy` resolved to the INSTALLED
checkout -- a tree with the OLD node probe.  The arms still printed plausible
parity numbers and the two fail-befores still refused, so nothing looked
wrong.  **The tell was a `None`**: `n_probe_requested` came back empty in the
JSON because that key does not exist in the installed tree.  The driver now
inserts the root itself (`g8_probe_121.py`), and the check that catches this
class of error in one line is::

    python -c "import lumenairy; print(lumenairy.__file__)"

run from the directory the driver runs in.
