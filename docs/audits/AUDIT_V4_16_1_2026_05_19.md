**However, this audit identifies 3 NEW P1 + 8 NEW P2 + 9 NEW P3** — concentrated in (a) places the verifier audits couldn't see because the test pins themselves don't exercise the production path, and (b) the documentation surfaces the 10 V-walkers don't cover.

**Headline new findings (sorted by severity):**

1. **🔴 P1-NEW-F1-1: `_transfer_jax` high-NA RuntimeWarning is STRUCTURALLY UNREACHABLE in production user flow.** The eager-mode gate at `jax_trace.py:565` uses `isinstance(direction_n, np.ndarray)`. But `make_jax_ray_state(...)` at lines 99-115 calls `jnp.asarray(N)`, converting to `jax.Array` / `jaxlib.xla_extension.ArrayImpl` — **NOT a subclass of `np.ndarray` since JAX 0.4+**. Inside `trace_jax(...)`, `_transfer_jax` is invoked with JAX-array `state.N` at lines 966, 1006, 1555. The predicate returns early on EVERY production path. **All 4 tests in `test_v4_16_1_agent_b.py:519-678` construct `JaxRayState` DIRECTLY with `np.array(...)`, bypassing `make_jax_ray_state`** — no integration test calls `trace_jax(...)` end-to-end with a high-NA bundle. The audit's user-facing claim ("high-NA users get an explicit one-shot RuntimeWarning") is silently false; the closure is dead code in user flow.

2. **🔴 P1-NEW-F1-2: `propagate_ensemble` silently downcasts CuPy/JAX backends to NumPy.** At `ensemble.py:252`, `np.asarray(ensemble)` triggers GPU→CPU transfer for CuPy `cp.ndarray` and forces concretization for JAX `jax.Array`. The per-realization loop feeds NumPy slices to the propagator, defeating any backend-specific kernel. **Docstring at :249-253 explicitly advertises "Tolerate duck-typed array protocols (CuPy, JAX)"** — the opposite of what the code does. Users who built their Schell ensemble on GPU get silent transfer + CPU loop. Fix: `xp = array_namespace(ensemble); xp.abs(...)**2`.

3. **🔴 P1-NEW-F1-3: `MultiWavelengthMerit` SUM→AVG is a SILENT behavior change** with no `FutureWarning` / `DeprecationWarning`. The CHANGELOG frames this as a "silent bug fix" but it is also a silent regression vector: existing user-calibrated 3-wavelength weights now produce merit values 3× smaller. Published `design_optimize` recipes silently produce different optimum positions for the same starting point. A one-cycle `FutureWarning` when `len(wavelengths) > 1` would have alerted users their existing scripts now behave differently.

4. **🔴 P1-NEW-F2-HIGH-1: `README.md` ↔ `pyproject.toml` dependency declaration drift** (cross-cutting meta-pattern recurrence). README.md:4089, :4116 still list `refractiveindex` as a **Required** dependency and include it in `pip install numpy refractiveindex` — but `pyproject.toml` moved it to `[glass]` extras this release. **Same class of bug** (silent doc drift) that GLASS_VALIDITY consistency check retired structurally — but on the README surface, no walker exists.

5. **🔴 P1-NEW-F2-HIGH-2: `requirements.txt` ↔ `pyproject.toml` dependency drift.** `requirements.txt:5` still lists `refractiveindex>=1.0`; line 20 still lists `zarr>=2.14` (bumped to `>=3.0` this release). Same sibling-gap class, different surface.

**Verdict:** **The substantive code work is exceptional.** Zero P0; all 4 correctness bugs verified with sibling-gap sweeps; the new `propagate_ensemble` helper math is provably correct; the 10th meta-pin walker has both positive and negative counter-pins; 4-way convergent glass-comment finding correctly fixed. **The blemish is structural meta-pattern recurrence in documentation surfaces:** the very release that hardened code-side consistency (`@lru_cache↔registry`, `GLASS_VALIDITY↔GLASS_REGISTRY`) shipped with README/requirements.txt/ROADMAP/CHANGELOG arithmetic all stale. **P1-NEW-F1-1 — `_transfer_jax` high-NA RuntimeWarning is structurally unreachable in production** (F1)
- File: `lumenairy/raytrace/jax_trace.py:565`
- Gate: `if not isinstance(direction_n, np.ndarray): return`
- Production user flow: `make_jax_ray_state(N=...)` at `:99-115` calls `jnp.asarray(N)` → `jax.Array` (NOT `np.ndarray` subclass since JAX 0.4+)
- `_transfer_jax` invoked at `:966, :1006, :1555` with JAX-array `state.N` → gate returns early on EVERY production path
