## Part 1 — P1 findings

### P1-A (NEW, headline) — RCWA zeroes transmittance into ANY lossy exit substrate

`rcwa_efficiency_1d`, `rcwa_efficiency_2d`, and `rcwa_jones_1d` return **T=0 for every order** the instant the exit substrate has loss (κ≥0.001), silently corrupting the energy balance. Lead-confirmed on a bare Fresnel interface (vacuum → n₂):

| n₂ | RCWA R+T | Fresnel R+T | RCWA T | true T |
|---|---|---|---|---|
| 1.5+0j | 1.0000 | 1.0000 | 0.96 | 0.96 ✓ |
| 1.5+0.001j | 0.040 | 1.0000 | **0.000** | 0.96 |
| 1.5+0.1j | 0.042 | 1.0000 | **0.000** | 0.9585 |
| 1.5+0.5j | 0.077 | 1.0000 | **0.000** | 0.9231 |

- **Isolated to the substrate:** a lossy *layer* with a lossless substrate is fine (R+T=0.334, A=0.666 physical). Only the lossy *exit half-space* triggers it.
- **PMM is correct** (matches analytic Fresnel), so it's RCWA-specific. `@ rcwa/oned.py:553` (`rcwa_efficiency_1d`), `oned.py:880` (`rcwa_jones_1d`), `twod.py` (2-D). The transmitted-flux weight `Re(kz_sub/kz_inc)·|t|²` is being dropped/zeroed because a lossy substrate's orders are all complex-kz and get classified as non-propagating, when they still carry net forward flux.
- **Why every prior audit (incl. mine) missed it:** we always probed lossy *layers/cells* with lossless half-spaces; the lossy *exit substrate* regime was a blind spot. This cycle's energy sweep specifically targeted it. **Likely long-standing, not a v5.12.0 regression** (a git-bisect would confirm).
- **Impact:** any device with an absorbing substrate — metal back-reflector, doped Si, absorbing exit medium, index-matched lossy output — gets wrong transmittance and a corrupted power budget. High-impact for real modeling.

**Remediation:** compute transmitted efficiency as `Re(kz_sub)/Re(kz_inc)·|t|²` with the *complex* substrate kz (the propagating-into-lossy-medium flux), not a real-kz propagating mask. Add a lossy-substrate energy-balance regression test (vs analytic Fresnel/TMM).

### P1-B — `fff_nv` curved-wall ~50% absorption mis-split is warn-gated, not fixed (my prior P1-A)

v5.12.0 "addressed" my v5.11.0 P1-A by adding a **non-blocking `UserWarning`** (commit `a01f73b`, `rcwa/twod.py:514-524`: `if _nv_cross > 1e-2: warnings.warn(...)`) — **not** a raise, and **not** a corrected factorization. Re-confirmed live: lossy metal disk (eps=−15+3j, M9) `fff_nv` A=0.1404 vs `li`-oracle A=0.2916 (**~52% mis-split**), `warned=True`. A user who suppresses or ignores warnings still silently gets the half-wrong absorptance. The team's own `RCWA_PMM_POST_REORG_AUDIT_2026_06_09` independently re-flags this as P1 ("text-only warning doesn't block"). The disk regression test now *asserts the bug* (`A_nv < 0.6*A_li`) with an honest "replace this when fixed" comment. **Still P1.**

**Remediation:** either correct the NV curved-wall cross-term factorization, or **raise** (not warn) on non-separable geometry so a wrong number can't silently propagate.

### P1-C? (contested) — PMM covariant-slant may share the lossy-exit-substrate issue

The team's post-reorg audit flagged a P0: `_pmm_jones_oblique_solve` conjugates eps to the internal `exp(+iωt)` convention but `kz_ord` (`pmm/_core.py:3569-3571`) selects forward/backward via the *public*-convention `Im(kz)<0` rule on conjugated eps. My energy + org verifiers found the covariant path **correct for a lossy grating with lossless half-spaces** (dA=1.3e-5 vs oracle), and the org verifier **refuted** the related CHANGELOG-honesty claim. So this only plausibly bites for a **lossy exit half-space** — the same regime as P1-A. **Open:** a targeted covariant probe with a lossy substrate is needed; likely the same root flux issue. Reported at lower confidence than P1-A/B.

## Part 2 — P2 findings

**P2-A — 2-D PMM efficiency return arity changed (4-tuple → 3-tuple).** `pmm_efficiency_2d`/`_staggered` now return `Efficiency2D(orders,R,T)` (3-unpack, with `dof` as an attribute) where v5.11.0 returned a bare 4-tuple `(orders,R,T,dof)`. External `o,R,T,dof = pmm_efficiency_2d(...)` callers break. Verifier-confirmed; the team self-labels commit `37334de` "the breaking part" — so the v5.12.0 "public API unchanged" headline is overstated for these two entry points. (It *is* a cleaner unified return; just not backward-compatible.) `@ pmm/twod.py:480`.

**P2-B — Covariant OOP "floor 1e-2→1e-4" overstates accuracy.** vs an independent RCWA full-3×3 z-staircase oracle (n_slabs=200, validated to 1e-6 at slant=0), the covariant OOP wall-normal **TM** channel floors at **~2.5e-3** at slant=45 (deg16→28: 2.57e-3→2.47e-3, a *plateau*), not 1e-4. The "1e-4" is measured against the **convection** PMM path, which shares the identical wall-normal inverse-rule floor — self-referential. The TE channel is clean (<8e-4). So the *capability* is real (the "structurally impossible" claim is genuinely refuted — it converges spectrally), but the accuracy headline should read ~2.5e-3 vs independent ground truth. `@ pmm/_core.py:3825` (docstring).

**P2-C — PMM covariant forward-mode rebalance mixes incommensurate scales unnormalized (followup F5 still open).** `_cov_split` (`pmm/_core.py:3506-3509`) does `argsort(np.where(|Im(kz)|<tol, Sz, Im(kz)))` — sorting across Poynting flux `Sz` (~length²) and dimensionless `Im(kz)` **without normalization**, in the branch where the initial forward-count ≠ half. The shipped RCWA analog *was* normalized. Verifier confirmed real wrong-physics impact in that rebalance branch (P2, not escalated because the public default slant path doesn't hit it). The followup audit's claim that F5 was "fixed" is inaccurate.

**P2-D — Eager `jax`+`numba` imports dominate cold start (~21s).** Unchanged from last cycle (still the #1 speed lever). `import lumenairy` pulls jax+jaxlib+numba (1401 modules); root-caused to `raytrace/jax_trace.py:787` (pytree registration at module load) + `lenses.py:76` (top-level `import numba`). Both deferrable; numba has pure-NumPy fallbacks. Verifier-confirmed.

*(Adjusted down by verifiers: 16 untagged releases → P3; RCWA/PMM-not-optimize-merits → P3; asymmetric-OOP-no-passive-solve → P3. Refuted: per-wavelength-eig-reuse "P2" — non-dispersive indices still change Kx with λ, so the eig genuinely must be recomputed.)*

- **16 untagged releases** (v5.5.3..v5.11.0 incl. 5.10.1-5.10.6) — git jumps v5.5.2 → v5.12.0; the backlog grew.
