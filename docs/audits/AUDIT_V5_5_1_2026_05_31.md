My AUDIT_V5_5_0 headline finding — that lumenairy's RCWA distributes oblique-TM diffraction-order power wrongly (26× over the claimed grcwa bound) — **does not hold up, and I am retracting it.** The evidence, assembled this cycle:

## Part 5 — Speed / compute optimization (NEW user ask, P1)

**The single highest-leverage change: cap BLAS threads. ~100-300× speedup, zero numerics change, effort S.**

On this box (scipy_openblas64 0.3.31, DYNAMIC_ARCH MAX_THREADS=24, Py 3.14), every LA primitive gets *dramatically slower* with more threads — the non-symmetric eigensolver (`zgeev`, largely serial) + the S-matrix BLAS3 thrash under oversubscription:

| threads | eig (2N=246) | inv | solve | matmul |
|---|---|---|---|---|
| 1 | 1573 ms | 109 | 120 | 45 |
| **2 (optimum)** | **565** | **25** | **17** | **6** |
| 4 | 4735 | 183 | 148 | 18 |
| 24 (default) | ≫ | — | — | — |

End-to-end: n_orders=41 warm solve was **159 s** under default threads → **~1 s** at 2 threads. n_orders=61: 371 s → 3.65 s.

**Phase breakdown (threads capped):** S-matrix assembly (Redheffer + interface) **58-65%** > layer eig **29-37%** > region modes 4-5% > Fourier/Toeplitz **1-2%**. (R3's "pure-Python Toeplitz loops" claim is stale — the rework vectorized them to one FFT + a strided index.) Empirical complexity with sane threads is a clean ~O(N³); the apparent O(N⁶⁻⁸) under default threads was the contention artifact.

**Ranked roadmap:**
1. **BLAS thread cap to 2** (S, ~100-300×, zero risk) — wrap the eig + S-matrix core in `threadpoolctl.threadpool_limits(2, 'blas')` (threadpoolctl ships with numpy); add `rcwa.set_blas_threads()`. Optimum is 2, not 1. *This dominates everything.*
2. **1-D Ky=0 block-decouple** (M, ~2.8-3.2×, exact) — for planar 1-D, the 2N eigenproblem splits into independent N×N TE/TM blocks (off-diagonal blocks are exactly zero); a single-polarization call needs only its block's eig. Doesn't apply to conical/2-D/anisotropic.
3. **Lazy-import jax** (S, drops ~50-84 s off cold startup) — `raytrace/__init__.py:78` eagerly pulls jax; RCWA never needs it at import. Convert to PEP-562 lazy `__getattr__`.
4. **eigh for symmetric TE** (M, up to ~8×, CONDITIONAL/medium-risk) — only for lossless + symmetric-profile TE (the block is complex-symmetric, not Hermitian, in general). Gate behind a strict Hermitian check or skip.
5-8. Sweep-aware solver (~2-5% only — eig is λ-dependent, can't hoist); homogeneous cache (ineffective for sweeps); **GPU not viable** (cuSOLVER has no non-symmetric `geev`); jax-jit/numba marginal (wrap the same LAPACK eig).

**Bottom line for spectral-sweep + inverse-design workloads:** thread cap (#1) turns 159 s/solve into ~1 s; add the Ky=0 decouple (#2) for another ~3× on 1-D spectra; lazy jax (#3) for startup. Side finding: install MKL-backed numpy for a further several-× on the eig itself (zero code change). Also: R3's old benchmark used `period=0.8 metres` (a typo for µm) — a degenerate all-evanescent regime with nonphysical energy; timing conclusions hold but future benchmarks should use physical geometry.

## Part 6 — Library integration (NEW user ask, I1)

**The end-to-end pipeline is verified working today:** RCWA solve → `to_jones_field(nx,ny,dx)` → `jf.propagate(z,λ)` is **bit-identical** to module-level `angular_spectrum_propagate`, exposing the entire JonesField pipeline (lens, mirror, all propagators, Stokes). Spatially-varying tiling via `apply_jones_matrix(callable)` already works (the metalens hook). `apply_reflection` non-mutation confirmed. Cache registry enrollment consistent.

**The key limitation + opportunity:** `to_jones_field` is **specular (zeroth-order) only** — but `solve()` already computes every order's complex `rx,ry,tx,ty` and **discards all but (0,0)**. Multi-order is a pure addition.

**Ranked integration roadmap:**
1. **Multi-order bridge** `to_jones_field(order=+1)` / `to_jones_orders()` (HIGH, S/M) — the data exists; unlocks the real metasurface story (a deflector/metalens puts most power in ±1). Each order is a tilted carrier → feed `propagate_tilted`.
2. **RCWA inverse-design via `optimize/`** (HIGH, M) — Example 13 hand-rolls gradient ascent; the library already has `JaxMeritTerm(fn, build_args)` that routes `jax.grad` through `design_optimize`. Gap: the driver always runs a lens ray-leg a metasurface has no prescription for (needs a `need_ray=False` short-circuit). Bigger win: co-optimize a rigorous DOE *inside* an imaging system.
3. System-pipeline `'metasurface'` element (M) — note the scalar `propagate_through_system` can only carry the (0,0) amplitude; the honest path is the JonesField chain.
4. **te/tm↔s/p alias + the missing RCWA→thin_grating reduction test** (S) — v5.5.1 already added the aliases; add the reduction pin to credibly claim the thin_grating upgrade path.
5. `tile_jones_response([RCWAResult], layout)` metalens helper (M) — formalize the per-pixel pattern; local-periodicity caveat must be documented.
6. Per-order Jones → LC/polarization co-sim (M, rides on #1).
7. RCWA Designer dock (M — none exists; thin_grating_dock/coatings_dock do).
8. Partial-coherence sweep (L, niche).

**Docs gap:** the cookbook RCWA recipe (+37 lines) demonstrates **standalone RCWA only** — not the RCWA→JonesField→propagation pipeline. Best demo to add: beam-deflector cell → `to_jones_field(order=+1)` → `propagate_tilted` → focal spot.
