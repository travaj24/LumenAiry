## 1. THE MECHANISM

### 1.1 A linear fit cannot see a branch cut

`np.angle` returns the principal value in `(-pi, pi]`.  Write the true exit
phase as `phi(x, y) = c + psi(x, y)` with `c` the element's global piston and
`psi` the wavefront.  What the metric receives is

```text
ph = wrap(c + psi)
```

and it then fits `ph ~ a0 + a1 x + a2 y + a3 (x^2+y^2)` in the LEAST-SQUARES
sense.  If `wrap()` is the identity on the data -- i.e. if `c + psi` happens to
lie inside one branch -- then `a0` absorbs `c` and the residual is the
wavefront.  If it is not, the data has a step of `2 pi` across a curve in the
pupil, the linear model cannot represent a step, and the fit spreads the error
into `a1`, `a2`, `a3` as well.  The residual is then dominated by the **cut**,
not by the optics.

No tolerance repairs this, because the corrupted value is not "a bit large" --
it is a different quantity.  The triplet cell reports `1.2869` rad for a
`0.0311` rad wavefront: **41x**, and in the direction that makes a GOOD design
look bad.

### 1.2 What made the luck run out

`mu`, the amplitude-weighted circular mean of the wrapped exit phase, is the
piston as the metric sees it.  Measured on the same fixtures:

| fixture | `mu` at v5.34.0 | `mu` on this branch | masked pixels within 0.35 rad of `+-pi` |
|---|---|---|---|
| P2 triplet w1.6 1.2x | `-0.894` | `-3.065` | **0.000 -> 0.986** |
| P2 triplet w1.6 2.5x | `-0.977` | `+3.138` | 0.000 -> 0.755 |
| P2 singlet w1.2 1.2x | `-0.505` | `+1.503` | 0.080 -> 0.061 |
| P2 doublet w1.0 1.2x | `-0.006` | `-1.465` | 0.000 -> 0.000 |
| E4 7 mm, guard OFF | `+1.338` | `-0.929` | 0.077 -> 0.130 |
| E4 7 mm, guard ON | `-1.322` | `+2.695` | 0.000 -> 0.171 |

The shift is 1.5-4.0 rad, i.e. `k0 * Lam(0) mod 2 pi` composed down the chain --
the restored constant, and on the triplet it is the `-2.1713` rad measured
directly off the field in S0.  The triplet's own phase cluster is only 0.47 rad
wide, so it survives a shift of up to ~2.9 rad and dies past that.  It got
2.171 rad and landed astride the cut.  The doublet, whose cluster is 0.018 rad
wide, would survive almost any shift -- and does.

### 1.3 Why only a few cells of twenty-four

Because the failure needs a coincidence: the cluster has to STRADDLE `+-pi`.
The 12 P2 cells and 12 E4 cells each drew an effectively arbitrary residue, and
a few lost.  That is also why the failing SET is **interpreter-dependent** --
CI reported three, this box reproduces four (S3) -- and why the fix's own local
verification never saw it: `Lam(0)` is ~5e+04 rad, so its residue mod `2 pi` is
set by the last ~5 digits of a double, i.e. by libm and BLAS.  **A CI failure
that moves between interpreters for this reason is a metric defect by
construction**: correct physics cannot depend on which decade of the mantissa
carries the piston.

## 4. THE FIX

Four lines of piston reference, in each file's own copy of the construction.
The two files already keep private copies of the whole meridional ray oracle
(`_system_surfaces`, `_trace_collimated`, `_oracle_*`), so a private copy of the
metric is this pair's established idiom rather than a new duplication.  In both
files the inline block is lifted into a named `_wavefront_rms(env, dx_out)` so
there is one place per file to guard.

```python
w  = amp[mask] ** 2
ph = np.angle(env)[mask]
mu = np.angle(np.sum(w * np.exp(1j * ph)))      # weighted CIRCULAR mean
ph = np.angle(np.exp(1j * (ph - mu)))           # de-rotate, then fit as before
```

**Why the circular mean and not something else.**  It is the choice that makes
the metric EXACTLY invariant rather than approximately so.  Under
`env -> env * exp(1j c)` the wrapped phase becomes `wrap(ph + c)` and the
weighted circular mean is **equivariant**, `mu -> wrap(mu + c)`, because it is
computed from the complex sum rather than from the (discontinuous) angles.  So
`wrap(ph - mu)` is unchanged pixel by pixel, and every number downstream --
design matrix, `lstsq`, residual, rms -- is unchanged bit for bit.  Measured: a
17-point sweep of `c` over `[0, 2 pi]` moves the rms by **3.9e-16 rad** (S5).

Alternatives tried and rejected:

* **Reference to the centre pixel.**  Invariant, but it reads one sample, so it
  imports that pixel's own noise into every cell.
* **Iterating the fit on the wrapped residual** (re-centre, refit, repeat).
  This is the textbook wrapped-fit refinement and it is WRONG here: on the two
  `singlet w1.2` cells -- whose genuine aberration spans 6.05 rad, i.e. 96 % of
  a full branch -- it converges to `0.3906` against a ray oracle of `0.7952`,
  because each pass folds real signal into the cut.  Single de-rotation gives
  `0.8400`, which is the answer that agrees with the independent oracle.  The
  refinement was dropped on that evidence, not on taste.

Everything else in both files is untouched: same mask, same weights, same design
matrix, same `lstsq`, same tolerances, same bars.

**The `singlet w1.2` cells remain the metric's weak point and are not repaired
here.**  Their wavefront error is genuinely ~0.84 rad rms, so the wrapped
residual still grazes the cut (6 % / 8 % of masked pixels) even after
de-rotation.  What the reference buys is that the remaining contamination is now
piston-INDEPENDENT: a fixed property of the fixture's own aberration, identical
at `v5.34.0` and on this branch to 1.3e-16, and well inside the `0.35 x oracle`
tolerance.  A metric that could measure > 0.8 rad rms cleanly needs 2-D phase
unwrapping, which is a larger change than a CI adjudication should make.
Recorded in S7.

## 5. THE GUARD

`test_wavefront_rms_is_invariant_under_a_global_piston`, one per file (the two
metrics are independent copies, so both need pinning).  Self-contained, no
chain, no library call, < 0.1 s: a Gaussian carrying a real quartic aberration
is swept through 17 global phases over `[0, 2 pi]` and the rms must not move.

| | rms over the sweep | spread |
|---|---|---|
| pre-reference construction | **0.2384 -> 1.3922 rad** (Strehl 0.944 -> 0.144) | **1.154 rad** |
| with the circular-mean reference | 0.346114 (flat) | **3.9e-16 rad** |

The bar is `1e-9 rad`: nine decades above the achieved spread and nine below the
pre-fix one, so it cannot be satisfied by luck in either direction.  **The
oracle is exactness itself** -- the answer must not depend on `c` at all -- which
is what makes this a guard rather than another calibrated row.  A second
assertion (`base > 0.2`) refuses to let the fixture degenerate into a flat
wavefront that would pass vacuously.

What the guard does NOT do is say anything about optics.  That is deliberate:
the physics assertions in both files were already correct and are unchanged;
what was missing was a check that the instrument reading them is an instrument.
