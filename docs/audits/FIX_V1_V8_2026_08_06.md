## 1. V3 (HIGH) -- the replica guard was `centre_out`-blind

### 1.1 Root cause

`_check_readout_replica` compared `N_out*dx_out` against the period and never
read `centre_out`.  The Bluestein reconstruction is periodic in the ABSOLUTE
output coordinate -- `E(u + p) == E(u)` identically -- so the faithful zone is
the interval `|u| <= p/2` about the FIELD's own origin.  Moving the window off
axis does not move that zone: it SPENDS it, and it spends it twice over,
because the window is symmetric about `centre_out` (the offset consumes
half-period on the near side and pushes the far edge out by the same amount).

The correct condition is per axis

```
2 * |centre_out| + N_out * dx_out  <=  period
```

and the shipped condition was that formula specialised to `centre_out == 0`.

transform is the RESIDUAL -- which is zero only if the caller happens to
centre the window on the chief ray.  At the DEFAULT `centre_out=(0, 0)` the

Synthetic N-BK7 singlet, collimated in, `r_in=TiltedCarrier(inf, L, 0)`,

```
  0.046    2.7662 mm   843.621 um    3.279 periods
```

With the guard waived, a window one WHOLE period from the chief ray returns a

```
  on the chief ray         peak|F| = 3.985110e+01
  chief ray + 1 period     peak|F| = 3.985110e+01
  chief ray + 2 periods    peak|F| = 3.985110e+01
```

After the fix, on the chain: the chief-ray window RETURNS, the +1-period window
and the default on-axis window both REFUSE, and an untilted chain (`L = 0`,

### 1.6 The EXACT readout -- the offset it weighs is also the residual

`carrier_referenced_exact_focus_readout` builds its fine grid CENTRED ON THE
CHIEF RAY and hands the Bluestein step `centre_out - centre`.  `_co` is now
resolved BEFORE the guard so the guard weighs that residual.  Consequence,
measured (beam at `centre = 0.2 mm` on a 1.024 mm grid, period 416.0 um):

```
  centre_out ON the chief ray (residual 0)   -> returned peak|F|=4.9451e-01
  centre_out one PERIOD off the chief ray    -> REFUSED
  centre_out on the OPTICAL AXIS             -> REFUSED  (span 419.2 um > 416 um)
```

A decentred congruence read out on its own chief ray costs NONE of its period,
however far off axis it sits -- which is the physically right answer and would
have been wrong under a naive absolute-`centre_out` guard.  The refusal message
says so explicitly on this path.

### 1.7 The multi orchestrator's `_fit` needed one pixel of headroom

`propagate_traced_carrier_chain_multi` snaps each congruence's window onto the
common lattice, so its centre sits up to `dx_out/2` from the chief ray per
axis.  Under the corrected condition that costs `2 * dx_out/2 = dx_out`, and
`_fit` previously sized the window to the FULL period -- so an 'auto' run could
size a window its own downstream guard then refused.  `_fit` now reserves
exactly one pixel, which covers the snap by construction.

## 2. V1 / V2 (MED) -- the small-extent standoff branch

### 2.1 Root cause

The shipped law `m_req = min(M, sat*ext)`, `f = m_req/sqrt(ext^2 - m_req^2)`
with `M = 3.2`, `sat = 0.866` degenerates below `ext = M/sat = 3.695`: there
`m_req = sat*ext` and

```
f = sat*ext / sqrt(ext^2 - sat^2 ext^2) = sat/sqrt(1-sat^2) = sqrt(3)
```

EXACTLY, for every extent and every NA.  So under 3.695 beam radii of grid the
"derived, extent-following" law was one more CONSTANT multiple of the Rayleigh
range -- 1.732 instead of 0.8 or 6.0 -- and that is exactly where the 9-cell
"worse than both" band sat.  (This is pinned as a fail-before witness in
`test_the_old_law_was_a_constant_below_the_threshold`, which evaluates the
shipped closed form in-line from the module's own constants and asserts it
returns `f_cap` at eight extents.)

The cap's justification is what fails.  "Past `growth` the margin buys nothing"
is a statement about the margin's DERIVATIVE, not about the error.  `C` is
exponential in `margin^2` and `margin` keeps creeping toward its asymptote
`ext`, so clipping keeps falling long after the geometric gain looks flat.
Measured at ext 2.0: margin 1.732 at `f_cap` gives `C = 1.7e-2`; margin 1.973
at `f = 6` gives `C = 7.0e-3` -- a 2.4x accuracy gain from a cap the module had
declared worthless.

### 2.2 What the fix does

Below the threshold the clipping floor `C(ext) = C0 exp(-ext^2)` is not small,
so the leg cannot be chosen by "shortest that clears M" (nothing clears M).  It
has to TRADE residual clipping against the hand-off leg error `L`.  So `L` is
now calibrated rather than only assumed monotone.

**Calibration of `L` (independent of the acceptance matrix).**  245 points, 7
NA x 5 extents x 9 legs, admitted only where the clipping term is negligible BY
CONSTRUCTION (`margin >= 2.9`, so `C <= 8e-5`) and the Bluestein period
comfortably covers the scoring window (no replica contamination), scored on a
4 `w0` window against the verifier's oracle:

```
  L(f, NA) ~ 0.155 * NA^3.0 * f^1.6      log-residual rms 0.596 (a 1.8x band)
```

The free 3-parameter fit returns `A = 0.1549, a = 2.995, p = 1.583`; a grid of
constrained fits over `a in [2.5, 4.5] x p in [1.2, 1.8]` on the same 245
points has its minimum at exactly `(3.0, 1.6)` with `A = 0.1538`.  The shipped
values are that minimum, rounded.  **They were not re-tuned against the 54-cell
acceptance matrix.**

Evidence that `[2]` has the right variables and is not just a curve: at
NA 0.45 the measured `L` is the SAME NUMBER across a 5.3x change of grid
extent, for every leg --

```
  L at NA 0.45      ext 3      ext 4      ext 6      ext 10     ext 16
    f = 1              --         --    3.213e-2   3.214e-2   3.238e-2
    f = 2              --   7.161e-2    7.169e-2   7.171e-2   7.166e-2
    f = 6        2.067e-1   2.068e-1    2.069e-1   2.069e-1   2.069e-1
```

-- four significant figures at `f = 6`, three at `f = 2`.  It depends on the
leg and the NA and NOT on the grid, exactly as the `C + L` decomposition
claims (and as `FIX_D2_D3_D5` S1.1 asserted from the columns at ext 3-10
without pricing the NA axis).

**The shipped sub-threshold rule** (`_small_extent_focus_standoff_f`):

1. If the leg at `f_cap` would trip `_near_focus_needs_bridge`, RETURN `f_cap`.
   That leg does not run this transport at all -- it runs the through-waist ASM
   bridge, whose error is set by how well the near-focus grid samples the
   compact waist, not by `C`.  At low NA the bridge is measurably the better
   route (ext 1.5 / NA 0.10: 1.91e-2 through the bridge against 4.09e-2 for the
   best fast-path leg), which is WHY 0.8 zR beat the shipped law in part of the
   band: 0.8 zR happened to land inside the bridge there.  Extending those
   cells anyway was measured to cost 1.9x, so the resolver now asks which code
   path its own leg will take.
2. Otherwise minimise `C0 exp(-margin(f)^2) + A NA^3 f^1.6` over
   `f in [f_cap, f_asym]` by a 256-point geometric scan.  The FLOOR is the
   previously shipped `f_cap` -- the trade may only LENGTHEN, because
   shortening walks into the bridge and into a Bluestein period too short for
   the caller's window.  The CEILING `f_asym = 0.99/sqrt(1-0.99^2) = 7.018` is
   where the margin has reached 99 % of its reachable asymptote `ext`; past it
   no leg buys containment and only `L` grows.

     ext 1.5 / NA 0.10).  Beating it requires a resolver that can choose the
     BRIDGE as the better route, i.e. a two-branch accuracy model.  This fix
     deliberately does not do that -- it only declines to fight the bridge
     where the bridge already has the leg (S2.2 rule 1).  Left open, S7 item 1.
   * against **6.0 zR**: that constant is a LONGER leg than the trade picks
     (`f = 5.97` against 5.14 at NA 0.10 / ext 1.8), and the calibrated `L` is
     CONSERVATIVE at low NA -- the single-power fit `A NA^3` over-predicts the
     leg error there by ~5x against the per-NA intercepts (1.55e-4 vs a
     measured 3.0e-5 at `f = 1`, NA 0.10), so the model stops short of the
     measured optimum (`f = 8`, the scan edge).  A per-NA `p` would close it;
     a single `(A, a, p)` cannot, because the measured `f` exponent itself runs
     from 2.30 at NA 0.05 to 1.05 at NA 0.45.  Conservative is the right
     failure direction here (a shorter leg is closer to the previously shipped
     behaviour and cannot enter a new regime), and it is why the fix is stated
     as a bound rather than an optimum.

## 3. The V1 / V2 contract change, and the one test it rebased

`test_niche_tight_focus_readout::test_the_resolved_leg_holds_the_beam_at_the_hand_off_plane`
asserted `margin == min(M, sat*ext)` as an exact identity at every extent.
That identity is exactly the thing the fix has to break below the threshold, so
it is rebased rather than deleted:

* above `ext = M/sat`: the identity is UNCHANGED and still exact
  (`margin == 3.2` to 1e-6);
* below it: `sat*ext <= margin <= 0.99*ext` -- floor = the old law (never
  shorter), ceiling = the asymptote fraction;
* and the non-constancy assertion MOVES from the margin to `f`.  The old
  identity looked extent-following because `sat*ext` moves with the grid; the
  defect was that `f` did not.  The rebased test now asserts that at least two
  sub-threshold extents give `f != f_cap` and that the sub-threshold factors
  spread by `> 1.2x`.  The wide-spread case (`f` from 3.69 down to 1.73 across
  ext 1.8 -> 3.5, a 2.1x spread) is pinned separately at NA 0.15 in the new
  suite, because the spread at this fixture's NA 0.278 is necessarily small --
  `L` grows as `NA^3`, so a fast beam cannot afford much extra leg.

No other assertion in that file moved.

## 4. V6 (LOW) -- the bar stays hard; the margin is now quoted

The verifier's measurement is real and reproduces:

```
  NA=0.1  ext=3.0            NA=0.278 ext=6.0
    0.98  p   6.3928e-04       0.98  p   1.3500e-03
    1.00+ p   6.5295e-04       1.10  p   1.3501e-03
    1.10  p   7.0013e-04       1.50  p   1.7804e-02
    1.50  p   1.1888e-03       2.00  p   1.0000e+00
    2.00  p   9.9999e-01
```

**The bar is NOT loosened and the guard is NOT downgraded** (pinned:
`test_the_disposition_is_still_error_by_default`).  The justification, now
written into the docstring and the message:

At exactly one period every returned sample is a DISTINCT sample of the field.
Past it, some returned samples are literal aliases of others --
`E(u + p) == E(u)` identically, independent of the field, the NA, the standoff
and the window.  One period is therefore the only bar this geometry-only guard
can state correctly-by-construction.  Any looser bar would be a bet on the halo
being weak out there, and the ladder above is what that bet's failure looks
like: relL2 1.0 by two periods, a 750x degradation over the same span whose
first 10 % cost 7 %.

What the guard CAN do, and now does, is hand the caller the measurement instead
of only the verdict.  The refusal message quotes:

* the per-axis SPAN `2|centre_out| + N_out*dx_out` and both periods;
* the overshoot in metres;
* how many samples per edge are provably aliases;
* the largest safe `N_out` AT THIS OFFSET (or, when the offset alone exceeds
  half a period, that no window is faithful there and how far in to bring it).

The alias count is a real measurement, not a fixed sentence: it is asserted to
GROW with the overshoot (1.02 p < 1.10 p < 1.50 p) in
`test_the_refusal_quotes_the_measured_overshoot`.

## 5. V8 (LOW) -- `tilt` under a paraxial gap kernel

### 5.1 The drop is real, and it is still there -- by design

Fail-before reproduced and PINNED as a permanent property
(`test_fail_before_the_tilt_really_is_inert`): at `R = inf, -0.2, +0.5` the
returned envelope is `np.array_equal` with and without `tilt = (0.06, -0.04)`
under `gap_kernel='fresnel'`.  The fix ANNOUNCES the drop; it does not secretly
start honouring it.

### 5.2 Why announce rather than refuse, and why not teach fresnel the tilt

Decided from what the paraxial transfer function can represent.  Expanding the
exact kernel about the carrier wavevector `k s` and keeping `O(q^2)`:

```
phase(q) = k z - z [ |q|^2/(2 k N) + (s.q)^2/(2 k N^3) ] + O(q^4),  N = sqrt(1-|s|^2)
```

so a tilt IS representable at paraxial order -- as an ANISOTROPIC dilation of
the propagation distance (`z/N` across the tilt, `z/N^3` along it).  Teaching it
to the fresnel arm is cheap.  It is also the wrong thing to do: `'fresnel'`
exists precisely AS the legacy paraxial kernel, is documented as such on every
entry point, and is pinned FP-identical to prior releases by the carrier suites
(`_carrier_step_fast`'s own comment: "Explicit 'fresnel' keeps the historical
arithmetic FP-identical").  Giving it a tilt term would buy correctness for one
knob at the price of the reproducibility that is the other knob's entire
purpose.

Refusing would remove that option outright and hard-break any tilted chain that
pins `'fresnel'` for a reproduction.  A caller who wants the tilt honoured has a
one-word remedy (`gap_kernel='auto'`, exact on every backend, tilt to all
orders); a caller who wants the legacy arithmetic keeps it.  So: a
`RuntimeWarning`, unconditional, naming BOTH knobs and the consequence.

This differs from D11b (astigmatic + `'exact'` -> REFUSE) for a reason that is
not taste: there the caller asked for EXACT and could not be given it, so
returning anything would be answering a different question.  Here the caller
asked for the LEGACY PARAXIAL kernel and gets exactly that; what is dropped is
a term that kernel by definition does not have.

### 5.3 Scope

Fires from `propagate_carrier_referenced` -- the single public funnel every
carrier leg passes through (direct API, focus readouts, chain, multi
orchestrator), before the branch, so all four arms (collimated, astigmatic,
fast, focus-crossing) are covered exactly ONCE per call.  It also covers the
ASTIGMATIC path, which forces the separable per-axis paraxial kernel whatever
`gap_kernel` says (`'exact'` is already refused there) and never receives
`tilt` at all -- an adjacent silent drop the verifier did not name.

Measured after:

| case | warnings | tilt honoured |
|---|---|---|
| `gap_kernel='fresnel'`, tilt != 0, `R = inf / -0.2 / +0.5` | **1**, names both knobs | no (unchanged) |
| `gap_kernel='fresnel'`, tilt == 0 | 0 | n/a |
| `gap_kernel='auto'` or `'exact'`, tilt != 0 | 0 | yes (fields differ) |
| astigmatic `R=(-0.2,-0.3)`, `'auto'`, tilt != 0 | **1**, names ASTIGMATIC | no |
| equal-radii tuple `(-0.2,-0.2)`, `'auto'`, tilt != 0 | 0 (scalar path) | yes |

`propagate_carrier_referenced`'s numpydoc also gained the `gap_kernel` and
`tilt` Parameters entries the verifier noted were missing entirely.

## 7. What is NOT closed

1. **The ext 1.8-2.0 low-NA band still loses to 0.8 zR by up to 1.98x**
   (S2.4).  Closing it needs a resolver that can pick the near-focus BRIDGE as
   the better route rather than only avoid fighting it -- i.e. a second
   accuracy model for a second code path.  That is the same open item
   `FIX_D2_D3_D5` S5.1 recorded, now bounded and quantified rather than
   open-ended.
2. **`L(f, NA)` is a FIT, not a derivation.**  Its 1.8x band and its
   single-exponent compromise (the measured `f` exponent runs 2.30 -> 1.05 over
   NA 0.05 -> 0.45) are what leave the band in item 1.  Only the LOCATION of a
   broad minimum is taken from it; no returned field depends on its accuracy
   beyond the leg length it selects.
3. **`mft._warn_mft_output_window` still says "samples beyond +/-period/2 of
   centre_out"** -- the same false geometry V3 fixed in `carrier.py`, inherited
   in the propagator that the readouts call.  `mft.py` is outside this fix's
   writable scope.  It is a WARNING and not a guard, and the correct guard now
   fires first on both public readouts, so nothing wrong is returned because of
   it -- but the sentence is wrong and should be corrected by the `mft` owner.
4. **The chain and multi orchestrator now REFUSE configurations that
   previously returned**, wherever the chief-ray residual pushes the window
   outside one period -- including the DEFAULT `centre_out=(0, 0)` on a tilted
   chain whose chief ray walks more than half a period.  That is a true
   positive (S1.5 shows the ghost it prevents), but it IS a behaviour change on
   a shipped path, and design 121's production chain was not re-run here.  The
   remedy for a caller who hits it is to centre the window on the chief ray --
   which the message now says, quoting the chief ray's own coordinates on the
   exact path.
5. **Design 121 itself was not re-run.**  Both the standoff change (every chain
   taking the paraxial final leg) and the guard change (any chain whose readout
   window is not centred on its chief ray) can reach it.
6. **Nothing here was run on GPU, CuPy or JAX.**  The V8 announcement is
   backend-independent (it fires at the entry point, before any backend
   dispatch); the standoff resolver is host-side float arithmetic on
   host-reduced scalars.  Both are arguments, not measurements.
