## 3. The method, so the next wave is run the same way

1. **Brief -> engineer -> independent verifier -> orchestrator commit.**  Each package had a written brief
   (`briefs/`), one engineer agent (Opus) that owned an explicit file list, and after it landed an adversarial
   verifier that did NOT read the engineer's fixtures as truth: it built its own oracle (an independent algorithm
   -- a brute-force Rayleigh-Sommerfeld sum from an exact conic trace, a double-double reference, a Richardson-
   extrapolated derivative), re-derived every number on a fixture of its own, attacked the Migration notes and the
   pins (mutation matrices), fixed what it found inside its ownership and wrote up the rest as "requested changes".
   The orchestrator applied the requested changes it could, recorded the rest, ran a verification chain of its own
   (ruff, fingerprints, the package's files with `--store-durations`, a `-k` slice, `check_doc_identifiers.py`,
   `validation/run_all.py` slices) and committed with the explicit file list.  Verifiers found real defects inside
   the new code in ten of twelve packages; none reached a default path.
2. **Byte identity is proved archive-to-archive.**  `git archive <parent> lumenairy` and `git archive <commit>
   lumenairy` extracted to two scratch trees, each imported in a CHILD process with `cwd` and `PYTHONPATH` set to
   the tree and `lumenairy.__file__` asserted to live under it, then `np.array_equal` / SHA-256 of the exact bytes.
   Never through pytest, never against the shared working tree (other agents write in it concurrently).
3. **Agents never run git write commands** (`add`, `commit`, `stash`, `checkout`, `restore`, `reset`) **and never
   kill processes**; the orchestrator commits, one commit per package, never amended, every message ending with the
   `Co-Authored-By` line the maintainer asked for.
4. **Every python invocation carries** `OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 MKL_NUM_THREADS=1`, one pytest
   process per agent, in the FOREGROUND (an agent's turn boundary kills its background children).
5. **Comments explain, history documents narrate.**  A source comment says what the code does NOW and why; the
   version / audit narrative goes to `docs/history/<module>.md` and the module is re-recorded with
   `python scripts/record_history_fingerprints.py <module> --reason "..."` (docstring- and comment-only edits do not
   move the fingerprints).  `tests/unit/test_audit2609_a17_history_lint.py` is the ratchet.
6. **Tests follow `docs/TESTING_STANDARDS.md`**: no wall-clock assertions (count operations instead), bars derived
   two-sided from a measured ladder with the margin stated, oracles independent of the code under test, fail-before
   shown on the parent commit in an isolated tree.
7. **Defaults move only with a Migration note** and a measurement beside them; everything else ships opt-in behind a
   keyword whose default reproduces the previous release byte for byte.
8. **`.test_durations`** (pytest-split) is topped up on every landing with `--store-durations --durations-path
   .test_durations`; `repro/orch/release_tools/durations_gap.py` must read 0 tracked tests missing at a release.

## 4. Open work, by priority

### 4.1 P1 -- WP-B12: the FGA reference plane (`briefs/WP-B12.md`)

Found by VERIFY-B7b (`fixes/VERIFY_WP-B7b.md` sections 3.3, 3.5, 8).  `lumenairy.raytrace.differential.
ray_transfer_jacobian` and `ray_transfer_jacobian_analytic` return the base-ray state ON the last surface (the
intersection point), while four sites in `lumenairy/propagators/fga.py` -- `_fga_core`, `_fga_coarse`, the coarse
trace and `_caustic_zone` -- add the image-side leg as if the state were on the exit-vertex plane.  Every beamlet
therefore carries a spurious phase of `k * sag(r)` on a curved last surface: 7.58 waves of OPL and 0.64 um of
height at the rim of an N-SF11 R = +-1.6 mm biconvex, 15.02 waves on a bent singlet, exactly zero on a flat last
surface.  Consequence: `apply_real_lens_fga` / `apply_real_lens_fga_vector` / `apply_real_lens_universal(method=
'fga')` return a 0.125-fidelity field at a singlet focus where the exact answer is reproduced at 0.9998 once the
state is projected (`x - sag*ux`, `y - sag*uy`, `opd - sag*sqrt(1+ux^2+uy^2)`); the caustic-zone estimate is
shifted by about the sag (~0.5 % of the focal distance).  Both WP-B7 and WP-B7b saw the deficit and mis-read it as
"FGA converges to the wrong field at a caustic"; 5.47.0 therefore routes a single-valued field inside the
aberration envelope to the phase screen -- a correct mitigation on curved-last-surface lenses, and 0.03 of fidelity
worse than FGA on a flat-last-surface singlet near the budget.  The repair moves every FGA field on a curved-last-
surface prescription and numbers pinned in `test_fga.py`, `test_fga_h4_h5.py`, `test_g1_gate_generality.py`,
`test_niche_audit_w9_dispatch2.py`, `test_niche_p8_capstone.py`, `test_niche_p7_seidel_gate.py`,
`test_audit2609_a4_fga_s10.py` and `test_audit2609_b7b_caustic_routing.py`, so it needs its own oracle ladder and
its own verifier.  The `DifferentialTransfer` docstring already states the last-surface convention (5.47.0).
After the repair: re-score the caustic route (FGA 0.9998 vs the screen's 0.9991 at ten times the cost) and decide
the `aberrated` condition on the H2 f/5 dual-oracle fixture -- BEFORE the repair that reading measures the defect,
not the gate (VERIFY-B7b section 3.5; keep the condition until then).

### 4.1b P1 -- the persistent Newton worker pool hangs instead of falling back (found at the release gate)

`apply_real_lens_traced`'s parallel Newton inversion (`lumenairy/elements/_lens_traced.py::_invert_newton_parallel`) runs
its chunks on a module-level persistent `ProcessPoolExecutor` (spawn context).  When the pool BREAKS -- a worker exits
while the executor's queue-feeder thread is mid-write -- the function's fallback path calls `close_worker_pool()`, whose
`_PERSISTENT_POOL.shutdown(wait=True)` deadlocks inside CPython 3.14's `_ExecutorManagerThread._terminate_broken`
(it joins the `QueueFeederThread`, which is blocked in `multiprocessing.connection._send_bytes` to the dead worker), so
the serial fallback the code intends is never reached and the calling process hangs forever.  Captured twice with
`faulthandler` (`handoff/orchestrator_log_2026_09_13-14.md`, 13:13 and 13:39 entries; the dumps are in the scratch logs
quoted there): one main thread in `close_worker_pool -> shutdown`, one in `as_completed` waiting on futures the broken pool
will never complete, the manager thread in `_terminate_broken -> join`, the feeder in `_send_bytes`.

**The trigger, found late on 2026-09-14: pytest's DEFAULT file-descriptor output capture.**  With default capture the
spawned workers never answer and the pool breaks; the identical test passes in 6 s with `--capture=sys` and in 203 s
with `-s`.  The interaction appeared on this box at about 11:00 (the same tests were green under default capture at
09:00 in VERIFY-B7b's run and at every landing), so it is a box-state / harness interaction, not a Wave-4 code
regression -- but the library's response to a broken pool (deadlock instead of the serial fallback) is real and
independent of what broke the pool.  Run gates with `--capture=sys` until the interaction is understood; the
5.47.0 gate's remaining lanes ran that way.

Reproduction on this box (2026-09-14 from about 11:00 on; 5 of 5 attempts under default capture, in-tree and in
`git archive` trees of 21110326, c62c2f14 and 9b5e4e41 with fresh or warm numba caches):
`pytest tests/unit/test_audit2609_b4_collins_transport.py -k test_both_transports_reproduce_the_audit_s_own_readings`
and `pytest "tests/unit/test_niche_audit_w9_dispatch2.py::test_the_two_selectors_agree_everywhere[3000.0-512]"`.  Both
drive `propagate_traced_carrier_chain`, whose two arms run in a `ThreadPoolExecutor(max_workers=2)` and SHARE the
persistent process pool from two threads.  What is established: `spawn` itself works (a 4-worker pool returns in 0.2 s),
workers import `_lens_traced` (0.3 s), a direct `apply_real_lens_traced(..., n_workers=4)` on a 384^2 field completes
(2.8 s), the Windows Application log records no python.exe faults, RAM is 127 GB with 49 GB free.  What is not: why a
worker dies (or the executor believes it did) under the two-arm chain -- the leading hypothesis is a race between the two
arm threads on the shared pool's teardown / re-creation (`_get_persistent_worker_pool` rebuilds the pool when the cost
class changes; a rebuild by one thread while the other thread's chunks are in flight would look exactly like a broken
pool to the executor), which timing on the loaded box may have made frequent today.

Minimum robustness fix (one line, needs its own verifier because it is the default path of every traced-lens call):
in the broken-pool fallback use `shutdown(wait=False, cancel_futures=True)` (and let the atexit handler / a later
`close_worker_pool` reap), so the serial fallback runs instead of the deadlock; then find the pool-breaking cause with
worker-side logging (`concurrent.futures.process` `BrokenProcessPool.__cause__`, a `faulthandler` in
`_newton_invert_chunk`).  The 5.47.0 gate's per-file lanes ran with `--capture=sys`, under which every one of these
tests passes (section 8); a user who hits the hang can pass `n_workers=1` (serial Newton) to `apply_real_lens_traced`
/ the carrier chain.

## 5. Gotchas -- the box, the tools, the process

* **Spend limits.**  The account's usage limit is a spend budget per reset window, not a concurrency cap: Wave 4
  was interrupted six times (three at 9-10 concurrent agents, three at one or two).  Every kill costs about an
  hour of resumes.  Agents resume from their transcripts (`SendMessage` to the agent id) with state-from-disk
  instructions: which of their files are modified (`git status`), what landed meanwhile, what to rerun.  Never
  block on an agent task's output -- it returns the agent's whole JSONL transcript; wait for the completion
  notification.
* **Hangs and crashes in long pytest runs on this box.**  (1) From 2026-09-14 ~11:00 every test that spawns worker
  processes hung under pytest's DEFAULT fd capture and passed under `--capture=sys` (section 4.1b) -- run gates with
  `--capture=sys` until that interaction is understood.  (2) A long run beside other heavy python processes has twice
  died with `Windows fatal exception: access violation` (once in the dense `reconstruct_field_from_beamlets` path of
  `lumenairy/propagators/gbd.py`, which passes alone in 30 s); the box has 127 GB of RAM, so it is not memory.  Run
  release gates one FILE per pytest process (or pytest-split groups, `--splits N --group k`) with FULL per-process
  logs so a crash costs one unit and keeps its traceback, and with `-o faulthandler_timeout=900` so a hang dumps
  every thread; `tasklist /V` twice a few minutes apart tells a hang (frozen CPU time) from slowness.  Map `-q`
  progress marks to `--collect-only` ids by counting ONLY progress lines (letters inside warning text are not marks).
  Never kill processes by a command-line pattern that the launching shell's own command line also contains.
* **Bash on this Windows box.**  Long heredocs (more than ~100 lines or two long ones) fail to parse -- write
  scripts with the Write tool, then run them; a heredoc halves `\\d` backslashes in Python source; `$_` inside a
  double-quoted PowerShell command is expanded by bash first (single-quote the PowerShell string or use a `.ps1`
  file); `wmic` is absent; `taskkill //PID n //F` (double slashes under Git Bash).  The permission classifier blocks
  `rm` of repository files -- leave regenerable outputs untracked and gitignored.
