## TL;DR

**v4.15.1 successfully closes the v4.15.0 audit** — all 2 P0 + 12 P1 + 16 P2/P3 items have shipping code matching the documented fix, with non-tautological test pins. V1 verification ran the 102 v4.15.1 audit-closure tests and confirms all pass. The release also ships two substantial new features (operator algebra subpackage, rays-from-field bridge) with strong physics math.

**However, this audit identifies 1 NEW P0 + 9 NEW P1s + ~12 P2 + ~10 P3** — most are not in v4.15.0-closure code but in the rapid-scope expansion of the two new features and their downstream integration.

**Headline new findings (sorted by severity):**

1. **🔴 P0-NEW-1: `create_gaussian_schell_source` silent contract break** (F1). v4.15.0 returned `(E_2d, x, y)`; v4.15.1 default returns `(E_3d, dx, dy, wavelength)` 4-tuple. **No `DeprecationWarning` emitted** despite lavish deprecation wiring elsewhere in `sources/core.py`. Pre-v4.15.0 callers doing `E, x, y = create_gaussian_schell_source(...)` silently get `E.ndim==3` with `x` bound to a scalar. May propagate through downstream code as 2D via broadcasting until physics is wrong.

2. **🔴 P1-NEW-A: `FourierTransform` field-vs-ABCD inconsistency** (V2). ABCD matches the 3-stage `FreeSpace(f)*ThinLens(f)*FreeSpace(f)` chain, but `_apply` runs only 2 stages — leaves a residual `exp(+ik/(2f)·r²)` quadratic phase. ABCDs agree; fields don't. No test exercises `FourierTransform(f)(src)` vs the literal 3-stage chain application.

3. **🔴 P1-NEW-B: `from_prescription` flat-mirror parity disagrees with `system_abcd`** (F1). `from_prescription.py:170-174` flips `mirror_parity` unconditionally on `is_mirror=True`; `system_abcd` (raytrace/core.py:2275-2291) only flips for CURVED mirrors. The `<1e-12` ABCD parity pin (verified by V2) holds **only for non-folded prescriptions** — the regression test `test_v4_15_1_agent_g_matches_system_abcd.py` exercises zero mirror systems.

4. **🔴 P1-NEW-C: `FreeSpace._apply` silently drops `dy`** (F1). Calls `propagate(E, z=, wavelength=, dx=dx, ...)` without `dy`. `CylindricalLens` correctly threads `dy=dy`; `FreeSpace` doesn't. Any anamorphic algebra chain starting with `Magnify(a_x, a_y) * FreeSpace(d)` silently propagates on the wrong grid.

5. **🔴 P1-NEW-D: `'cdf'` placement docstring vs code mismatch in `rays_from_field`** (V3). Docstring claims pixel-wise threshold; actual code applies threshold to MARGINAL sums (`Ix = I.sum(axis=0)`). `'rejection'` and `'uniform'` are pixelwise; `'cdf'` is the odd one out.

6. **🔴 P1-NEW-E/F/G: Defensive-check gaps in EXISTING propagators for NEW types** (F2). `propagate_through_system` / `apply_real_lens` accept `PartialCoherenceMCF` and 3-D ensemble silently; no `isinstance` / `ndim` guards. Cryptic `AttributeError` or wrong-axis FFT.

7. **🔴 P1-NEW-H: Schell ensemble-tuple breaking change not flagged** in CHANGELOG (F2). No `### Breaking changes` subhead in v4.15.1 entry despite 3 confirmed breaking items: Schell return shape, `strehl_vector` reference now required, `system.evaluate` mixed-shape ValueError.

8. **🔴 P1-NEW-I: `rays_from_field` may silently return fewer than `n_rays`** (F1). Docstring promises `n_rays`; `_place_rejection` caps at `50·n_rays` tries and may exit short; `_place_uniform` returns survivors. Error only triggers on `n_actual == 0`.

9. **🔴 P1-NEW-J: ROADMAP.md is stale** (F2). Says "v4.15.0, ~1400 unit tests"; actual is v4.15.1 with 1625.

**Verdict:** v4.15.1's audit closure is genuinely clean (no physics regressions in the closure work itself). The new findings cluster in **downstream integration** — new types shipped without updating consumers, breaking changes shipped without CHANGELOG flagging. **Tier-0 v4.15.2 patch (~70 LOC, 3-4 hours)** would close the P0 + the 9 P1s. The fundamental engineering remains strong.

### CLUSTER_B Operator algebra (V2, F3)

**Implementation quality: STRONG.** 91 tests pass; 8 of 10 claims verified clean:

- **ABCD primitives all correct** from first principles (V2 + F3): `FreeSpace(d)`, `ThinLens(f)`, `FourierTransform(f)` (derived from `T(f)·R(f)·T(f)`), `CylindricalLens` per-axis
- **`from_prescription` ↔ `system_abcd` parity NON-TAUTOLOGICAL** — two independent code paths compared at 1e-12 across 10 cases
- **Anamorphic support** correctly threads `_abcd_x`/`_abcd_y`
- **Composition convention** consistent across `system_abcd`, `from_prescription`, and the 4f-system example
- **Aperture composition** sequential (apply_aperture twice if `Aperture * Aperture`)
- **Phase 2 deferral clean** — no half-shipped symbolic reduction logic
- **Examples runnable** — valid signatures throughout

**Forbes Q-bfs orthonormalizer verified by hand** (F3): `n=0` gives `c_0² · ∫₀¹ x(1-x) dx = 6 · 1/6 = 1`; `n=1` gives `c_1² · 2/15 = (15/2) · 2/15 = 1`. Formula matches code.

**🔴 P1-NEW-A — FourierTransform field/ABCD inconsistency** (V2): ABCD `[[0,f],[-1/f,0]]` is closed-form for the 3-stage chain `FreeSpace(f)*ThinLens(f)*FreeSpace(f)`. But `_apply` runs only TWO stages (lens then Fresnel), producing `FFT(E) * exp(+ik/(2f)r²)` with a residual output-plane quadratic phase. A user composing `FourierTransform(f)` with a phase-sensitive downstream operator gets different fields than the literal 3-stage chain — though identical ABCDs. **No test exercises field-vs-3-stage agreement.**

**P2-NEW — Magnify docstring backward, math correct** (V2 + F3 2-way confirm): `Magnify(a=2)` produces `new_dx = dx/2` and output extent N·dx/2 — i.e., output is SHRUNK by 2 (not magnified). Docstring at `primitives.py:320` says "physical extent scales as `a * (N * dx)`" — opposite of code. Implementation IS internally self-consistent and energy-conserving (Nazarathy/Shamir `V[a]` convention). CHANGELOG line 207-211 claim about spec's `resample_field` "energy-conservation bug" is plausible (interpolation onto bigger grid without amplitude rescale WOULD break energy by `a²`), but the agent shipped a SEMANTICALLY DIFFERENT operator (demagnifier vs spec's magnifier) and called it a bug-fix.
