#### Why the third callsite stays unwired

Per the brief's explicit option (b):

> Drop `_PerturbedABCDFallbackSentinel` (the audit-noted dead class)
> and document why; only wire the two scalar sentinels.

The third callsite's fallback is a 2-tuple `(efl_p, bfl_p)` not a
single scalar.  Wrapping the tuple in a single sentinel singleton
breaks downstream unpacking (the immediate consumer assigns
`sub_ctx.efl = efl_p`, `sub_ctx.bfl = bfl_p` -- if `efl_p` were the
singleton, the `float()` cast at sub-context construction would
work via `__float__` but the second component `bfl_p` would be lost).
A tuple-aware sentinel (option (a) in the brief) would solve this,
but at the cost of an asymmetric API where two of the three
sentinels are scalar-shaped and the third is tuple-shaped --
worsening the maintainability story.

To respect the "Don't touch any file outside the scope list"
constraint (the v4.15.2 test
`test_v4_15_2_agent_e.py::TestOptimizeCoreSentinelMigration` pins
the existence of `_PerturbedABCDFallbackSentinel`), Agent C does
NOT remove the class.  Instead the class:

* Gains a `.. deprecated:: 4.15.3` docstring section that explains
  the dead-code rationale.
* Gains a class-level `_v4_15_3_dead_code = True` marker so a
  future regression check (or a programmatic v4.16+ migration
  script) can identify it without parsing the docstring.

The callsite itself (`core.py:2948`) gains an inline comment
referencing the class docstring for the audit rationale.

#### Downstream consumers

The brief permits updates at "immediate consumer sites; don't
refactor the broader optimisation framework."  Two narrow consumer
edits were required:

1. **Callsite 1 (`MultiWavelengthMerit.evaluate` line 2424):** the
   local `bfl` is checked at the per-wavelength wave-leg gate via
   `np.isfinite(bfl) and abs(bfl) < 10` -- on the sentinel form
   this would raise `TypeError` (numpy's `isfinite` does not accept
   a generic object even when it has `__float__`).  Pre-wire the
   condition would have collapsed to `True` then false (the `< 10`
   check would have returned `False` because `1e9 < 10` is False),
   skipping the wave leg.  Post-wire we add an `is`-identity check
   FIRST so the sentinel form short-circuits cleanly:

   ```python
   if self.sub_merit.needs_wave and ctx.E_exit is not None and \
      bfl is not _INVALID_FL_SENTINEL_OBJ and \
      np.isfinite(bfl) and abs(bfl) < 10:
   ```

   Physics: identical to pre-wire (wave leg skipped at this
   wavelength when the ABCD extraction collapsed); type discipline:
   cleaner.

2. **`StrehlMerit.evaluate` (line 610):** previously did
   `max(0.0, self.min_strehl - ctx.strehl_best)` which fails on the
   sentinel form (no `__sub__` defined).  Post-wire we coerce
   `ctx.strehl_best` via `float()` so the sentinel collapses to its
   `.value` scalar (0.0) for arithmetic, preserving physics.  An
   identity check is still available BEFORE the cast for callers
   who want to distinguish a real-zero Strehl from a failed-scan
   zero.

No other downstream sites needed changes: the only other consumers
of `ctx.strehl_best` are diagnostic format-strings (e.g.
`f'strehl = {ctx.strehl_best:.4f}'` at `core.py:3620`) and these
hit the OUTER ctx (not the inner `sub_ctx` we wire), so the
sentinel never reaches them.

#### Pickle round-trip

The two wired sentinels round-trip pickle to themselves (preserved
identity) via the `_Sentinel` base's `__reduce__` protocol +
`_SENTINEL_REGISTRY` name lookup.  Already guaranteed by v4.15.2
Agent E's work; the new `test_v4_15_3_agent_c.py` adds dedicated
single-purpose pins for the two wired singletons so a v4.15.3
regression isolates cleanly.

## C.3 -- Tier-1: non-tautological FourierTransform pin

### What the audit caught

`AUDIT_V4_15_2_2026_05_18` P2 finding #3:

> `FourierTransform._apply` 3-stage pin essentially tautological:
> the test verifies the 3-stage chain equals the `FourierTransform`
> result by literally invoking the 3-stage chain.  Closure is
> correct, but the test only proves "rewrite did what the audit
> said", not "matches independent Fraunhofer kernel ground truth".
> A non-tautological pin would compare against a closed-form
> Gaussian-beam waist relation through a thin lens.

### What v4.15.3 ships

A new parametric test
`test_fourier_transform_gaussian_beam_waist_relation` in
`TestFourierTransform3Stage` (3 parametrised cases: VIS/mid-focal,
NIR/short-focal, VIS/long-focal).  The test:

1. Constructs an on-axis Gaussian input with known waist `w_in`.
2. Applies `FourierTransform(f)`.
3. Extracts the output waist from the second moment of the
   intensity:  `w_out = sqrt(2 * <r^2>)`.
4. Asserts the measured waist matches the closed-form
   `w_out = lambda * f / (pi * w_in)` (Saleh & Teich §3.2.2,
   Goodman §5.2.3) to within 5%.

The 5% tolerance is the budget the audit specified for
discrete-grid sampling errors.  **Measured error across the three
parametrised cases:**

| Case | `w_in` | `w_out_analytical` | `w_out_measured` | Rel error vs 5% tol |
|---|---|---|---|---|
| VIS_mid_focal (N=256, dx=4.7 um, f=50 mm, lambda=633 nm) | 200 um | 50.373 um | 50.373 um | < 0.0001% |
| NIR_short_focal (N=256, dx=4.0 um, f=25 mm, lambda=1.55 um) | 150 um | 82.230 um | 82.230 um | < 0.0001% |
| VIS_long_focal (N=256, dx=8.0 um, f=100 mm, lambda=633 nm) | 300 um | 67.163 um | 67.163 um | < 0.0001% |

The empirical headroom is ~50000x.  This pin is independent of the
3-stage decomposition: agreement requires the lens-side Fourier
optics to be physically correct, not just the implementation to be
self-consistent.

The existing tautological pin is preserved (so the v4.15.2
closure path stays pinned) but annotated with a `.. note::`
referencing the new non-tautological pin.
