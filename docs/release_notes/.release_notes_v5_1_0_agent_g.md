## v5.1.0 -- Agent G: `analysis/core.py` 6-file split

Closes the v5.0.1 ROADMAP "Architecture / housekeeping" 6-file-split
work for the analysis stack (`ROADMAP.md` v5.1.0 section, bullet
"`analysis/core.py` (4088 LOC) -> split beam-stats / Strehl / PSF /
MTF-OTF / polychromatic / Zernike / OPD").  v5.0 shipped a single
4088-LOC `analysis/core.py` carried over from v4.x; v5.1.0 carves it
into six topical submodules.

### Layout (post-split)

| Old (v5.0 / pre-split) | New home (v5.1.0)                           |
|------------------------|----------------------------------------------|
| `core.py` (4088 LOC)   | `core.py` (160 LOC -- thin re-export shell)  |
|                        | `beam_stats.py` (479 LOC)                    |
|                        | `strehl.py` (540 LOC)                        |
|                        | `psf_mtf_otf.py` (1267 LOC)                  |
|                        | `polychromatic.py` (665 LOC)                 |
|                        | `zernike.py` (601 LOC)                       |
|                        | `opd.py` (677 LOC)                           |

Per-submodule contents:

* **`beam_stats.py`** (5 public + 1 helper): `beam_centroid`,
  `beam_d4sigma`, `beam_power`, `beam_diameter`, `M2`.  Backend-aware
  via `array_namespace`; the four light helpers dispatch through the
  CuPy / JAX / NumPy abstraction without a host transfer.
* **`strehl.py`** (6 public + 1 helper): `strehl_ratio`,
  `strehl_marechal`, `strehl_phase_integral`, `coupling_efficiency`,
  `strehl_vector`, `coupling_efficiency_vector`, plus the internal
  `_validate_vector_field_shapes` validator.
* **`psf_mtf_otf.py`** (10 public + 3 helpers): Fraunhofer PSF /
  OTF / MTF + radial MTF (`compute_psf`, `compute_otf`, `compute_mtf`,
  `mtf_radial`); v4.14.0 spec-sheet metrics (`mtf_cutoff`,
  `encircled_energy_curve`, `encircled_energy_radius`); v4.15.0
  resolution metrics (`rayleigh_resolution`, `sparrow_resolution`,
  `fwhm_resolution`).  Internal helpers `_psf_1d_profile`,
  `_to_numpy_host`, `_radial_profile_subpixel`.
* **`polychromatic.py`** (5 public): `chromatic_focal_shift`,
  `polychromatic_strehl`, `polychromatic_psf`, `ee_polychromatic`,
  `radial_power_bands`.  `radial_power_bands` is a pure-NumPy
  cumulative-power sampler kept here because it has no prescription
  dependency yet is the building block several through-focus /
  encircled-energy callsites build on.
* **`zernike.py`** (8 public + 4 helpers + 3 cache primitives): OSA-
  indexed Zernike polynomials, decomposition, reconstruction,
  `astigmatism_mag_angle`, `clear_zernike_basis_cache`.  Internal
  helpers `_zernike_radial`, `_zernike_basis_cache_key`,
  `_zernike_basis_matrix_build`, `_zernike_classical_name`.  The
  module-import-time `_register_cache_clearer('zernike_basis', ...)`
  call lives here now (single registration; the legacy
  `core.py` registration was dropped to avoid double-registration
  on the new layout).
* **`opd.py`** (7 public): `check_sampling_conditions`,
  `check_opd_sampling`, `remove_wavefront_modes`, `opd_pv_rms`,
  `wave_opd_1d`, `wave_opd_2d`, `depth_of_focus`.

### Public-API guarantees (preserved bit-for-bit)

The v5.0 `__all__` enumeration is preserved verbatim in the new thin
`core.py` shell, plus the two private symbols (`_xp_of`,
`_validate_vector_field_shapes`) and the four internal Zernike
helpers / three Zernike cache primitives that downstream tests have
been pinning since v4.14.2.  Every historical import path continues
to resolve:

* `from lumenairy import X`           -- top-level convenience.
* `from lumenairy.analysis import X`  -- sub-package.
* `from lumenairy.analysis.core import X` -- legacy, pre-split path.

For each of the 41 public symbols, all three import paths point at
the **same function object** (identity equality, not just name
equality).  This is exercised by
`tests/unit/test_v5_1_0_agent_g_split.py::test_three_paths_resolve_to_same_object`.

The downstream internal-import consumers continue to work:

* `lumenairy/analysis/__init__.py` -- re-exports 41 public names from
  the new shell.
* `lumenairy/__init__.py` -- top-level convenience exports unchanged
  (the analysis sub-package `__init__.py` is the import surface).
* `lumenairy/analysis/plotting.py` -- imports `beam_centroid`,
  `beam_d4sigma` via `from .core import ...` (works via the shell).
* `lumenairy/analysis/ao.py` -- imports `zernike_polynomial`,
  `zernike_index_to_nm` via `from .core import ...` (works via the
  shell).
* `lumenairy/analysis/through_focus.py` -- imports `beam_centroid`,
  `beam_d4sigma`, `radial_power_bands` via `from .core import ...`
  (works via the shell).
* `lumenairy/_context.py` -- imports `clear_zernike_basis_cache` via
  `from .analysis.core import ...` (works via the shell).

### No physics / numerics change

This is a **mechanical reorganisation only**.  No function body was
edited (apart from one cross-file dependency wiring noted below).
The Strehl / PSF / Zernike / OPD numerics are bit-for-bit identical
to v5.0.

The single cross-file wiring change is `encircled_energy_curve` in
`psf_mtf_otf.py`: when the caller omits `centroid`, the function
falls back to `beam_centroid`, which now lives in `beam_stats.py`.
The import is a deferred `from .beam_stats import beam_centroid`
inside the function body so the two submodules don't pull each
other transitively at import time.  Similarly, `ee_polychromatic`
in `polychromatic.py` has a deferred `from .psf_mtf_otf import
encircled_energy_curve` for the same reason.
