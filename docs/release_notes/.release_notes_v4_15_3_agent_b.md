# v4.15.3 - Agent B release notes (draft)

Scope: P1-NEW-F1-1, P1-NEW-F1-2, P1-NEW-F1-4, P2 sentinel-subclass-promotion +

## Fixes

### P1-NEW-F1-1: FreeSpace + FourierTransform SAS-anamorphic crash with method='auto'

* **File:** `lumenairy/algebra/primitives.py:127-160` (`FreeSpace._apply`),
  `:574-602` (`FourierTransform._apply` via composition).
* The v4.15.2 P1-NEW-C closure added `if dy is not None and float(dy) !=
  float(dx): kw['dy'] = float(dy)` to thread `dy` into the dispatcher.
  This was correct for kernels that accept `dy` (ASM, Fresnel,
  Fraunhofer, RS), but with `self.method == 'auto'` (the default), the
  dispatcher routes to **SAS** in the far-field regime (`Q = lambda*z /
  (N*dx**2) > 1`).  SAS is a square-grid-only kernel and does NOT accept
  `dy` -- the call raised `TypeError: sas_propagate() got an unexpected
  keyword argument 'dy'`.
* **Fix:** when `dy is not None and float(dy) != float(dx) and method ==
  'auto'`, force `method='asm'` regardless of `self.method`.  This makes
  `auto` a hint rather than a contract; the user implicitly opted into
  anamorphic support by passing `dy`, so SAS (which is square-grid only)
  is structurally inappropriate.
* **FourierTransform** is fixed by composition: its `_apply` creates two
  `FreeSpace(self.f, method=self.method)` instances and delegates to
  their `_apply`, which now contains the anamorphic guard.
* **Verification:** `lumenairy.propagators.dispatch.propagate(..., dy=2e-6,
  method='auto')` in the far-field regime still raises the underlying
  SAS `TypeError` (proving the bug is real at the dispatcher level), but
  `FreeSpace(d, method='auto')._apply(..., dy=2e-6)` succeeds and
  round-trips on a 32x32 anamorphic test grid with `Q = 4`.

### P1-NEW-F1-2: Schell DeprecationWarning stacklevel one short

* **File:** `lumenairy/sources/core.py:1721` (`_warn_schell_return_kind_default`).
* The warning chain has 5 internal frames between `warnings.warn` and
  user code (`_emit` -> `warn_deprecated_signature` ->
  `_warn_schell_return_kind_default` -> factory body -> user).
  Pre-v4.15.3 `stacklevel=4` landed at frame 4 (the factory body) --
  one frame inside the library.  Bumped to `stacklevel=5`.

### P1-NEW-F1-2 (sweep): off-by-one in 6 more `sources/core.py` call sites

* **Files:** `lumenairy/sources/core.py:1203, 2368, 2451, 2525, 2596,
  2682`.
* The 5 `Source.*` legacy-positional classmethods (`Source.gaussian`,
  `Source.plane_wave`, `Source.point_source`, `Source.top_hat`,
  `Source.fiber_mode`) and `create_led_source` all called
  `warn_deprecated_signature(stacklevel=3)`.  Frame chain:
  `_emit` -> `warn_deprecated_signature` -> classmethod body -> user
  (4 frames).  `stacklevel=3` landed at the `warn_deprecated_signature`
  body inside `_deprecation.py`; `stacklevel=4` is required to land at
  user code.  Bumped all 6.

### P1-NEW-F1-4: `Source.gaussian_schell` / `Source.schell_model` bypass DeprecationWarning

* **File:** `lumenairy/sources/core.py:2773-2810` (`Source.gaussian_schell`),
  `:2842-2880` (`Source.schell_model`).
* Both classmethods hardcoded `return_kind: str = 'ensemble'`,
  short-circuiting the `_RETURN_KIND_UNSET` sentinel path used by the 3
  top-level factories.  Pre-v4.15.0 callers using these classmethods
  got a 4-tuple silently with no `DeprecationWarning`.
* **Fix:** changed both classmethods to use `return_kind: Any =
  _RETURN_KIND_UNSET` and added the same sentinel check pattern as the
  factories.  When the sentinel is seen, emit
  `_warn_schell_return_kind_default('Source.gaussian_schell')` /
  `('Source.schell_model')` and default to `return_kind='ensemble'`.
* **Docstring caveat:** both classmethods now explicitly document the
  2-D `Source.E` invariant break for the 3-D ensemble return.  Per the
  audit's "soft inconsistency is HONEST" recommendation, no
  architectural change is shipped (no `Source.realizations()`
  iterator); the docstring points at the future API instead.

### P2-NEW: `_RETURN_KIND_UNSET` to subclass

* **File:** `lumenairy/sources/core.py:1696` (was a bare `_Sentinel`
  instance; now a `_SchellReturnKindUnsetSentinel(_Sentinel)`
  singleton).
* Cosmetic-only; the registry-driven pickle round-trip is unchanged.
  The subclass-identity pattern lets downstream code do `isinstance(x,
  _SchellReturnKindUnsetSentinel)` without false positives from
  sibling bare `_Sentinel` instances.  Now consistent with
  `_ZeroApertureMaskSentinel` (in `optimize/core.py`),
  `_AngleUnsetSentinel` (in `elements/polarization.py`),
  `_NoDefaultSentinel` (in `_deprecation.py`).

## Empirical confirmation of FreeSpace anamorphic far-field fix

Reproducer (against `lumenairy.propagators.dispatch.propagate` directly,
bypassing the v4.15.3 fix in `FreeSpace._apply`):

```python
from lumenairy.propagators.dispatch import propagate
import numpy as np
N = 32; dx = 1e-6; dy = 2e-6; wavelength = 633e-9
z = 4.0 * N * dx * dx / wavelength
E = np.zeros((N, N), dtype=np.complex128); E[N // 2, N // 2] = 1.0
propagate(E, z=z, wavelength=wavelength, dx=dx, method='auto', dy=dy)
# TypeError: scalable_angular_spectrum_propagate() got an unexpected
# keyword argument 'dy'. Did you mean 'dx'?
```

Same call via the v4.15.3-fixed `FreeSpace` operator:

```python
from lumenairy.algebra import FreeSpace
op = FreeSpace(z, method='auto')
E_out, dx_out, dy_out = op._apply(E, dx=dx, dy=dy, wavelength=wavelength)
# output shape: (32, 32), dx_out=1e-06, dy_out=2e-06 -- SUCCESS
```

The fix forces `method='asm'` (the only kernel that accepts `dy`) when
the input grid is anamorphic, sidestepping the SAS routing that the
dispatcher would otherwise pick in the far-field regime.
