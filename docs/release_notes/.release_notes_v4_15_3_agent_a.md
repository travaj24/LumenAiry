# v4.15.3 -- Shared 2-D-scalar-field guard helper + meta-pin (Agent A)

Patch release closing the **P0-NEW-F2-1** finding from
`docs/audits/AUDIT_V4_15_2_2026_05_18.md`:

* The v4.15.2 P1-NEW-E/F closure hand-guarded 10 propagator/lens
  entry points but missed 9 sibling entry points in the same
  modules accepting the same `E_in` argument.  This is the textbook
  "fix N, miss N+1" meta-pattern that has now recurred in every
  audit round v4.13.0 -> v4.15.2.

v4.15.3 (Agent A) closes the 9 missed siblings AND adds a structural
counter-measure so the same pattern can't recur a third time.

## The structural fix

A new shared validation helper

```python
# lumenairy/_validation.py
def _check_2d_scalar_field(E: Any, fn_name: str) -> None:
    """Reject PartialCoherenceMCF and non-2-D inputs at the entry
    point of any coherent-field propagator or lens kernel."""
```

consolidates the `PartialCoherenceMCF`-and-`ndim != 2` defensive
guards that v4.15.1-v4.15.2 added inline at each entry point.  Every
v4.15.2-guarded site (10 sites) and every v4.15.3 new-sibling site
(9 sites) now share the helper, eliminating ~24 LOC of copy/paste
per site -- a net reduction of ~240 LOC of duplicated boilerplate
across 19 sites for ~110 LOC added (helper + meta-pin).

## The meta-pin

`tests/unit/test_v4_15_3_dispatcher_pin_2d_scalar_field.py` walks
`lumenairy/propagators/` and `lumenairy/elements/` for every public
top-level `def apply_*` / `def *_propagate*` / `def propagate` and
asserts that the first executable statement is a call to
`_check_2d_scalar_field` -- OR that the function name appears in
the documented `_GUARD_EXEMPTIONS` set with a cited reason.  A new
public scalar-field entry point added without the guard fails CI
at this pin (the v4.15.3 counter-measure to the recurring
sibling-gap meta-pattern).

The walker discovers **43 entry points**; of these, **18 are
guarded** (the migration scope minus `propagate_through_system`,
which lives in `system.py` outside the walker's package scope) and
**25 are documented as exemptions** with a cited reason.

### Documented exemptions

The exemptions break down as follows:

| Category | Count | Reason |
|---|---|---|
| Delegating wrappers (`asm_propagate`) | 1 | thin wrapper that delegates to one of the 5 guarded ASM-family propagators |
| Out-of-scope sibling (`apply_fresnel_curvature`) | 1 | phase-multiplication helper, not a propagator; re-evaluate at v4.16 |
| 3-D-only batched variant (`angular_spectrum_propagate_batch`) | 1 | contract REQUIRES `ndim == 3`; guard would invert the invariant |
| GBD beamlet propagators (`propagate_*`, `apply_*_to_beamlets`) | 7 | accept `BeamletBundle` objects, not 2-D scalar fields |
| Huygens-Fresnel propagators | 4 | accept HF state objects (`PathBundle` / opl-callable) |
| HFPI propagators | 5 | accept `PathBundle` objects |
| Vectorial-HFPI propagators | 3 | accept `VectorPathBundle` objects |
| Asymptotic / modal propagators | 3 | accept modal-coefficient representations and ray bundles |
| Subaperture propagator | 1 | accepts a subaperture-state object (dict + tile-local field tuple) |
| Generic-element `apply_*` helpers in `elements.py` | 9 | DO take 2-D scalar fields but NOT in v4.15.3 P0-NEW-F2-1 scope; re-evaluate at v4.16 |
| JAX-traceable lens variants | 2 | guard plan coupled to the v4.16 JAX autodiff partial-coherence story |
| Top-level polarization helpers | 6 | accept `JonesField` objects, not 2-D scalar fields |

Total: 43 walker hits = 18 guarded + 25 exempt.

## Behavioural preservation

The migration is behaviour-preserving:

* All 32 v4.15.2 Agent-C defensive-guard tests
  (`test_v4_15_2_agent_c.py`) still pass after the helper migration --
  the helper raises the same `TypeError` / `ValueError` with the
  same key tokens (`PartialCoherenceMCF`, `v4.16`,
  `for k in range(ensemble.shape[0])`) the v4.15.2 contract pins.
* 34/34 validation files PASS.
* No widening of narrowed `except` clauses; no public-API
  signature changes.
* Lazy `from lumenairy.sources.core import PartialCoherenceMCF`
  import lives inside the helper so the lazy-import pattern that
  avoided the circular dependency between `sources/` and
  `propagators/` / `elements/` / `system.py` is preserved.

## Constraints honoured

* cp1252-compatible (no non-ASCII characters in any added code or
  tests).
* No widening of narrowed `except` clauses; the helper raises
  `TypeError` (MCF) and `ValueError` (wrong-ndim) the same way the
  v4.15.2 inline guards did.
* Files modified are strictly within Agent A's scope:
  `lumenairy/_validation.py` (new), `lumenairy/system.py`,
  `lumenairy/propagators/dispatch.py`,
  `lumenairy/propagators/propagation.py`,
  `lumenairy/elements/_lens_thin.py`,
  `lumenairy/elements/_lens_real.py`,
  `lumenairy/elements/_lens_traced.py`,
  `lumenairy/elements/lenses_maslov.py`, plus the two new test
  files and this release-notes file.
* `lumenairy/__init__.py` was NOT modified -- the helper is
  imported lazily from each entry-point's function body via
  `from lumenairy._validation import _check_2d_scalar_field`
  (or `from .._validation import _check_2d_scalar_field` for
  in-package callers), so no public-API surface change is needed.
* Lazy `from lumenairy.sources.core import PartialCoherenceMCF`
  import inside the helper avoids the circular dependency between
  `sources/` and the consumer modules.  `python -c "import
  lumenairy"` confirms clean post every edit.
* The helper call is the first executable statement in each
  function body (after the docstring and the helper-import
  statement); the meta-pin walker verifies this structurally.
