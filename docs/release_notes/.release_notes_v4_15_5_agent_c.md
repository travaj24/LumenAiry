## Whether 587.56 / 633 nm wavelength annotation drift exists or was a red herring

**Drift exists -- corrected in CHANGELOG.**

The task description (`C.6`) suggested the example
`plot_opd_summary_singlet.py` uses 587.56 nm "per Agent D's
v4.15.4 work" and that the CHANGELOG's lambda=587.56 nm claim matches.
**The opposite is the case.**  The example file actually uses
`wavelength = 633e-9` (line 32):

```python
wavelength = 633e-9
rx = la.make_singlet(R1=50e-3, R2=-50e-3, d=4e-3, glass='N-BK7',
                      aperture=10e-3)
```

And Agent D's own release notes
(`.release_notes_v4_15_4_agent_d.md:135`) confirm: "Example PV/RMS
output (at 633 nm)" with the literal output text
`lambda = 633 nm`.

So the drift was in the CHANGELOG (`lambda=587.56 nm` claim) vs the
actual example file (uses 633 nm).  The audit's recommended fix
direction "587.56 nm -> 633 nm" correctly identified the CHANGELOG
side as wrong; Agent C corrected the CHANGELOG.

No other 587.56-nm / 633-nm contradictions were found in the
v4.15.4 entry of CHANGELOG, README, or release-note dotfiles
beyond this single mismatch.
