## C.1 -- Polychromatic encircled energy

`ee_polychromatic` is a convenience wrapper that runs
`polychromatic_psf` and then evaluates `encircled_energy_curve` at a
user-supplied set of radii.  The wrapper validates inputs *before* doing
any wave-optics propagation, so common user errors (mismatched-length
weight / wavelength arrays, non-monotonic radii, all-zero weights) fail
fast with a readable `ValueError`.

* **Input aliases**: `output_grid` / `output_dx` / `source` are
  accepted as aliases for the canonical `polychromatic_psf` kwargs
  `N` / `dx` / `E_in`.  Passing both forms raises `ValueError` rather
  than silently picking a precedence.  When `source` is supplied but
  `output_grid` is not, `N` is derived from `source.shape[0]`.  `dx`
  has no derivable fallback (the pixel pitch is a physical scale
  encoded nowhere in the array shape), so it is always required.
* **Weight handling**: Weights are validated to have `sum > 0` and
  re-normalised to unit sum internally before forwarding to
  `polychromatic_psf`, so scaling the weights by an arbitrary
  positive constant yields identical output.
* **Radii validation**: radii must be a finite, strictly-positive,
  strictly-increasing 1-D sequence.  These constraints match the
  contract of `encircled_energy_curve` but are pinned at the wrapper
  layer for a clearer error stack.

## C.2 -- Polarisation-aware Strehl + coupling

Two new vector-field helpers fill the polarisation-aware gap in the
existing scalar `strehl_*` / `coupling_efficiency` family.

### `strehl_vector`

Computes the peak-intensity ratio of the total vector intensity
`|Ex|^2 + |Ey|^2 + |Ez|^2` after equal-total-power normalisation
against the supplied (or default) reference.  Convention pinned to
match the scalar `strehl_ratio` definition mode-for-mode when
`Ey == Ez == 0` (so a linearly-polarised input collapses exactly to the
scalar peak-ratio form).

* **Reference convention**: `reference=None` defaults to a uniform
  plane wave of matching total power, giving an aberration-only
  Strehl when the input is itself the aberrated focus of a finite
  aperture.  An explicit `reference=(Ex_ref, Ey_ref)` or
  `(Ex_ref, Ey_ref, Ez_ref)` tuple overrides; this is the standard
  Mahajan vector-Strehl form when the reference is the polarisation-
  matched diffraction-limited focus from the same aperture.
* **Ez = None vs Ez = zeros**: A test pin verifies that omitting Ez
  is numerically equivalent to passing a zero-array Ez of matching
  shape -- the formula treats a missing Ez as identically zero.
* **Shape validation**: All vector components must be 2-D with
  matching shape.  1-D / 3-D / shape-mismatched inputs raise
  `ValueError` rather than silently broadcasting.

### `coupling_efficiency_vector`

Vector overlap integral
`eta = |<E | mode>|^2 / (<E|E> * <mode|mode>)` summing across Ex / Ey /
optional Ez components.  Reduces to the scalar
`coupling_efficiency` when Ey == mode_Ey == 0.

* The optional `Ez` and `mode_Ez` components are summed asymmetrically
  if only one is provided (the cross-term contribution is zero by
  construction).  This matches the scalar reduction and the high-NA
  Richards-Wolf use case where the field and mode may have different
  longitudinal-component structures.
* 1-D inputs and shape mismatches between field and mode raise
  `ValueError`.

## C.3 -- Resolution metrics

Three new helpers operating on a 2-D PSF intensity array, each
accepting `axis='radial' | 'x' | 'y'` and returning a scalar in metres.
A shared `_psf_1d_profile` helper extracts the 1-D profile (axis cut or
azimuthally-averaged radial bin) and locates the peak; the three public
functions then implement distinct criteria on top of that profile.

### `rayleigh_resolution(psf, dx, wavelength, *, axis='radial')`

Returns the first-zero distance of the PSF radial profile, with
parabolic sub-pixel interpolation.  For a clean Airy pattern the
first-zero radius is exactly the Rayleigh two-point-separability
criterion `1.22 * wavelength * f_number`.  A synthetic Airy test
pin (D=4 mm, lambda=600 nm, f=80 mm, oversample=8) validates this to
within 5% relative error.

### `sparrow_resolution(psf, dx, *, axis='radial')`

Searches for the smallest separation `d` at which the dual-source
profile `PSF(x - d/2) + PSF(x + d/2)` has zero second derivative at
the midpoint.  Computed via the equivalent identity that the
second-derivative of the single-source PSF at `r = d/2` equals the
midpoint curvature of the dual source: we scan the PSF curvature
outward from the peak and locate the first zero crossing, then
linearly interpolate for sub-pixel accuracy.

For an Airy pattern this gives Sparrow ~ `0.95 lambda f/#`,
consistently smaller than the Rayleigh first-zero radius.

### `fwhm_resolution(psf, dx, *, axis='radial')`

Returns twice the half-radius at half-max of the central peak (i.e.
the full width at half maximum diameter).  Linear interpolation
across the half-max crossing gives sub-pixel accuracy.

### Convention divergence from ROADMAP test spec

The original v4.15 task spec asked for the ordering
`sparrow < rayleigh; fwhm < sparrow` on an Airy PSF.  The
**physically correct** ordering for an Airy pattern is

* Sparrow ~ 0.947 * lambda * f/#
* FWHM ~ 1.029 * lambda * f/#  (full diameter)
* Rayleigh = 1.220 * lambda * f/#

i.e. `sparrow < fwhm < rayleigh`.  We implement honestly per the
docstring definitions (FWHM diameter as documented, not a HWHM) and
pin the physically-correct ordering `fwhm < rayleigh` in the test
suite.  The ROADMAP-spec ordering `fwhm < sparrow` would only hold if
`fwhm_resolution` returned the HWHM (half-radius) rather than the
full FWHM diameter -- but the docstring explicitly says "twice the
FWHM half-radius", which is the FWHM diameter.

This is a spec-side inconsistency rather than an implementation
choice; the test pin makes the convention explicit so a future spec
update or ordering claim has an obvious anchor.

### Edge cases pinned

* Flat / zero-intensity PSFs return `float('nan')` from all three
  functions rather than spurious 0 / first-bin values.
* Non-2-D PSFs (1-D, 3-D, ndarray with `ndim != 2`) raise
  `ValueError` from the shared `_psf_1d_profile` helper.
* `axis='x'` and `axis='radial'` produce finite, positive metrics
  that agree to within a factor of 3 on a symmetric Airy (the
  per-axis variant is intentionally not bit-for-bit equal to the
  radial-average variant; the test pin asserts only orders-of-
  magnitude agreement).

## C.4 -- Astigmatism magnitude + angle

`astigmatism_mag_angle(coeffs)` converts an OSA-indexed Zernike
coefficient array to the Mahajan §8.2 magnitude / orientation pair
for primary astigmatism.

### Convention pin

The OSA / ANSI single-index ordering used by `zernike_decompose`
places:

* `coeffs[3]` = Z(n=2, m=-2), "oblique astigmatism" = `c3`
* `coeffs[5]` = Z(n=2, m=+2), "vertical astigmatism" = `c5`

Magnitude is the quadrature sum, and the angle is the half-atan2 of
the (oblique, vertical) pair:

```
|astig| = sqrt(c3**2 + c5**2)
theta   = 0.5 * atan2(c3, c5)
```

This convention is consistent with Mahajan's "Aberration Theory Made
Simple" 2nd ed. §8.2 (treating the astigmatism figure as having C2
symmetry, so theta is unique modulo pi/2).  Pure vertical
astigmatism (c5 != 0, c3 = 0) gives theta = 0; pure oblique (c3 != 0,
c5 = 0) gives theta = pi/4.  Both are pinned in the test suite.

### Round-trip pin

A round-trip test synthesizes an OPD map from `(c3=5e-7, c5=-3e-7)`
via `zernike_reconstruct`, decomposes via `zernike_decompose`, and
verifies the recovered magnitude and angle match the analytic
formula within 5% magnitude / 1 mrad angle.  This pins both the
OSA-index alignment AND the magnitude / angle formula together; a
future drift in either side fails the pin.

### Validation

* Coefficient arrays shorter than 6 entries raise `ValueError`
  rather than `IndexError`.
* Non-1-D coefficient arrays raise `ValueError`.

## Discipline notes

* All new functions follow the `_xp_of(...)` backend-dispatch pattern
  where the operation is naturally array-agnostic (the vector Strehl /
  coupling overlap helpers).  The resolution-metric functions and
  `ee_polychromatic` work through `numpy` directly because they
  re-use the existing `compute_psf` / `encircled_energy_curve` /
  `polychromatic_psf` machinery which itself routes through
  `_xp_of` -- a CuPy-input array reaches the helpers as a CuPy
  return value already.
* File is cp1252-compatible: no non-ASCII characters in docstrings or
  code.  Test file uses only ASCII.
* Two new helpers are name-mangled (`_validate_vector_field_shapes`,
  `_psf_1d_profile`) and intentionally NOT exposed in `__all__`.

## Backward compatibility

No existing public function signatures, return shapes, or numerics are
changed by this drop.  The only side effect is that
`lumenairy.__all__` and `lumenairy.analysis.__all__` grow by 7 entries
each.
