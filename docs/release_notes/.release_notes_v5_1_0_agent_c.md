# Release notes -- v5.1.0 Agent C

**Scope.**  Split the 4103-line monolithic
``lumenairy/propagators/propagation.py`` into six logically-coherent
submodules per the v5.1.0 ROADMAP.  Mechanical file-level
reorganisation only -- no public API change, no physics change, no
behaviour change.  Every name previously importable from
``lumenairy.propagators.propagation`` continues to resolve from there
bit-for-bit.

## Summary

* Extracted FFT / cache / config infrastructure into
  ``propagators/fft_infra.py`` (the new home for the pyFFTW plan
  cache, the ASM transfer-function caches, the
  ``set_default_*`` / ``set_fft_*`` setter family, the four
  ``DEFAULT_*`` library knobs, and the shared
  ``_validate_propagator_inputs`` guard).
* Extracted the ASM-family kernels into ``propagators/asm.py``
  (``angular_spectrum_propagate``,
  ``angular_spectrum_propagate_tilted``,
  ``angular_spectrum_propagate_batch``,
  ``apply_fresnel_curvature``, ``_build_asm_H_square``).
* Extracted the single-FFT paraxial propagators into
  ``propagators/fresnel.py`` (``fresnel_propagate``,
  ``fraunhofer_propagate``).
* Extracted the Rayleigh-Sommerfeld convolution into
  ``propagators/rs.py``.
* Extracted the Heintzmann / Loetgering / Wechsler 2023 scalable
  angular spectrum into ``propagators/sas.py``.
* Extracted the Bluestein / MFT propagator family + ``resample_field``
  into ``propagators/mft.py``
  (``angular_spectrum_propagate_mft``, ``fresnel_propagate_mft``,
  ``fraunhofer_propagate_mft``, ``resample_field``).
* Reduced ``propagators/propagation.py`` to a thin re-export shell
  (~330 lines) whose only behavioural addition is a module-level
  ``__getattr__`` that forwards mutable-config attribute lookups
  (``DEFAULT_COMPLEX_DTYPE``, ``FFTW_THREADS``, ...) to the canonical
  copies in ``fft_infra``.  This preserves the pre-v5.1.0 semantic
  that ``import lumenairy.propagators.propagation as p;
  p.DEFAULT_COMPLEX_DTYPE`` reflects the LIVE value after a
  ``set_default_complex_dtype`` call.
* Added regression tests in
  ``tests/unit/test_v5_1_0_agent_c_split.py`` pinning the public
  surface (object identity, ``__all__`` membership, shared cache
  identity across the re-export boundary, end-to-end smoke for each
  propagator).
* Updated three meta-pin tests so they remain anchored after the
  split (the parameterised cache-lock pairing test, the
  cache-registry late-binding pin, and the multiprocess fork-notes
  documentation pin).

## Module-level state handling

**Choice: Option B.**  Mutable module-level globals (DEFAULT_* knobs,
FFT-config scalars, all caches, the cache lock) live in the new
``propagators/fft_infra.py`` module.  ``propagation.py`` re-exports
each name and adds a module-level ``__getattr__`` for the subset that
gets reassigned at runtime (the ``DEFAULT_*`` knobs and the FFT
backend config scalars).

The ``__getattr__`` is required because ``from .fft_infra import X``
captures the import-time value of ``X``; for live attribute access via
``propagation.X`` to track ``set_default_*`` updates, we either need
the setter to mutate ``propagation.X`` directly (the pre-v5.1.0
semantic) or we forward attribute lookups dynamically.  Option B does
the latter so the canonical "value lives once, in ``fft_infra``"
invariant is preserved.

The four ``set_default_*`` setters and their ``get_default_*`` peers
remain importable from ``lumenairy.propagators.propagation``
(per-spec).  Their canonical definition site is ``fft_infra.py``;
``propagation.py`` re-exports the function objects so the legacy path
resolves to the same callable.

## Migration recipe

There is none.  The split is bit-for-bit back-compat at the
import-path level.  Existing code that imports from
``lumenairy.propagators.propagation`` (or transitively via
``lumenairy``) continues to work unchanged.

Code that wants to use the new finer-grained import paths can do so:

```python
# Old (still works, recommended for back-compat):
from lumenairy.propagators.propagation import angular_spectrum_propagate

# New (equivalent, faster to import if you ONLY need ASM kernels):
from lumenairy.propagators.asm import angular_spectrum_propagate
```

The finer-grained import paths skip the import-time cost of pulling
in every sibling module's body, which can shave ~10-50 ms on
single-feature CLI tools that only need one propagator family.
