## FourierTransform implementation choice

Per spec §3.3.3 the implementation can be either:

- **Option (a)** -- apply thin-lens phase + Fresnel-propagate by `f`,
  single FFT.
- **Option (b)** -- `FreeSpace(f) * ThinLens(f) * FreeSpace(f)` 2f
  setup, three propagations.

**Chosen: option (a)** (per spec recommendation "Pick option (a) for
performance.").  Implementation in
`lumenairy/algebra/primitives.py::FourierTransform._apply` delegates
to `apply_thin_lens` then `fresnel_propagate`; the returned
`(dx_out, dy_out)` are the Fresnel-FT natural grid pitches
`lambda*f/(N*dx_in)` so downstream operators see a correctly-sized
output.  Tested in
`test_v4_15_1_agent_g_application.py::TestFourierTransformApplication`
and pinned for ABCD equivalence with the option-(b) chain in
`test_v4_15_1_agent_g_examples.py::TestExample2fFourierTransform::test_2f_setup_matches_fourier_transform`.

## Deviations from CLUSTER_B_SPEC.md §3

1. **Magnify `_apply` does NOT delegate to `resample_field`.**  The
   spec's §3.5 recipe is:
   ```python
   new_dx = dx / self.a_x
   new_dy = dy / self.a_y
   E_out = resample_field(E, dx_in=dx, dx_out=new_dx,
                           dy_in=dy, dy_out=new_dy)
   E_out *= np.sqrt(self.a_x * self.a_y)
   ```
   But `resample_field` only accepts `dx_in` / `dx_out` (no `dy_*`
   parameters), and with `N_out = N_in` and `dx_out = dx/a` it
   interpolates the **central crop** of the input -- which does NOT
   correspond to the V[a] coordinate-scaling operation.  Concretely:
   V[a]f(x) = sqrt(a)·f(a·x) sampled on a grid with `new_dx = dx/a`
   evaluates to `sqrt(a) · E_in[j]` at output pixel `j` (because
   `a · (j·new_dx) = j·dx` is exactly the input grid position at
   index `j` -- no interpolation is needed).  The spec recipe gives
   the wrong energy (Energy_out / Energy_in = a² for a 2D field
   that fits within the contracted region; verified empirically in
   the initial test failure).

   **My implementation:** `Magnify._apply` multiplies the input by
   `sqrt(a_x · a_y)` and reports the new grid pitch
   `(dx/a_x, dy/a_y)` -- no resampling, no interpolation noise.
   Energy conservation is exact:
   `|E_out|² · dx_out · dy_out == |E_in|² · dx_in · dy_in` at every
   pixel by construction.  This is the closed-form realisation of
   the spec's `|E_out|^2 * dx_out * dy_out == |E_in|^2 * dx_in * dy_in`
   equality, just without the wrong intermediate resample.  Pinned
   by `TestMagnifyApplication::test_magnify_changes_grid_pitch_and_preserves_energy`.

   The `resample_field` import is consequently NOT used by
   `Magnify._apply`; if a future caller needs anamorphic
   interpolation on top of the algebra scale, they can call
   `resample_field` directly on the input field.

2. **Tuple-input entry point widened to accept the anamorphic
   `(E, dx, dy, wavelength)` form** in addition to the spec-required
   `(E, dx, wavelength)`.  This preserves the spec's bare-tuple
   shortcut while supporting anamorphic prescriptions without
   forcing callers through the `Source` factory just to thread `dy`.
   Pinned by `TestEntryPoints::test_call_tuple_4_anamorphic`.

3. **`Operator.from_prescription` is exposed as `Operator.from_prescription(...)`
   via a `setattr`-injected classmethod**, not a static `@classmethod`
   inside `base.py`.  The factory needs `ThinLens`/`FreeSpace` from
   `primitives.py`, and `primitives.py` imports from `base.py` --
   defining `from_prescription` inside `base.py` would create a
   circular import at module-load time.  The injection happens once
   in `algebra/__init__.py` after both modules are loaded; from a
   user perspective `lumenairy.Operator.from_prescription(...)` works
   exactly as the spec describes.  No deviation from the public API,
   only an implementation detail to avoid the cycle.

4. **`CylindricalLens._apply` short-circuits when an axis's focal
   length is `np.inf`** (no `apply_cylindrical_lens` call for that
   axis).  Spec table just says "Delegates to apply_cylindrical_lens";
   the short-circuit is a numerical / performance refinement that
   matches the closed-form ABCD (identity on the inf-focal axis).
   This preserves complex64 input dtype across the operator (no
   redundant lens-phase float64 promotion).

No deviations from §3.4 (ABCD math) or §3.7 (test list).  All spec-
required tests are present (plus 20+ additional coverage tests
beyond the spec minimum).

## Public API surface (new in v4.15.1)

```python
# Top-level imports
from lumenairy import (
    Operator,
    CompositeOperator,
    FreeSpace,
    ThinLens,
    CylindricalLens,
    Magnify,
    FourierTransform,
    Aperture,
    GaussianAperture,
)

# Build a system algebraically
sys = (
    FreeSpace(0.1) * ThinLens(0.1) * FreeSpace(0.2)
    * ThinLens(0.1) * FreeSpace(0.1)
)

# Read off properties without applying to any field
print(sys.abcd)          # [[-1, 0], [0, -1]] -- 4f inverter
print(sys.efl)           # +inf (afocal)
print(sys.A, sys.B, sys.C, sys.D)
print(sys.is_anamorphic) # False

# Apply to a Source
src = lumenairy.Source.gaussian(N=512, dx=2e-6, wavelength=633e-9,
                                 w0=80e-6)
out = sys(src)           # Source -> Source

# Or to a bare ndarray
E_out = sys.apply(src.E, dx=src.dx, wavelength=src.wavelength)

# Or to a tuple
E_out, dx_out, wl_out = sys((src.E, src.dx, src.wavelength))

# Build from a prescription
rx = lumenairy.make_singlet(R1=50e-3, R2=-50e-3, d=5e-3,
                              glass='N-BK7', aperture=25.4e-3)
op = lumenairy.Operator.from_prescription(rx, wavelength=633e-9)
# op.abcd matches system_abcd(surfaces, 633e-9)[0] to within 1e-12

# Inspect intermediate stages
intermediates = sys.apply_with_intermediates(
    src.E, dx=src.dx, wavelength=src.wavelength,
)
for i, (E_i, dx_i, dy_i) in enumerate(intermediates):
    print(f"Stage {i}: shape={E_i.shape}, dx={dx_i:.3e}")
```

## CHANGELOG draft (for `CHANGELOG.md`)

### Added (v4.15.1 -- CLUSTER_B Item 2: Operator Algebra Layer)

- New `lumenairy.algebra` subpackage providing a Nazarathy/Shamir-
  style operator algebra over the existing array-first propagator
  infrastructure.  Primitives carry closed-form 2×2 ABCDs (real
  float64, supports anamorphic systems via separate `_abcd_x` /
  `_abcd_y`) and delegate field application to existing LumenAiry
  functions.
- Top-level exports added (9 new symbols, Tier 2):
  `Operator`, `CompositeOperator`, `FreeSpace`, `ThinLens`,
  `CylindricalLens`, `Magnify`, `FourierTransform`, `Aperture`,
  `GaussianAperture`.
- `Operator.from_prescription(prescription, wavelength, *,
  method='auto')` classmethod converts a LumenAiry prescription dict
  into a `CompositeOperator` whose ABCD matches
  `system_abcd(surfaces_from_prescription(p), wavelength)[0]` to
  within 1e-12 absolute (verified across singlet / doublet /
  telephoto / close-pair / flat-window prescriptions × VIS+NIR
  wavelengths).
- New examples: `examples/algebra_4f_system.py` (4f imaging
  inverter + centroid sign-flip demonstration) and
  `examples/algebra_anamorphic.py` (cylindrical-lens line focus).
- New tests: `tests/unit/test_v4_15_1_agent_g_{abcd,application,
  matches_system_abcd,examples}.py` (91 tests total).

Symbolic-reduction collapse rules (Phase 2 of CLUSTER_B_SPEC §3.6)
are deferred to a follow-up release.
