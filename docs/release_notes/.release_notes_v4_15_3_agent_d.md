### D.3 -- rays_from_field threshold-comparison consistency (P2)

The v4.15.2 audit (Part 2, P2 findings) noted that the three placement modes in `lumenairy/raytrace/from_field.py` used inconsistent threshold comparisons:

| Mode | Pre-v4.15.3 comparison |
|---|---|
| `_place_cdf` | strict `>` (line 431) |
| `_place_rejection` | inclusive `>=` (line 495) |
| `_place_uniform` | strict `>` (line 541) |

(Note: the audit's prose at Part 2 P2 reverses this -- it states `_place_rejection` uses strict `>` and the other two use `>=`.  Reading the actual code, the direction is opposite: `_place_rejection` was already inclusive; the other two were strict.  The audit's finding -- that pixels at exactly `intensity_threshold` had inconsistent treatment across modes -- is real regardless of which mode is the outlier.)

v4.15.3 picks `>=` (inclusive) as the canonical "pixel intensity meets threshold" convention -- matches the natural intuition that a pixel whose normalised intensity is "exactly the threshold" should be retained, and matches what `_place_rejection` already did.

#### Changes to `lumenairy/raytrace/from_field.py`

* `_place_cdf` line 431: `np.where(I_norm > threshold, I, 0.0)` -> `np.where(I_norm >= threshold, I, 0.0)`
* `_place_uniform` line 541: `mask = (I / Imax) > threshold` -> `mask = (I / Imax) >= threshold`
* `_place_rejection`: unchanged (already inclusive); a docstring note records the cross-mode consistency claim.
* Module-level docstring and public-API parameter docstrings updated to describe the inclusive convention.
* Module footer history note adds a v4.15.3 line describing the change.

#### Numerical behaviour change at the boundary

This is a NUMERICAL behaviour change for inputs at the exact threshold boundary.  Pre-v4.15.3 a pixel whose normalised intensity is exactly `intensity_threshold` was:

* Dropped in `cdf` and `uniform` modes.
* Retained in `rejection` mode (modulo the second-level Bernoulli acceptance step, which has independent probability `v == threshold` per draw).

Post-v4.15.3 the boundary pixel is retained in all three modes.

For typical workflows (`intensity_threshold` is a denoising cutoff of 1e-4 against a beam profile that varies by 10+ orders of magnitude across the support) the change is below test tolerance.  The user-visible delta is confined to:

* Synthetic-fixture inputs constructed with pixels at exactly the threshold.
* Quantised fields (e.g. integer-amplitude masks rescaled to `[0, 1]`) where many pixels can land at the threshold simultaneously.

Existing tests are unaffected -- the 32 pre-v4.15.3 rays_from_field tests all pass after the change.
