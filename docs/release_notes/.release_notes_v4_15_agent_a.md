# v4.15 Agent A — Modal asymptotic per-pixel vectorisation

Status: draft (closes ROADMAP v4.15 item #1).

## Summary

`propagate_modal_asymptotic` switches from a per-pixel
warm-started Newton loop to a single batched cold-start
`_solve_envelope_stationary_batch` + `_compute_M_b_batch` path.
This closes the v4.14.0 audit's "wrong-saddle basin" physics
finding (warm-start chain entered wrong-saddle basins at grid
edges, silently zeroing those pixels via the `|b_quad| > 700`
overflow guard) and ships a 19x perf win on the canonical
N=128 LG_(0,0) grid.

## What changed

### Code

- `lumenairy/propagators/asymptotic.py:propagate_modal_asymptotic`
  body replaced (lines ~2530-2895).  The pre-v4.15 per-pixel
  Python loop with warm-start Newton chain is gone; the v4.15
  body builds element-wise masks (`in_box_s2`, `in_box_v`,
  `finite_Mb`, `ok_det`, `ok_bquad`, `ok_amp`) and routes a
  single batched call through the existing v4.14.0 private
  helpers:
  - `_solve_envelope_stationary_batch(... v_cx=v_cx, v_cy=v_cy)`
    -- cold-start from `v2_centre` on every pixel (NO warm-start
    chain).
  - `_compute_M_b_batch(...)` -- batched M, b, J*, phi*, G_0,
    detJ.
  - Closed-form 2x2 `M^-1` and `det M` (avoids `np.linalg.inv`
    overhead at N elements).
  - `_gaussian_moment_table_2d_batch(...)` for batched moment
    tables, indexed as a 3-D `(N, max_i+1, max_j+1)` array.
  - Per-(`k_src`, `k_pup`) mode pair:
    `_batched_polynomial_substitute_linear_2d(...)` and
    `_batched_polynomial_under_affine_shift(...)`, then a
    direct 4-axis contraction against the moment array.
  - The Maslov-branch unwrap remains a sequential O(N) pass
    over the valid pixels for `'1d_raster'` / `'row_reset'`
    modes (the unwrap is fundamentally serial); `'principal'`
    uses a vectorised `np.sqrt(det_M)`.
- The wrong-saddle warm-start chain is DELETED.  Each pixel
  cold-starts from `(v_cx, v_cy)`.

## Why this matters (physics)

The pre-v4.14 warm-started Newton chain in
`propagate_modal_asymptotic` lands in *wrong-saddle basins*
near grid edges, where the envelope-stationary equation has
multiple solutions for the same `(s_2, source)` pair.  The
warm-start chain (initialising each pixel's Newton from the
previous pixel's `v_star`) drags the iteration into the
unphysical saddle.  At that saddle, `|b_quad.real|` exceeds the
overflow guard at 700, and the pixel is silently zeroed.

Symptoms in production:

- Aberration tensor entries become non-smooth near the chief
  ray (the LG aberration tensor builds on
  `propagate_modal_asymptotic` for high-order modes; entire
  Seidel/Zernike channels were quietly degraded by warm-start
  saddle-jumping).
- Maslov stationary-phase chains computed on a fine grid
  (`through_focus`, `polychromatic_psf` slow-path) showed
  jagged amplitude vs focus / wavelength.

The v4.15 cold-start batched Newton starts every pixel from
the pupil centre `(v_cx, v_cy)` independently.  This finds the
*physical* saddle uniformly across the grid -- no chain
dynamics, no basin-dragging.  The result is strictly more
non-zero pixels at grid edges, physically MORE correct, and
breaks the old bit-equality test pins.

## Cascade impact

Modules that consume `propagate_modal_asymptotic`:

- `aberration_tensor(... output_modes=...)`: the L ≠ 0
  σ-integration grid path (since v4.9) routes through
  `propagate_modal_asymptotic` per source mode.  v4.15
  recovers any grid-edge content the warm-start dropped.
  Existing test pins on `aberration_tensor` use either
  small-grid (low N, less wrong-saddle exposure) or
  L = 0 closed-form chief-ray paths (unaffected by
  `propagate_modal_asymptotic`); should pass unchanged.
- `decompose_lg` / `decompose_hg`: unaffected -- they decompose
  pre-computed fields.
- Through-focus and polychromatic helpers calling
  `propagate_modal_asymptotic` per focus/wavelength point gain
  the full 19x perf and the wrong-saddle correctness.

## Bit-equality -> property-pin migration

Two bit-equal pins were intentionally relaxed in this release
because the algorithm changed:

| Test | Pre-v4.15 | v4.15 |
|---|---|---|
| `test_lg00_single_mode_matches_reference` | `rel < 1e-10` vs warm-start ref | `1e-8` abs vs cold-start ref + 5% energy + nz-count >= warm |
| `test_multimode_matches_reference` | `rel < 1e-10` vs warm-start ref | `1e-8` abs vs cold-start ref + 5% energy + nz-count >= warm |
| `test_lg00_single_mode_bit_equal` (v4.14.0 audit file) | `rel < 1e-12` vs warm-start ref | `1e-8` abs vs cold-start ref + 5% energy + nz-count >= warm |
| `test_lg_p0_4mode_prescription_bit_equal` (v4.14.0 audit file) | `rel < 1e-12` vs warm-start ref | `1e-8` abs vs cold-start ref + 5% energy + nz-count >= warm |

The pre-v4.15 pins compared bit-by-bit against the warm-start
reference; that comparison no longer makes sense because the
warm-start reference is itself the buggy algorithm.  The
v4.15 cold-start path is the canonical algorithm; the test
helpers ship fresh inline scalar reproductions of the
cold-start algorithm and pin per-pixel agreement against
those at `1e-8` absolute (the achievable floor from
closed-form-inv vs `np.linalg.inv` micro-rounding plus einsum
ordering).

The 5% energy tolerance and the `nz-count >= warm` pin
*directionally* encode the wrong-saddle physics finding: any
pixel the warm-start chain falsely zeroed gets recovered by
the cold-start path, so the cold-start energy is `>=` the
warm-start energy and the non-zero pixel set is a superset.

## Measured perf

- N = 128 LG_(0,0) on the development machine (Windows 11,
  Python 3.14, NumPy 2.x):
  - v4.15 batched: 1.902 s
  - pre-v4.15 warm-start scalar reference: 36.944 s
  - speedup: **19.4x**
- Wrong-saddle pixel-count recovery on the same grid:
  - new non-zero pixels: 15918
  - warm-start non-zero pixels: 15866
  - delta: +52 pixels recovered

## Constraints honored

- No widening of narrowed `except (np.linalg.LinAlgError,
  ValueError, OverflowError)` clauses to bare `except
  Exception`.  Element-wise failures are now surfaced through
  boolean masks rather than try/except + continue; the only
  remaining try/except wraps the batched helper calls
  themselves (a single try/except for the whole batch is
  semantically equivalent to the per-pixel try/except since
  the batch helpers are structured to mask per-element
  failures internally; the outer try/except only fires if the
  whole batch fails at the Python level).
- All files cp1252-compatible (ASCII only).
- No touches outside the scope list
  (`lumenairy/propagators/asymptotic.py`,
  `tests/unit/test_perf_v4_12_0_asymptotic.py`,
  `tests/unit/test_audit_fixes_v4_14_0_agent_1.py`,
  `tests/unit/test_v4_15_agent_a.py`,
  `docs/release_notes/.release_notes_v4_15_agent_a.md`).

## Known follow-ups

- The runtime warnings ("overflow encountered in exp",
  "invalid value encountered in multiply") that v4.15
  initially produced have been suppressed via safe sentinel
  substitution before `np.exp` calls (pixels masked out by
  `ok_bquad` / `ok_amp` no longer feed `np.exp` with values
  that would overflow).
- `aberration_tensor`'s σ-integration grid path is structurally
  unchanged; future audit passes may want to compare its
  pre-/post-v4.15 Seidel/Zernike tensor outputs on a
  representative singlet to quantify how much grid-edge
  content was being lost to the warm-start.  Out of scope for
  v4.15 Agent A; flag for integration-time review.
