## v4.16.2 -- Agent A: propagators + raytrace closures

Closes the 2 P1 + 4 P3 propagator / raytrace findings from
`docs/audits/AUDIT_V4_16_1_2026_05_19.md`:

* **P1-NEW-F1-1** -- `_transfer_jax` high-NA `RuntimeWarning` was
  structurally unreachable in the production user flow because the
  v4.16.1 gate used `isinstance(direction_n, np.ndarray)` while the
  canonical `make_jax_ray_state(...)` factory yields a `jax.Array`
  (NOT a `np.ndarray` subclass since JAX 0.4+).
* **P1-NEW-F1-2** -- `propagate_ensemble` silently transferred CuPy
  ensembles to host NumPy via the `np.asarray(ensemble)` fallback,
  defeating GPU / autodiff workflows; the docstring advertised the
  opposite behaviour.
* **P3-NEW-F1-1** -- empty 3-D ensembles passed the `ndim == 3` check
  then raised opaque `ZeroDivisionError` via `I_acc / float(0)`.
* **P3-NEW-F1-2** -- `propagator_kwargs={'dx': ...}` colliding with
  positional `dx=` raised bare Python `TypeError`.
* **P3-NEW-F1-5** -- v4.16.1 B.4 dtype-probe pin only checked
  `@jax.jit`; `jax.grad` (separate trace context, different Tracer
  subclass) was uncovered.
* **P3-NEW-F1-6** -- no positive pin for `propagator_kwargs` legitimate
  pass-through.

All changes are additive and backwards-compatible.  No physics
semantics change; the Wolf `I_partial = <|E_k|^2>_k` accumulation is
bit-identical on the NumPy path.

### P1-NEW-F1-1 -- `_transfer_jax` JAX-aware gate (production-reachable)

`lumenairy/raytrace/jax_trace.py`.

**Diagnosis (from audit Part 2):** `_maybe_warn_transfer_jax_high_na`
short-circuited on every production call because the gate used
`isinstance(direction_n, np.ndarray)` and the production state.N is a
`jax.Array`.  The v4.16.1 B.5 tests pinned the warning by constructing
`JaxRayState` directly with `np.array(...)` -- bypassing
`make_jax_ray_state` -- so the gate was green at test time but dead at
the user's call site.

**The deeper issue:** `trace_jax(...)` wraps the inner kernel in
`jax.jit(_kernel)` at line 1091.  Even with a fixed gate inside
`_transfer_jax`, the eager call path STILL hits the warning check with
a Tracer (because the cached jit kernel traces through the body).  So
the fix has two parts: (a) fix the gate to admit eager `jax.Array`,
(b) hoist a one-shot probe to the eager entry of `trace_jax` itself,
BEFORE any jit / cache layer, where `initial_state.N` is still a
concrete `jax.Array`.

**Diff (gate)**:
```python
# Before (v4.16.1):
if not isinstance(direction_n, np.ndarray):
    return

# After (v4.16.2):
if not hasattr(direction_n, '__array__'):
    return
try:
    n_abs = np.abs(np.asarray(direction_n))
    ...
except (TypeError, ValueError):
    return  # Tracer -> TracerArrayConversionError (TypeError subclass)
```

**Diff (trace_jax entry)**:
```python
# v4.16.2 (audit P1-NEW-F1-1): hoist eager probe before jit/cache.
if not _TRANSFER_JAX_WARNING_EMITTED:
    thicks_py = jp.aux[7]
    if thicks_py:
        try:
            t_repr = float(max(abs(float(t)) for t in thicks_py))
        except (TypeError, ValueError):
            t_repr = 0.0
        if t_repr > 0.0:
            _maybe_warn_transfer_jax_high_na(initial_state.N, t_repr)
```

**Why this works (table):**

| Caller / context             | `direction_n` type     | `hasattr __array__` | `np.asarray` | Gate outcome           |
|------------------------------|------------------------|---------------------|--------------|------------------------|
| `_transfer_jax(np.ndarray)`  | `np.ndarray`           | True                | succeeds     | Eager check fires      |
| `_transfer_jax(jax.Array)`   | `jaxlib.ArrayImpl`     | True                | succeeds     | Eager check fires      |
| Inside `@jax.jit`            | `DynamicJaxprTracer`   | True                | raises       | Skips cleanly (caught) |
| Inside `jax.grad`            | `JVPTracer`            | True                | raises       | Skips cleanly (caught) |

**Physics double-check:** The warning content is unchanged.  Per-surface
transverse error is still `thickness * (1 - |N|^2) / 2 ~= thickness *
NA^2 / 2` (paraxial expansion of `(1 - cos(theta))`).  At NA = 0.5
(|N| = sqrt(3)/2 = 0.866), thickness = 1 mm: drift ~= 1.25e-4 m per
surface -- a few percent of a typical 5 mm BFL trace.  Threshold of
|N| = 0.95 (NA ~= 0.31) sits comfortably above the LumenAiry baseline
NA ~= 0.1 regime; users in the 0.1 < NA < 0.31 band don't see
spam-warnings.

**Sibling-gap sweep:**
* `jax_trace.py:423` -- another `isinstance(x, np.ndarray)` predicate
  in `_is_traced(x)`.  Different intent: it EXCLUDES 0-D NumPy scalars
  from the "traced" branch; everything else with `.shape` (including
  JAX arrays / tracers) goes the JAX route.  Logically correct -- NOT
  a sibling-gap.
* No other `isinstance(..., np.ndarray)` gates in `jax_trace.py`.
* `_transfer_jax` is the only function in the file with an explicit
  eager-vs-traced predicate.

### P1-NEW-F1-2 -- `propagate_ensemble` backend-preserving dispatch

`lumenairy/propagators/ensemble.py`.

**Diagnosis (from audit Part 2):** Line 252's
`ensemble = np.asarray(ensemble)` triggered GPU->CPU transfer for
CuPy and forced concretisation for JAX, defeating the docstring claim
"Tolerate duck-typed array protocols (CuPy, JAX)".  Users who built
their Schell ensemble on GPU got silent transfer + a CPU per-realisation
loop.

**Fix:** detect the backend via `array_namespace(ensemble)` and run
the accumulator + (optional) propagated-ensemble buffer on the same
xp.  Map complex -> matching real dtype for the accumulator
(`complex64 -> float32`, `complex128 -> float64`).  For JAX
(immutable), use list-then-stack for the propagated-ensemble buffer;
for NumPy / CuPy, use in-place buffer (preserves the v4.16.1 perf
characteristic).

**Diff:**
```python
# Before (v4.16.1):
if not isinstance(ensemble, np.ndarray):
    try:
        ensemble = np.asarray(ensemble)  # <-- downcast CuPy/JAX
    except ...:
        ...
...
I_acc = np.zeros((Ny, Nx), dtype=np.float64)  # <-- always NumPy
for k in range(n_real):
    out_k = fn(ensemble[k], ...)
    E_out_k = _coerce_field_from_propagator_return(out_k)  # <-- np.asarray()
    I_acc += np.abs(E_out_k) ** 2
I_partial = I_acc / float(n_real)  # <-- NumPy

# After (v4.16.2):
if not (hasattr(ensemble, 'ndim') and hasattr(ensemble, 'shape')
        and hasattr(ensemble, 'dtype')):
    ensemble = np.asarray(ensemble)
xp = array_namespace(ensemble)  # NumPy / CuPy / JAX namespace
...
real_dtype = np.dtype(in_dtype).type(0).real.dtype  # complex -> real
I_acc = xp.zeros((Ny, Nx), dtype=real_dtype)  # <-- xp-native
for k in range(n_real):
    out_k = fn(ensemble[k], ...)
    E_out_k = _coerce_field_from_propagator_return(out_k)  # backend-preserving
    sq = xp.abs(E_out_k) ** 2
    I_acc = I_acc + sq if (xp is not np and not cupy) else (I_acc += sq)
I_partial = I_acc / float(n_real)  # <-- xp-native
```

**Empirical verification (manual smoke test):**
```
NumPy ens (complex128, n=4) -> I_partial: ndarray, float64, max=0.1596
JAX  ens (complex64,  n=4) -> I_partial: ArrayImpl, float32, max=0.1596
np.testing.assert_allclose(np.asarray(I_jax), I_np, rtol=2e-5) -> OK
```

The float32 vs float64 discrepancy is intrinsic to JAX's default x64=False
setting; the relative error is bounded at single-precision (~1e-5).
Pinned in `test_jax_and_numpy_results_agree`.

**Physics double-check:** Wolf's canonical formula
`I_partial(r) = <|E_k(r)|^2>_k` is symmetric across the ensemble
average; the result is independent of the backend.  Per realisation
the operation is `abs(E)**2` which is element-wise and commutes with
backend dispatch (no FFT-ordering concerns).

**Sibling-gap sweep on `np.asarray(...)` in `lumenairy/propagators/`:**
* `result.py:128` -- inside `PropagationResult.__array__(...)`.  The
  `__array__` protocol method is the LEGITIMATE backend-to-NumPy
  boundary (it's exactly what `np.asarray(result)` is supposed to call).
  NOT a sibling-gap.
* `asymptotic.py:3033, 3073` -- inside the LG decomposition step
  (`decompose_lg` is NumPy-only by construction).  NumPy boundary is
  intrinsic.  NOT a sibling-gap.
* `hf.py:336`, `subaperture.py:241` -- same as above (LG decomposition
  inside Huygens-Fresnel / sub-aperture propagators).  NOT a sibling-gap.
* `propagation.py:1478` -- inside a docstring/comment.  Not code.

The `propagate_ensemble` fallback was the only TRUE sibling-gap: it
claimed backend support but didn't deliver.  All other `np.asarray`
sites are legitimate boundaries to NumPy-only downstream code.

### P3-NEW-F1-1 -- Empty ensemble `ValueError`

`lumenairy/propagators/ensemble.py`.

**Diagnosis:** `shape=(0, Ny, Nx)` passed the `ndim == 3` check; the
downstream `I_acc / float(0)` raised opaque `ZeroDivisionError`.

**Diff:**
```python
# Added after the ndim check:
if ensemble.shape[0] == 0:
    raise ValueError(
        "propagate_ensemble: empty ensemble (n_realizations=0).  "
        "The partial-coherence intensity ``< |E_k|^2 >_k`` is "
        "undefined without at least one realisation.")
```

**Why a ValueError, not ZeroDivisionError caught + re-raised:** The
domain-level error fires BEFORE any propagator call, saving the user
the per-realisation-loop wait.  The phrasing cites the upstream
`n_realizations=0` parameter so the user can pinpoint the Schell-call
that produced the empty ensemble.

### P3-NEW-F1-2 -- Kwargs collision check (`dx`, `wavelength`)

`lumenairy/propagators/ensemble.py`.

**Diagnosis:** `propagator_kwargs={'dx': ...}` plus positional `dx=`
triggered `TypeError: got multiple values for keyword argument 'dx'`
from Python's `**kw` merge step.  Correct error, confusing wording.

**Diff:**
```python
# Added at function entry (before any other processing):
if propagator_kwargs is not None:
    collisions = (set(propagator_kwargs) & {'dx', 'wavelength'})
    if collisions:
        raise ValueError(
            f"propagate_ensemble: propagator_kwargs contains keys "
            f"that collide with positional arguments: "
            f"{sorted(collisions)}.  Pass dx / wavelength only via "
            f"the top-level kwargs, not propagator_kwargs.")
```

**Note on scope:** the check is intentionally restricted to
`{dx, wavelength}` (the positional args of `propagate_ensemble`) and
does NOT cover other keys.  `propagator_kwargs={'z': ...}` overriding
`**kwargs={'z': ...}` is a LEGITIMATE precedence use case and is
pinned in `test_propagator_kwargs_overrides_top_level_kwargs`.

## Migration notes for users

* **`propagate_ensemble` on CuPy / JAX inputs** -- now returns the
  matching backend.  Code that relied on the silent NumPy downcast
  (i.e. fed CuPy in and expected NumPy out) must add an explicit
  `to_numpy(...)` or `np.asarray(...)` at the call site.  This is an
  intentional contract correction; the v4.16.1 docstring already
  promised backend preservation.  Most users won't notice because
  the canonical workflow stays on NumPy.
* **Empty ensembles** -- `propagate_ensemble(empty_ensemble, ...)`
  now raises `ValueError` instead of `ZeroDivisionError`.  Code that
  caught `ZeroDivisionError` (none in-tree) must update to `ValueError`.
* **Colliding kwargs** -- `propagate_ensemble(...,
  propagator_kwargs={'dx': v})` now raises `ValueError` instead of
  Python's `TypeError`.  Pass `dx` only via the positional kwarg.
