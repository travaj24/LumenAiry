## v4.15.1 -- Agent D scope: close the Forbes Q-bfs / Q-con consumer paths

Closes the half-shipped Forbes Q paths flagged in `docs/audits/AUDIT_V4_15_0_2026_05_18.md`.  Math + dispatcher were correct in v4.15.0; six consumer-side defects silently dropped the freeform coefficients or shipped wrong documentation.  All six are fixed below.

### D.1 -- P1-NEW-D: raytrace flat-keys allowlist gathers Forbes Q

`lumenairy/raytrace/core.py` lines 1507-1511 narrow allowlist (the gather step that copies legacy flat-keys form into the `Surface.freeform` dict) did NOT include the Forbes Q keys.  A prescription with `freeform_type='q_bfs'` and `q_bfs_coeffs=[...]` and `r_max=5e-3` had `freeform_type` carried through correctly (so the dispatcher routed) but the coefficients silently dropped on the floor before they ever reached `Surface.freeform`.  The raytraced sag reduced to a pure best-fit sphere, and `apply_real_lens_traced` silently lost the freeform departure.

**Fix.**  Extend the allowlist with `'q_bfs_coeffs'`, `'q_con_coeffs'`, and `'r_max'` so the gather step preserves the Forbes Q payload.  Narrow edit at the canonical gather site; no widening of any other `except` / dispatcher / filter clause.

### D.2 -- P1-F1-1: radial clip aligned with `r_max` for Q-bfs / Q-con

`surface_sag_q_bfs` (was at lines 445-461) and `surface_sag_q_con` (was at lines 546-561) used a rectangular `|x| <= norm_x AND |y| <= norm_y` clip.  But the Forbes Q-bfs and Q-con bases are defined on the radial coordinate `u = r / r_max` over the unit disc, so the proper clip is `r <= r_max` (a CIRCULAR domain).  Pre-fix consequences:

* A pixel at `(0.9 r_max, 0.9 r_max)` has radial distance `1.27 r_max` (outside the Forbes domain), but the rectangular clip with `norm_x = norm_y = 1 m` let it through.  The Q-bfs prefactor `u^2 (1 - u^2)` goes negative beyond `u = 1`, so the sag had a spurious sign-flipped region at the corners.
* A pixel at `(0, r_max)` was zeroed correctly by the rectangular clip only because `r_max < norm_x` was assumed -- not by intent.

**Fix.**  PRIMARY clip is now radial (`r <= r_max`); SECONDARY clip is the rectangular `[-norm_x, norm_x] x [-norm_y, norm_y]` pupil box.  Both clips apply -- a pixel must lie inside both to keep its freeform departure.  The `norm_x` / `norm_y` kwargs are retained as a tighter (or anamorphic) pupil-clip on top of the radial guard.  Docstrings updated to make the radial-domain definition explicit.

### D.3 -- P1-F1-2: `surface_sag_freeform` requires `r_max` for Q-bfs / Q-con

`surface_sag_freeform` (the dispatcher) silently defaulted `r_max=1.0` (one METRE) when missing from the surface dict, for `freeform_type` in `('q_bfs', 'q_con')`.  A user passing X/Y in metres ended up with a Forbes domain of 1 m -- typically orders of magnitude larger than the actual aperture, so the polynomial evaluated on a sub-pixel of the surface and the freeform departure was effectively a no-op.  Silent units mismatch.

**Fix.**  Raise `TypeError("surface_sag_freeform: 'r_max' is required when freeform_type='q_bfs'/'q_con' ...")` with a clear message pointing the caller at the correct unit and the clear-aperture-semi-diameter convention.  Other freeform types (xy_polynomial, Zernike, Chebyshev) are unaffected.

### D.4 -- P3 doc-formula correction in the module docstring

The module-level comment block in `lumenairy/elements/freeform.py` stated the Q-bfs orthonormalizer (or equivalently the unmapped [-1, 1] norm) with the wrong `(n+1)` power and a spurious factor of 8:

* Wrong (pre-fix): `c_n = sqrt((2n+3)(n+2) / (n+1)^2)`, equivalently `h_n_[0, 1] = 8 (n+2) / ((2n+3)(n+1)^2)`.
* Correct (post-fix): `c_n = sqrt((2n+3)(n+2) / (n+1))`, equivalently `h_n_[0, 1] = (n+1) / ((2n+3)(n+2))`.

The implementation in `_jacobi_norm_factor` was always correct (verified by the audit's first-principles derivation, the numerical orthonormality matrices in `TestForbesQbfsOrthonormality`, and the new `TestOrthonormalizerDocstringMatchesCode` regression pin); only the prose lied.  The corrected comment block now derives the formula from A&S 22.2.1 (Jacobi norm on `[-1, 1]`) mapped to `[0, 1]` via the `2^(alpha + beta + 1)` weight factor, and explicitly notes the v4.15.0 wrong-prose history so future re-readers don't reintroduce it.

CHANGELOG line 124-126 carries the same wrong formula but is Agent F's territory (CHANGELOG edits); Agent D leaves that line untouched.

### D.5 -- P3-NEW-A: wave-optics path applies Q-bfs / Q-con properly (option A chosen)

`apply_real_lens` (the wave-optics path in `lumenairy/elements/_lens_real.py`) emitted a `RuntimeWarning` and silently skipped the freeform departure for any `freeform_type` -- including the new Forbes Q types.  Switching from `apply_real_lens_traced` (raytrace) to `apply_real_lens` (wave-optics) therefore silently lopped the Q sag off the OPD.

**Choice: option (a) properly apply.**  The brief said option (a) is preferred for v4.15.1 if the wave-optics path file is in scope.  `_lens_real.py` was explicitly delegated to Agent D for this purpose (per the brief's "you handle the wave-optics Q dispatch if you choose option (a)" clause).  Implementing (a) closes the wave-optics asymmetry and matches the raytrace path's behaviour.

**Fix.**  In the per-surface sag-build block of `apply_real_lens`, for `freeform_type in ('q_bfs', 'q_con')` route through the existing `surface_sag_freeform` dispatcher to compute the full base-conic + freeform-departure sag on the decentered `(Xs, Ys)` grid.  The dispatcher honours the v4.15.1 P1-F1-1 radial clip and P1-F1-2 required-`r_max` guards.

**Edge case: Forbes Q + biconic base.**  `surface_sag_freeform` only supports rotationally symmetric base conics, so combining `freeform_type='q_bfs'` with `radius_y` set still warn-and-skips the freeform (consistent with the raytrace path's existing behaviour, which raises `NotImplementedError` for biconic + freeform).  Users that need biconic + Forbes Q should use `apply_real_lens_traced`.

**Other freeform types (`xy_polynomial`, `'zernike'`, `'chebyshev'`).**  These remain warn-and-skip on the wave-optics path -- the task brief flagged them as Agent F's scope for the wave-optics asymmetry closure.  The existing `RuntimeWarning` is preserved for them; only the Q-bfs / Q-con branch is rerouted in this patch.

### D.6 -- P2: `__all__` symmetry re-exports

`surface_sag_q_bfs` and `surface_sag_q_con` were exported from top-level `lumenairy/__init__.py` but were missing from `lumenairy/elements/__init__.py`, so `from lumenairy.elements import surface_sag_q_bfs` raised `ImportError` even though the top-level resolution worked.  Same asymmetry for `make_off_axis_parabola` (top-level vs `lumenairy/io/__init__.py`).

**Fix.**  Re-export the three names through their respective subpackage `__init__.py` and add them to the corresponding `__all__` lists.  Function implementations themselves are untouched (`make_off_axis_parabola` is Agent A's territory; D only adds the import + `__all__` entry).

### Notes on the (a)/(b) choice for the wave-optics path (D.5)

The brief offered:

* **(a)** Properly apply Q-bfs / Q-con sag in the wave-optics path (matching what raytrace does), OR
* **(b)** Explicitly raise `NotImplementedError` rather than warn-and-skip so the user knows the path doesn't support it.

**Chose (a).**  Rationale:

* The brief explicitly recommended (a) for v4.15.1 and explicitly delegated the `_lens_real.py` Q dispatch to Agent D ("per the brief, you handle the wave-optics Q dispatch if you choose option (a)").
* The Q-bfs / Q-con sag is a 2-D scalar phase contribution structurally identical to the existing `_surface_sag_general` + `surface_sag_biconic` path; the dispatcher integration is a localised six-line addition.
* The fix routes through `surface_sag_freeform` (the existing dispatcher), so the v4.15.1 P1-F1-1 radial clip and P1-F1-2 required-`r_max` guards are automatically honoured -- the wave-optics path inherits the same fixes the raytrace path got.
* Option (b) would be strictly more conservative but leaves the asymmetry vs raytrace pinned indefinitely; in v4.15.1's "close the Forbes Q consumer paths" framing, leaving wave-optics broken would be half-shipping the patch.

**Scope discipline.**  The (a) implementation is restricted to the `freeform_type in ('q_bfs', 'q_con')` branch.  Other freeform types (xy_polynomial, Zernike, Chebyshev) continue to warn-and-skip per their existing v4.11.2 behaviour -- the brief flagged those as Agent F's wave-optics scope.

**Biconic-base edge case.**  `surface_sag_freeform` does not support biconic-base + Q-bfs / Q-con; combining `radius_y` with a Q freeform on the wave-optics path falls back to the biconic-only sag and emits a clarifying `RuntimeWarning`.  This matches the raytrace path's `NotImplementedError("Freeform departure on a biconic base is not supported yet")` behaviour (just demoted from raise to warn, consistent with `apply_real_lens` not being a strict-correctness-or-fail path).
