* **P2-NEW-V4-2 -- `[tool.mypy]` config preparation.**  v5.0
  shipped a `[tool.mypy]` config that, when run, produced ~1952
  errors: 63 inside the declared 5-module scope (`backend/`,
  `_deprecation.py`, `_context.py`, `progress.py`, `memory.py`)
  plus ~1889 cascade errors as mypy followed imports into
  un-annotated downstream modules (numpy, scipy, matplotlib, and
  the bulk of `lumenairy/`).  v5.0.1 adds
  `follow_imports = "silent"` to `[tool.mypy]` so a future
  activation only sees the 63 scope-local errors that the v5.1
  cleanup actually owns; per-file overrides are not needed
  because the `files` whitelist is already explicit (mypy will
  not enter any code outside the whitelist with
  `follow_imports = "silent"`).  No CI wiring at v5.0.1 -- the
  `unit-tests.yml` workflow keeps mypy unwired until the v5.1
  scope-local cleanup lands; the config-prep release stays
  scoped.

### P3 closures

* **P3-NEW-F1-1 -- stale Python 3.9 references in the V11 walker.**
  `tests/unit/test_v4_16_2_dispatcher_pin_doc_consistency.py:51-52,
  :68` had a tomllib import-fallback comment block citing
  Python 3.9 and `requires-python = ">=3.9"`.  v5.0 bumped the
  library floor to 3.10; v5.0.1 refreshed the comments to name
  Python 3.10 as the only fallback target and added a v5.0.1
  audit-closure comment at the site.

* **P3-NEW-F2-2 -- CHANGELOG ui/ -> lumenairy/ui/ doc drift.**
  CHANGELOG line 72 cited the ruff `extend-exclude` as
  `"validation/, docs/, examples/, ui/"` but `pyproject.toml`
  correctly scopes the exclude as `lumenairy/ui/`.  v5.0.1
  corrected the CHANGELOG to use the canonical path and added
  an inline audit-closure citation.

* **P3-NEW-F2-MCF -- CHANGELOG MCF deferral clarification.**
  CHANGELOG line 112's bare `MCF.coherence_at(...) object`
  bullet was unclear: `PartialCoherenceMCF` and its
  `coherence_at(...)` method already shipped in v4.15.1 and
  the class is re-exported at the top level as
  `lumenairy.PartialCoherenceMCF`.  v5.0.1 rewrote the bullet
  to clarify the actual deferred work -- a shorter top-level
  alias `lumenairy.MCF` for symmetry with
  `lumenairy.propagate_ensemble` so the partial-coherence
  import story is uniform.  The v4.16.x ROADMAP entry "MCF
  object" predates v4.15.1 and was carried forward without
  rewording at v5.0; the v5.0.1 CHANGELOG bullet is now the
  authoritative deferral statement.

* **P3-NEW-V3-3 -- 3.14 classifier vs CI matrix mismatch.**
  `pyproject.toml` listed Python 3.14 in the classifiers but
  the CI matrix in `.github/workflows/unit-tests.yml` runs
  3.10-3.13 only.  v5.0.1 dropped 3.14 from the classifiers --
  the canonical target is the CI matrix.  3.14 is too new for
  the optional accelerator dependencies (numba, jax, pyfftw) to
  have published wheels against; when 3.14 wheels stabilise the
  matrix grows first and the classifier returns.

* **`apply_*_lens` shim-preservation closure.**  Documented in
  the CHANGELOG v5.0.0 entry's "Shims preserved" block and in
  the ROADMAP v5.1 section's "Active back-compat shims at v5.0
  (intentionally kept)" subsection that the 3 retained shims
  (`apply_thin_lens`, `apply_real_lens`,
  `apply_real_lens_traced`) are **intentionally kept** as
  legitimate one-stop public API surface.  Both notes
  explicitly anticipate the v5.2+ audit that would otherwise
  flag them as stale-shim candidates.
