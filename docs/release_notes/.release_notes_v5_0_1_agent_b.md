## v5.0.1 -- Agent B: shim-removal anti-regression pin parity

Closes 1 P2 + 2 P3 findings from
`docs/audits/AUDIT_V5_0_0_2026_05_20.md` concentrated on the
asymmetric anti-regression coverage of the v5.0 honest-break
closures.  Tight scope per the v5.0.1 patch plan: tests + a
CHANGELOG arithmetic correction; no library code touched (other
agents own ruff/F821 cleanup, ROADMAP refresh, and mypy/library
work).

### Items closed

* **P2-NEW-F2-1 -- shim-removal anti-regression pin asymmetry.**
  Only 1 of 5 v5.0 honest-break closures had an anti-regression
  pin at ship (`test_analysis_dot_analysis_shim_removed_in_v5_0`
  at `tests/unit/test_validation_helpers.py:319`).  Risk: a v5.1
  maintainer could accidentally re-add `lumenairy/ao.py`,
  `lumenairy/io/hdf5.py`, top-level `lumenairy/system.py`, the
  JAX legacy aperture schema, or the `cosmic_ray_rate=` kwarg
  with no test failure.

  Added a new test class
  `TestV5_0_ShimRemovalAntiRegression` at the end of
  `tests/unit/test_validation_helpers.py` with one pin per
  closure (5 tests, modeled structurally on the existing
  analysis-shim pin):

  1. `test_lumenairy_ao_shim_removed_in_v5_0` --
     `from lumenairy.ao import DeformableMirror` -> `ImportError`.
  2. `test_lumenairy_io_hdf5_shim_removed_in_v5_0` --
     `from lumenairy.io.hdf5 import save_field_h5` -> `ImportError`.
  3. `test_lumenairy_system_top_level_removed_in_v5_0` --
     `from lumenairy.system import propagate_through_system` ->
     `ImportError` (the new path `lumenairy.propagators.system`
     works; the top-level is gone).
  4. `test_jax_aperture_legacy_schema_removed_in_v5_0` --
     `propagate_through_system_jax(..., 'params':{'radius':...})`
     -> `ValueError` whose message contains `legacy` and
     `removed in v5.0` (the `match=` pattern locks in the
     migration recipe text alongside the raise).
  5. `test_apply_detector_cosmic_ray_rate_kwarg_removed_in_v5_0`
     -- `apply_detector(..., cosmic_ray_rate=R)` -> `TypeError`
     (unexpected keyword argument).

  Each test cites the audit closure in a comment
  (`# audit closure: P2-NEW-F2-1 (shim-removal anti-regression
  pin asymmetry)`).  All 5 tests pass at v5.0 HEAD.

* **P3-NEW-F1-4 -- public-API smoke negative counter-pin.**
  `tests/unit/test_public_api.py` had no synthetic broken-`__all__`
  fixture proving the assertion machinery isn't vacuous (e.g. if
  someone changed `hasattr(la, name)` to `name in dir(la)` --
  which would silently pass for any string).  Added
  `test_phantom_name_in_dunder_all_would_be_caught`: injects
  a phantom name into `la.__all__`, asserts `hasattr(la, phantom)
  is False`, and removes the phantom cleanly via `try/finally`.
  Pattern parallel to V11's `_DISCOVERED_CALLSITES` counter-pin
  work from the v4.16.x walker series.

* **P3-NEW-3-way convergent -- CHANGELOG "536 entries"
  arithmetic.**  V3 + V4 + F2 all flagged that
  `CHANGELOG.md:82` cited "536 entries verified at v5.0 ship"
  but `len(lumenairy.__all__) == 533`.  The 536 is the **pytest
  case count**: 533 parametrized + 3 standalone smoke tests
  (`test_dunder_all_exists_and_is_a_list`,
  `test_dunder_all_has_no_duplicates`,
  `test_version_string_format`).  Updated to "533 entries
  verified via 536 smoke tests (533 parametrized + 3
  standalone)" -- pure arithmetic correction; no test impact.

### Sibling-gap sweep

After installing the 5 new pins, swept the CHANGELOG v5.0
"Breaking changes" block (lines 22-55) for any v5.0 closure
that still lacks an anti-regression pin.  Result: **complete
coverage**.

| v5.0 closure | Pin |
|---|---|
| Python 3.10+ floor | Runtime-enforced via `pyproject.toml` `requires-python = ">=3.10"`; not a removable shim.  V11 walker covers CHANGELOG entry. |
| `lumenairy.system` -> `lumenairy.propagators.system` | NEW: `test_lumenairy_system_top_level_removed_in_v5_0` (top-level removed); preserved-public-namespace verified by `test_public_api.py` (auto-picks up `propagate_through_system` via `__all__`). |
| `lumenairy.analysis.analysis` shim | Existing: `test_analysis_dot_analysis_shim_removed_in_v5_0`. |
| `lumenairy.ao` shim | NEW: `test_lumenairy_ao_shim_removed_in_v5_0`. |
| `lumenairy.io.hdf5` shim | NEW: `test_lumenairy_io_hdf5_shim_removed_in_v5_0`. |
| JAX aperture legacy schema | NEW: `test_jax_aperture_legacy_schema_removed_in_v5_0`. (Also covered by 3 positive-path sibling tests in `test_audit_fixes_v4_12_0_round4_jax.py` lines 114/149/185, but those are split across shapes; the new pin gives a single canonical entry point in the v5.0.1 anti-regression class.) |
| `apply_detector(cosmic_ray_rate=)` kwarg | NEW: `test_apply_detector_cosmic_ray_rate_kwarg_removed_in_v5_0`. (Also covered by `test_legacy_kwarg_removed_in_v5_0` in `test_audit_fixes_v4_9.py:242`, but that pin lives with v4.9 deprecation history; the new pin co-locates the kwarg removal with the other v5.0 shim closures.) |

The two NEW pins that overlap pre-existing tests are intentional
duplicates -- they group all five v5.0 honest-break closures
into a single class so a v5.1 maintainer searching for "what
v5.0 broke and where's it pinned" has one obvious home.

Meta-observation: the v5.0 audit's framing of this as a
"sibling-gap surface" is accurate -- the meta-pattern has
miniaturized again, from doc-consistency surfaces (V11) down to
"anti-regression-pin coverage of the breaking-change set itself."
Sibling-gap discipline is now self-referential: the audit walks
the audit-closure tests for completeness.

### Decision: kept new pins in `test_validation_helpers.py`

The prompt offered the choice of a new file
`test_v5_0_1_agent_b.py` vs adding the class to
`test_validation_helpers.py`.  Picked the latter to keep
the new pins physically adjacent to
`test_analysis_dot_analysis_shim_removed_in_v5_0`.  Easier for
future maintainers to find by grep on
`shim_removed_in_v5_0`.  No new file means lower test-tree
fragmentation; the v4.13.1 ROADMAP-V12 audit explicitly
flagged 57-file `test_audit_fixes_*` proliferation as a v5.1
consolidation target, so adding yet another tiny file for 5
tests would have cut against that grain.

The counter-pin landed inside `test_public_api.py` for the
same reason -- it belongs with the assertion machinery it
counter-tests, not in a sidecar file.
