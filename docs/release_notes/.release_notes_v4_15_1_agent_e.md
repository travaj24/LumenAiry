## P1-NEW-C -- UI deprecation migration

`lumenairy/ui/model.py:SourceDefinition.to_source` had 7 callsites
using the legacy positional `Source.<factory>(<size>, N, dx,
wavelength)` form (the form that started emitting
`DeprecationWarning` at v4.15.0 startup).  The v4.15.0 release that
introduced the deprecation shim didn't migrate its own internal UI
consumers; on first widget construction a stray Source-factory
DeprecationWarning surfaced from inside the library.

### Resolution

All 7 callsites migrated to the canonical kwarg-only form:

| Site (model.py line) | Before | After |
|---|---|---|
| 162 (plane_wave) | `_Source.plane_wave(N, dx_m, wavelength, ...)` | `_Source.plane_wave(N=N, dx=dx_m, wavelength=wavelength, ...)` |
| 175 (gaussian) | `_Source.gaussian(w0, N, dx_m, wavelength, ...)` | `_Source.gaussian(N=N, dx=dx_m, wavelength=wavelength, w0=w0, ...)` |
| 181 (gaussian_aperture; reuses gaussian factory) | `_Source.gaussian(w0, N, dx_m, wavelength, ...)` | `_Source.gaussian(N=N, dx=dx_m, wavelength=wavelength, w0=w0, ...)` |
| 187 (top_hat) | `_Source.top_hat(d, N, dx_m, wavelength, ...)` | `_Source.top_hat(N=N, dx=dx_m, wavelength=wavelength, diameter=d, ...)` |
| 193 (fiber_mode) | `_Source.fiber_mode(mfd, N, dx_m, wavelength, na=..., ...)` | `_Source.fiber_mode(N=N, dx=dx_m, wavelength=wavelength, mode_field_diameter=mfd, na=..., ...)` |
| 200 (point_source) | `_Source.point_source(N, dx_m, wavelength, z0=..., ...)` | `_Source.point_source(N=N, dx=dx_m, wavelength=wavelength, z0=..., ...)` |
| 227 (fallback plane_wave) | `_Source.plane_wave(N, dx_m, wavelength, ...)` | `_Source.plane_wave(N=N, dx=dx_m, wavelength=wavelength, ...)` |

A one-block migration comment is anchored at the top of the
mapping (lines 159-165) so future audit readers can trace the

## P1-F1-6 -- system.evaluate mixed-shape prescription precedence

`system.py:_prescription_to_elements` previously accepted a
prescription dict carrying BOTH

- the factory shape: `'surfaces'` + `'thicknesses'` (output of
  `make_singlet` / `make_doublet`); and
- the Zemax shape: `'elements'` + `'all_thicknesses'` (output of
  `load_zemax_zmx`).

When both were present, the code silently routed through the Zemax
branch with no diagnostic.  The audit's concern is the
hand-grafted case: a user starts from a `make_singlet` dict, then
attaches an `elements` list to it (e.g. to add a mirror), and the
silent precedence drops the entire `surfaces` half.

### Resolution

`_prescription_to_elements` now raises `ValueError` if both shapes
are present in the same dict.  The error message names both shape
keys so the user knows which set to strip.  Callers that want the
Zemax shape should drop `surfaces` + `thicknesses`; callers that
want the factory shape should drop `elements` + `all_thicknesses`.

This is a behavior change for any caller that passed `load_zemax_zmx`
output DIRECTLY to `system.evaluate`: the loader emits both shape
sets (for `apply_real_lens` convenience), and the direct pass-through
now raises.  Migration: pass `{k: v for k, v in rx.items() if k not
in ('surfaces', 'thicknesses')}` instead, or call
`_prescription_to_elements`-equivalent paths via `propagate_through_system`
directly.

### Test pin

`TestE2SystemEvaluateMixedShape::test_mixed_shape_raises_value_error`
-- builds a hand-mixed dict containing both shapes; asserts
`ValueError` is raised and the message names both keys.

## P2 -- Sentinel consolidation

The audit Part 3 F3 P2 flagged three sentinel singletons that did
not share the `_deprecation._Sentinel` base class -- a structural
duplication that left each of them susceptible to a separate set
of bugs.  In particular none of the three carried a `__reduce__`
method, so a pickle round-trip produced a NEW instance on the
receiving side and silently broke `is`-identity checks in
distributed merit evaluation (joblib / multiprocessing).

### Resolution

`_deprecation._Sentinel` is extended with:

- A module-level `_SENTINEL_REGISTRY: dict[str, _Sentinel]`
  populated by `__init__` (every instance registers itself by name).
- A `__reduce__` method returning
  `(_sentinel_unpickle, (self._name,))` so pickling round-trips
  through a name lookup rather than reconstructing the instance.
- `_sentinel_unpickle(name)` -- a module-level reconstructor (also
  exported in `__all__`) that pickle finds by name.  Returns the
  registry singleton when present; falls back to constructing a
  fresh `_Sentinel(name)` (which then self-registers) so cross-
  process pickling works even if the original class isn't
  imported on the receiving side.

The two custom sentinels then change one line each to inherit:

- `lumenairy.optimize.core._ZeroApertureMaskSentinel(_Sentinel)`
  with `__init__` calling `super().__init__('_ZERO_APERTURE_MASK')`.
  The singleton `_ZERO_APERTURE_MASK` is exported unchanged.
- `lumenairy.elements.polarization._AngleUnsetSentinel(_Sentinel)`
  with `__init__` calling `super().__init__('_ANGLE_UNSET')`.  The
  singleton `_ANGLE_UNSET` is exported unchanged.

Sentinel inventory (the dispatch task asked for a third sentinel
beyond the two custom classes; the only other `_Sentinel` instance
is the base-class instance `_NO_DEFAULT` in `_deprecation.py:60`,
which now picks up the registry / pickle-safe protocol automatically
through the base-class extension):

| Sentinel | File | Class |
|---|---|---|
| `_NO_DEFAULT` | `_deprecation.py` | `_Sentinel` (base) |
| `_ZERO_APERTURE_MASK` | `optimize/core.py` | `_ZeroApertureMaskSentinel(_Sentinel)` |
| `_ANGLE_UNSET` | `elements/polarization.py` | `_AngleUnsetSentinel(_Sentinel)` |

A grep for `class _\w*Sentinel` returns exactly these three classes
(the base plus the two subclasses).  No fourth named `*Sentinel`
class survives.

### Test pins

`TestE4SentinelPickleRoundTrip`:

- `test_no_default_pickle_round_trip` -- `_NO_DEFAULT` round-trip
  preserves `is`-identity.
- `test_zero_aperture_mask_pickle_round_trip` -- same for
  `_ZERO_APERTURE_MASK`.
- `test_angle_unset_pickle_round_trip` -- same for `_ANGLE_UNSET`.
- `test_sentinel_inheritance_consolidated` -- both
  `_ZeroApertureMaskSentinel` and `_AngleUnsetSentinel` are
  `issubclass(_Sentinel)`.
- `test_sentinel_registry_contains_all_three` -- the registry
  maps `'NO_DEFAULT'`, `'_ZERO_APERTURE_MASK'`, and `'_ANGLE_UNSET'`
  to the canonical singleton instances.

## P3-1 -- n=1.0 consistency

`optimize/multiconfig._resolve_lens_glass_index` previously rejected
`n=1.0` strict via `if not (1.0 < n < 5.0):`.
`user_library.register_fixed_glass` already accepted `n=1.0`
inclusive via `if not (np.isfinite(n_f) and 1.0 <= n_f <= 4.0):`.
A user who registered `register_fixed_glass(name='vacuum', n=1.0)`
saw the registration succeed, but a subsequent
`_resolve_lens_glass_index('vacuum', wavelength=...)` triggered the
fallback path (with a confusing "outside expected (1.0, 5.0) range"
warning) and returned `n=1.5`, mis-resolving the lens index.

### Resolution

The `_resolve_lens_glass_index` bounds check is changed to
`if not (1.0 <= n <= 4.0):` -- inclusive on both ends, matching
`register_fixed_glass`.  Vacuum / air at n=1.0 exactly is now an
accepted value.  The upper bound widened from 5.0 to 4.0 (matching
user_library) because n>4 is almost certainly a typo / unit
mismatch (mm vs m vs um in a custom dispersion callable); the
canonical high-index limit is Ge ~ 4.0.

### Test pins

`TestE5P3NEqualOneConsistency`:

- `test_register_fixed_glass_accepts_n_equal_1` -- pins the
  user_library side (already correct; pin prevents regression).
- `test_resolve_lens_glass_index_accepts_n_equal_1` -- pins the
  multiconfig side; registers `'__vacuum_resolve_pin__'` with
  n=1.0, then resolves it through `_resolve_lens_glass_index` and
  asserts the returned value is `pytest.approx(1.0, abs=1e-12)`
  WITH NO `UserWarning` (promoted to error so a regression to the
  fallback path fails the test).

## P3-2 -- Codegen major-version-bump warning

`io/codegen.py` emitted a runtime version pin in both generated
script flavors (`_generate_unrolled` and `_generate_system_style`)
that was lower-bound only:

```python
if tuple(map(int, lumenairy.__version__.split(".")[:3])) < (4, 15, 0):
    raise RuntimeError(...)
```

A user running the v4.15-generated script on a future v5.x runtime
got no warning that the script was generated against a v4.x API
(which may have breaking changes by v5.0).

### Resolution

Both flavors now emit an additional upper-bound check that fires
`UserWarning` (not `RuntimeError` -- the script still runs):

```python
import warnings as _la_codegen_warnings
if tuple(map(int, lumenairy.__version__.split(".")[:3])) >= (5, 0, 0):
    _la_codegen_warnings.warn(
        "This script was generated against lumenairy 4.15.0; "
        "current version is {lumenairy.__version__}.  Major version "
        "5+ may have breaking API changes; consider regenerating "
        "the script via lumenairy.io.codegen.generate_simulation_script.",
        UserWarning, stacklevel=2,
    )
```

The next-major tuple is computed at generation time from the
generating library version (`(_gen_major + 1, 0, 0)`), so a script
generated by v5.4 would emit the warning starting at v6.0, etc.

### Test pins

`TestE5P3CodegenMajorVersionWarning`:

- `test_unrolled_script_has_upper_bound_warning` -- generates an
  unrolled script and asserts the source contains the
  `>= (5, 0, 0)` upper-bound check, the `UserWarning` category, and
  the "breaking API" message text.
- `test_system_script_has_upper_bound_warning` -- same for
  `style='system'`.

## P3-3 -- LambertianBSDF frame assumption

`elements/bsdf.LambertianBSDF.evaluate` silently assumed the
surface-local frame has +z = outward surface normal.  The
hemisphere check is a sign test on the scattered-direction
z-component; if the caller passes a world-frame direction without
applying the global -> surface-local rotation, rays were
mis-classified.

### Resolution

1. Docstring gains an explicit "Frame assumption" subsection
   spelling out the convention.
2. `evaluate` gains a runtime check: when the `incident_dir` is a
   3-vector with `|x|+|y| > 0.3` and `z > +0.7`, emit a
   `RuntimeWarning`.  This is the signature of a world-frame
   direction being used as-is (z near +1 implies normal incidence
   in the world frame; large transverse + near-z is the
   "off-axis but not rotated" pattern).  The check is advisory
   only; the result is still returned so legitimate Monte-Carlo
   paths with pre-rotated incident vectors (which are
   axially aligned, |x|+|y|=0) don't trip it.

### Test pins

`TestE5P3LambertianBSDFFrameWarning`:

- `test_incident_dir_with_transverse_component_warns` -- pass
  `incident_dir=(0.2, 0.2, 0.96)` and assert `RuntimeWarning`
  fires with the word "surface" in the message.
- `test_axially_aligned_incident_does_not_warn` -- pass
  `incident_dir=(0.0, 0.0, -1.0)` (canonical surface-frame input)
  and assert NO `RuntimeWarning` fires; the returned value is the
  expected `rho / pi`.

## P3-4 -- Coatings TIR cap warning

`elements/coatings.coating_reflectance` caps `sin_t` (the Snell
transmitted-angle sine) at 0.9999 when Snell's law has no real
solution.  Physics: the cap produces a finite real `cos_t` and so
a finite transmittance, which is WRONG at TIR -- the steady-state
R is 1.0 and T is 0.0.

Pre-v4.15.1 the intra-stack cap emitted a `RuntimeWarning`
(`stacklevel=2`), but the substrate-interface cap at line 141 was
silent.  A high-AOI polarizing-beam-splitter coating with a
lower-n substrate would silently lose accuracy at the substrate
interface with no diagnostic.  Additionally, `RuntimeWarning` is
filtered to silent in some IDE notebook / pytest configurations,
so the audit recommended switching to `UserWarning` for guaranteed
visibility.

### Resolution

- Both cap sites (the per-layer loop and the substrate interface)
  now emit `UserWarning` instead of `RuntimeWarning`, with a
  message that explicitly states the physics violation ("R should
  be 1.0, T should be 0.0 in the steady state").
- The substrate-interface cap is now wrapped in an `if sin_sub >
  1.0:` guard with its own warning emission (mirroring the
  intra-stack cap).
- A new comment block at each cap site explains the physics so
  future readers don't strip the cap without understanding the
  consequence.

### Test pins

`TestE5P3CoatingsTIRWarning::test_intra_stack_tir_warns` --
constructs a high-AOI (70 deg) high-n ambient (n=2.0) scenario
where the next layer has n=1.0 so sin_t > 1.8 and the cap fires;
asserts a warning containing "TIR" is emitted.

## Migration notes for callers

- **UI consumers**: no migration needed (this was an internal
  consumer migration).
- **`system.evaluate` callers** passing `load_zemax_zmx` output
  directly: starting v4.15.1 this raises `ValueError` because the
  loader emits BOTH shape sets.  Workaround:

  ```python
  rx = la.load_zemax_zmx('design.zmx')
  rx_zemax_only = {k: v for k, v in rx.items()
                    if k not in ('surfaces', 'thicknesses')}
  result = la.system.evaluate(rx_zemax_only, src)
  ```

- **Sentinel pickle consumers** (joblib / multiprocessing): no
  migration needed; the `__reduce__` protocol is fully backward-
  compatible and was carrying broken `is`-identity silently
  pre-v4.15.1 anyway.  Distributed merit eval should now see
  `is`-correct sentinel comparison.
- **`_resolve_lens_glass_index` users**: anyone hand-registering a
  glass with `n=1.0` (vacuum / air) will now resolve cleanly
  instead of falling through to the n=1.5 default.  If the n=1.5
  default was being relied on for an n=1.0 lookup, that was a
  silent bug.
- **Code-gen script users**: a v4.15.1-generated script running on
  a future v5.x runtime will now print a one-line `UserWarning`
  recommending regeneration; the script otherwise runs.
- **`LambertianBSDF` users**: passing world-frame directions
  without pre-rotation will now emit a `RuntimeWarning` (advisory
  only; the result is still returned).
- **`coating_reflectance` users hitting TIR**: warnings are now
  `UserWarning` (always-visible) and fire at BOTH cap sites
  (intra-stack and substrate interface), not just the intra-stack
  site.
