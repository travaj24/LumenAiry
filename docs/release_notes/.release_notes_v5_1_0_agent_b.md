## v5.1.0 -- Agent B: lumenairy/raytrace/core.py 6-file split

Closes the ROADMAP-deferred `core.py` decomposition for the
`lumenairy.raytrace` subpackage.  Tight scope per the v5.1.0
Agent B plan: mechanical reorganisation only -- the 4443-line
`raytrace/core.py` is split into seven focused submodules; the
ASCII content of every function / class / constant moves
verbatim; the public API (every name importable from
`lumenairy.raytrace.core` or `lumenairy.raytrace`) is preserved
bit-for-bit.

**No physics change.**  Every numerical helper -- intersection,
Snell refraction, paraxial recursion, Welford / Hopkins Seidel
sums, ABCD matrix, pupil imaging, OPD accumulation, ... -- is a
character-by-character copy of the pre-v5.1.0 v5.0.x source.
The audit-fix history (v4.7 Δ(u/n), v4.10 mirror sign, v4.11.2
mirror parity, v4.12.1 Newton-skip fast path, etc.) is preserved
in-place in the new submodules.

### Topology decision

The ROADMAP recommended a 7-way split with labels
**surface / intersection / trace / world-trace / Seidel /
ray-fan / layout**.  After mapping each function to a target
submodule I followed that exact topology, with two judgment
calls documented below:

### Judgment calls

1. **`seidel.py` carries the whole paraxial / aberration cluster
   (~900 LOC), not just the Seidel sums.**  Splitting paraxial
   trace, ABCD, lens-info, pupils, first-order, and Seidel into
   separate files would have required duplicating the
   `_paraxial_*` helpers or threading them through four import
   edges -- the dependency graph is fundamentally linear
   (`_paraxial_*` -> `system_abcd` -> `compute_pupils` /
   `first_order_data` / `seidel_coefficients`).  All these
   helpers share the Welford reduced-coordinate paraxial trace
   and the same mirror-parity sign convention; keeping them in
   one file makes the cross-checking commentary
   (`# pre-4.11.2`, `# v4.10`, ...) easier to read.  Naming the
   file `seidel.py` matches the ROADMAP's label.

2. **`layout.py` hosts the textual summary printouts, not 2-D
   layout figures.**  The pre-v5.1.0 `core.py` contained the
   `trace_summary` and `prescription_summary` printouts but no
   matplotlib 2-D layout figures (the spot diagram lives in the
   ray-fan/spot cluster).  I retained the ROADMAP's
   `layout.py` filename so a later v5.x agent can add 2-D
   layout figures without splintering the namespace; the
   printouts are the seed contents.  No physics or figure code
   was added.

3. **Two world-frame fan helpers (`ray_fan_data_world`,
   `opd_fan_data_world`) are deliberately OFF
   `ray_fan.__all__`.**  Pre-v5.1.0 `lumenairy/raytrace/__init__.py`
   imported them from `core` (so they were accessible by name)
   but did NOT add them to `lumenairy.raytrace.__all__` (the
   advertised public surface).  Preserving that "module-
   attribute visible but not advertised" status:
   * keeps `from lumenairy.raytrace import ray_fan_data_world`
     working bit-for-bit;
   * keeps `tests/unit/test_v4_16_0_walker_all_symmetry.py`
     (the `__all__`-symmetry walker introduced in v4.14.0
     P1-NEW-4) from flagging the new submodule's `__all__` as
     a sibling-gap regression.
   The functions are still re-exported explicitly from
   `core.py` so legacy import paths resolve unchanged.

4. **`core.py` deliberately does NOT define `__all__`.**  The
   pre-v5.1.0 `core.py` had no `__all__` either; star-imports
   from `core` fell back to "every module-level non-underscore
   name" semantics, and the v4.16.0 walker symmetry test
   only examines submodules that DO define `__all__`.  Adding
   an aggregated `__all__` here would advertise
   `ray_fan_data_world` / `opd_fan_data_world` as core's public
   surface even though `lumenairy.__all__` deliberately omits
   them -- exactly the sibling-gap regression the walker is
   there to catch.  The shell's docstring documents the
   decision in-place so a future maintainer doesn't add
   `__all__` without thinking about the walker contract.

### Public API contract

Every name listed in pre-v5.1.0
`lumenairy/raytrace/__init__.py`'s explicit `from .core import
(...)` block is verified importable from `lumenairy.raytrace.core`
AND `lumenairy.raytrace` after the split.  This includes the
private helper `_make_bundle` that `lumenairy/analysis/aberration.py`
imports directly from `lumenairy.raytrace.core`.

Anti-regression coverage: `tests/unit/test_v5_1_0_agent_b_split.py`
contains 141 tests in four layers:

1. **`TestSplitPublicSurfaceFromCore`** (~85 tests): each of the
   42 legacy public names is importable from both
   `lumenairy.raytrace.core` and `lumenairy.raytrace`, plus a
   star-import-pickup check.
2. **`TestSplitSubmoduleResidency`** (~7 tests): each public
   name resides in the expected new submodule (pins the
   topology so a v5.2 maintainer can't silently move
   `system_abcd` out of `seidel.py`).
3. **`TestSplitObjectIdentity`** (~32 tests): each name
   resolves to the *same* Python object regardless of the
   import path -- the classic "I accidentally duplicated the
   class definition after a split" tripwire.
4. **`TestSplitSmokeTrace`** (1 test): end-to-end singlet
   trace exercising the cross-module pipeline.  If any wiring
   broke (ray_fan can't see surfaces_from_prescription,
   world_trace can't see _refract, ...) this fails before the
   numeric audit suite even starts.
5. **`TestSplitNoTopologyDrift`** (2 tests): pin that
   `surface.py` is a leaf (no trace / intersection / seidel
   imports) and `intersection.py` doesn't pull the trace
   engine -- topology guards against a future "let's just
   merge intersection back into surface" drift.

### Bugs spotted (NOT fixed in this PR per the v5.1.0 scope)

Per the v5.1.0 plan: "If you spot a bug, document it in release
notes but DO NOT fix it in this PR."  Two minor observations
worth flagging for a follow-up audit:

* The pre-existing `raytrace_system` (now in `trace.py`)
  *mutates* `surfaces[-1].thickness` in place when it appends
  the image-plane surface (line ~4435 in the legacy
  `core.py:4435`).  `trace_prescription`'s equivalent block was
  hardened in v4.13.2 P1-NEW-J to use `_surface_copy_with`;
  `raytrace_system` was missed.  Same shared-state-mutation
  tripwire pattern.  Filed as TODO for a future cleanup.

* In `find_lenses` (now in `seidel.py`), the inner-loop label
  `start` shadows the outer-scope `start` parameter that would
  otherwise be passed to `lens_abcd`.  The current code uses
  `lens_abcd(surfaces, wavelength, start=start, end=end)` and
  Python's scoping resolves to the inner-loop variable
  correctly, but the readability cost is real.  Filed as a
  rename-candidate (`start_idx` would be clearer).

Both are pre-existing v5.0.x behaviour and are explicitly NOT
addressed in this v5.1.0 split.

### Cross-version notes

The split is a strict refactor: `__version__` stays at the
v5.0.1 value until a coordinator agent bumps it for the v5.1.0
release ship.  No `_DISCOVERED_CALLSITES` walker entries (the
walker doesn't enumerate the new submodules under any new
caller pattern), no `CHANGELOG.md` entries written by this
agent.
