## v4.16.2 -- Agent B: optimize-subsystem closures

Closes the 1 P1 + 3 P2 + 3 P3 optimize-subsystem findings from
`docs/audits/AUDIT_V4_16_1_2026_05_19.md`, all concentrated in
`lumenairy/optimize/core.py`:

* **P1-NEW-F1-3** -- `MultiWavelengthMerit` SUM->AVG was a silent
  behaviour change in v4.16.1.  The new AVG semantics are correct
  (match the docstring + the sibling `MultiFieldMerit` /
  `ToleranceAwareMerit` classes), but existing 3-wavelength weight
  calibrations silently saw a 3x drop in the merit contribution.
  v4.16.2 emits a one-cycle `FutureWarning` (latched at module
  level so it fires exactly once per process) flagging the
  transition.
* **P2-NEW-F1-1** -- `Constraint.__post_init__` used to run a
  defensive `fun(np.zeros(1))` probe so a vector return could be
  rejected at construction time.  For a BFL-style `fun` that
  internally calls `system_abcd(...)` the probe ran an entire
  ray-trace on every `Constraint(...)` instantiation, and caught
  exceptions were swallowed silently.  v4.16.2 removes the
  auto-probe; the shape check moves to an opt-in
  `Constraint.validate()` method.
* **P2-NEW-F1-2** -- v4.16.1's lambda-detector used
  `getattr(fun, '__name__', None) == '<lambda>'`, which missed
  closures (whose `__name__` is the inner-def name) and
  `functools.partial(lambda x: ..., ...)` (no `__name__`).  Both
  patterns are genuinely unpicklable and would fail under
  `differential_evolution(workers>1)` / joblib FD-gradient at the
  first parallel eval.  v4.16.2 replaces the heuristic with a
  direct `pickle.dumps(self.fun)` probe.
* **P2-NEW-F1-3** -- `tests/unit/test_v4_16_0_agent_c.py` had 4
  `Constraint(fun=lambda x: ...)` sites (and 1 sibling in the
  pymoo block) that started emitting `UserWarning` on every
  construction once the v4.16.1 detector landed.  All 5 sites
  promoted to module-level functions (the same pickle-safe pattern
  the warning recommends).  Suppressing the warning at the test
  fixture would just hide future drift; using module-level
  functions exercises the contract correctly.
* **P3-NEW-F1-3** -- `_resolve_bound(b, i, default)` silently
  accepted truncated 3-tuples like `(lb, ub, extra)` by indexing
  `b[i]`.  v4.16.2 adds an explicit `len(b) != 2` guard that
  raises `ValueError` with a clear hint.
* **P3-NEW-F1-7** -- the `Constraint` docstring example used
  `fun=lambda x: ...`, so copy-paste users hit the v4.16.1 lambda
  warning every time.  v4.16.2 rewrites the example to use a
  module-level `def my_constraint(x):` form.
* **P3-NEW-F1-8** -- scipy's `least_squares` contract is that
  `method='lm'` does NOT accept bounds; passing `method='lm'`
  together with non-None `bounds` silently overrode to
  `method='trf'`.  v4.16.2 adds a `UserWarning` at the override
  point so the user knows.

All changes preserve the v4.16.1 SUM->AVG arithmetic exactly --
no merit-value drift.  No physics semantics change.

### P2-NEW-F1-1 -- `Constraint.__post_init__` probe -> opt-in `validate()`

`lumenairy/optimize/core.py`.

**Removed from `__post_init__`** (was at line 3209-3232 pre-v4.16.2):

```python
try:
    _probe_x = np.zeros(1, dtype=np.float64)
    _probe_result = self.fun(_probe_x)  # <-- expensive for BFL etc.
except Exception:
    return
if isinstance(_probe_result, np.ndarray):
    if _probe_result.shape != ():
        raise TypeError(...)
```

**Moved to a new opt-in method**:

```python
def validate(self) -> None:
    """Best-effort scalar-shape check by probing fun(np.zeros(1))."""
    _probe_x = np.zeros(1, dtype=np.float64)
    try:
        _probe_result = self.fun(_probe_x)
    except Exception:
        return  # best-effort: same swallow-silent contract
    if isinstance(_probe_result, np.ndarray):
        if _probe_result.shape != ():
            raise TypeError(...)
```

**Why this matters:** the canonical user pattern is

```python
def _bfl_fn(x):
    pres = param.build(x)
    surfs = surfaces_from_prescription(pres)
    _, _, bfl, _ = system_abcd(surfs, wavelength)
    return float(bfl)

c = Constraint(fun=_bfl_fn, lb=5e-3, ub=None, label='BFL >= 5 mm')
```

Pre-v4.16.2 every `Constraint(...)` instantiation ran
`_bfl_fn(np.zeros(1))` -- which means `param.build(np.zeros(1))` ->
likely IndexError on a multi-variable parameterisation ->
exception caught silently.  Even for a 1-variable parameterisation
where the probe didn't raise, the entire trace ran.  Cost: O(1)
per `Constraint(...)` call but O(N) for an N-constraint setup,
and O(N * workers) under `differential_evolution(workers>1)`
where each worker forks and rebuilds the Constraint list.

The fix is to make the probe opt-in.  The docstring + a new test
in `test_v4_16_2_agent_b.py` document the migration:

```python
c = Constraint(fun=_bfl_fn, lb=5e-3, ub=None, label='BFL')
c.validate()   # explicit shape-check, runs the trace ONCE here
```

**Test fallout:** `tests/unit/test_v4_16_1_agent_c.py` had two
tests (`test_constraint_vector_return_is_rejected_in_post_init`,
`test_constraint_vector_return_message_cites_label`) that pinned
the v4.16.1 auto-probe behaviour.  Both updated to call
`.validate()` explicitly; the test names are preserved for
git-blame continuity.

### P2-NEW-F1-2 -- pickle-probe catches closures + functools.partial

`lumenairy/optimize/core.py`.

**Before (v4.16.1)**:

```python
fun_name = getattr(self.fun, '__name__', None)
if fun_name == '<lambda>':
    warnings.warn(...)
```

Misses:
* `def inner(x): ...` from a closure factory (`__name__ == 'inner'`)
* `functools.partial(lambda x: ..., ...)` (partial has no
  `__name__` attribute on stock CPython)
* Nested-def helpers (`__name__` is the helper's name, not lambda)

**After (v4.16.2)**:

```python
import pickle
try:
    pickle.dumps(self.fun)
except (pickle.PicklingError, AttributeError, TypeError) as e:
    warnings.warn(
        f"Constraint(label={self.label!r}): ``fun`` is not picklable "
        f"({type(e).__name__}: {e!s}); this will fail under "
        f"``differential_evolution(workers>1)`` / "
        f"joblib-parallelised FD-gradient with PicklingError. "
        f"Define ``fun`` as a module-level function (or use "
        f"functools.partial on a module-level function) for "
        f"parallel-workers compatibility.  Single-process SLSQP / "
        f"trust-constr works with non-picklable callables without "
        f"issue.",
        UserWarning, stacklevel=2,
    )
```

**Empirical verification** (regression tests pin all 3 patterns):

| Callable form                                  | v4.16.1 detector | v4.16.2 detector | Picklable? |
|------------------------------------------------|------------------|------------------|------------|
| `lambda x: float(x[0])`                        | WARN             | WARN             | NO         |
| `def inner(x): ...` from `_make_closure(...)`  | (missed)         | WARN             | NO         |
| `functools.partial(lambda x, c: ..., c=0.5)`   | (missed)         | WARN             | NO         |
| Module-level `def _module_level_sum(x): ...`   | (no warn)        | (no warn)        | YES        |

**Catch list** is `(pickle.PicklingError, AttributeError, TypeError)`:

* `pickle.PicklingError` -- the canonical "lambda inside this
  process can't be pickled" path.
* `AttributeError` -- closures over cell variables raise this on
  Python <3.10 in some pickle paths.
* `TypeError` -- some C-extension callables raise this when
  `pickle` can't introspect them.

**Performance note:** `pickle.dumps` on a typical user `fun`
(a small module-level function or `functools.partial`) takes
~10-100 microseconds.  The probe runs once per `Constraint(...)`
construction, which is once per design_optimize setup.
Acceptable for the safety benefit.

### P3-NEW-F1-3 -- `_resolve_bound` 2-tuple length guard

`lumenairy/optimize/core.py`.

**Before**:

```python
def _resolve_bound(b, i, default):
    if b is None:
        return default
    v = b[i]
    if v is None:
        return default
    return float(v)
```

Silently dropped the 3rd+ element of a tuple via indexing.

**After**:

```python
def _resolve_bound(b, i, default):
    if b is None:
        return default
    if len(b) != 2:
        raise ValueError(
            f"design_optimize(method='lm'): each bound must be a "
            f"2-tuple (lower, upper), got {len(b)}-tuple {b!r}.  "
            f"scipy's ``least_squares(bounds=(lb, ub))`` API takes "
            f"a 2-tuple of array-likes; only the first two "
            f"endpoints are meaningful.")
    v = b[i]
    if v is None:
        return default
    return float(v)
```

The check is a length comparison; it doesn't change the parsing
path for legitimate 2-tuples (`test_p3_resolve_bound_2tuple_still_parses_cleanly`
pins this with a vanilla `bounds=[(-1.0, 1.0), (-1.0, 1.0)]`
call that completes cleanly).

### P3-NEW-F1-8 -- `method='lm'` + bounds emits override warning

`lumenairy/optimize/core.py`.

**Before** (silent override):

```python
res = so.least_squares(
    residuals, x0,
    method='lm' if not (bounds is not None) else 'trf',
    bounds=(lb, ub) if bounds is not None else (-np.inf, np.inf),
    max_nfev=max_iter, verbose=1 if verbose else 0)
```

User passes `method='lm', bounds=[...]`; scipy gets
`method='trf'` instead.  No notice.  The v4.16.1 test names
`test_bug4_lm_bounds_*` claim "lm" but actually exercise "trf".

**After**:

```python
if bounds is not None:
    warnings.warn(
        "design_optimize(method='lm', bounds=...): scipy's "
        "least_squares does not accept bounds under method='lm'. "
        "Silently overriding to method='trf' (Trust Region "
        "Reflective), which supports box-constrained least "
        "squares.  Pass method='trf' explicitly to silence this "
        "warning, or drop the ``bounds`` argument to use the "
        "actual Levenberg-Marquardt algorithm.",
        UserWarning, stacklevel=2,
    )
res = so.least_squares(...)
```

The warning fires only when `method='lm'` was explicitly
selected AND `bounds is not None`.  Existing `method='lm'`
no-bounds calls are unaffected.

**Pin choice (audit option a, not b):** the audit offered two
options: (a) add a UserWarning at the override site, OR (b)
rename the v4.16.1 `test_bug4_lm_bounds_*` tests.  I picked (a)
per the prompt; the test file in scope adds an explicit pin
(`test_p3_lm_bounds_emits_override_userwarning`) for the new
warning, and a comment was added near the v4.16.1 Bug 4 tests
documenting the lm->trf override.

## Migration notes for users

* **`MultiWavelengthMerit` with >1 wavelength** -- first call per
  process emits a one-shot `FutureWarning` describing the
  v4.16.1 SUM->AVG transition.  Re-scale your weight calibrations
  by `len(wavelengths)` if they were tuned against the
  pre-v4.16.1 SUM behaviour.  Silence via
  `warnings.filterwarnings('ignore', category=FutureWarning,
  module='lumenairy.optimize.core')`.
* **`Constraint(...)` instantiation** -- no longer runs a probe
  call on your `fun`.  If you relied on the v4.16.1 vector-return
  rejection happening at construction time, call
  `c.validate()` explicitly after construction.  Catch
  exceptions are still swallowed silently (best-effort), matching
  the v4.16.1 behaviour.
* **`Constraint(fun=...)` lambda detection** -- now uses a
  `pickle.dumps` probe.  Closures, `functools.partial(lambda,
  ...)`, and other unpicklable callables that slipped past the
  v4.16.1 `__name__ == '<lambda>'` check now correctly emit the
  pickle-safety `UserWarning`.  Module-level functions (and
  `functools.partial` of a module-level function) pickle cleanly
  and do NOT warn.
* **`design_optimize(method='lm', bounds=...)`** -- now emits a
  `UserWarning` describing the lm->trf override.  Pass
  `method='trf'` explicitly to silence; drop the `bounds`
  argument to use the actual LM algorithm.
* **`design_optimize(method='lm', bounds=[(lb, ub, extra), ...])`** --
  now raises `ValueError` instead of silently dropping the 3rd
  element.  Trim your bound tuples to 2 elements.
