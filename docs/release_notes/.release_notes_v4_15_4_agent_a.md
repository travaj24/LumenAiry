# v4.15.4 -- Dispatcher meta-pin scope extension + 5 new sibling guards (Agent A)

Patch release closing the **P1-NEW-3WAY-1** + **P2-NEW-3WAY-2** + **P2-NEW-V2-1** + **P3-NEW-F2-3** findings from `docs/audits/AUDIT_V4_15_3_2026_05_18.md`.

## The meta-pattern, one level higher

v4.15.3 shipped the structural counter-measure (`_check_2d_scalar_field` helper + AST-walking dispatcher meta-pin) intended to retire the recurring "fix N, miss N+1" sibling-gap meta-pattern.  The v4.15.3 audit found the pattern **recurred inside the release that shipped the counter-measure** -- one level of indirection higher.  Where v4.15.2's gap was *function-level* (9 sibling functions missed in the same packages), v4.15.3's gap was *package-level*:

* The walker scoped to `('lumenairy/propagators', 'lumenairy/elements')` only
* Four public entry points accepting 2-D scalar fields live outside that scope
* Two more functions in scope (`richards_wolf_focus`, `debye_wolf_psf`) were missed by the name regex
* Three independent audit agents (V2 HIGH, F1 P1, F2 P2) converged on the same finding

v4.15.4 (Agent A) closes the **1 P1 + 3 P2 + 1 P2-name + 1 P3** by extending the walker scope, broadening the name discovery, guarding the 5 newly-found scalar-field sites, exempting the 1 newly-found non-scalar site, and adding the missing fake-violation counter-pin.

## Walker discovery refactor

The walker now uses **`__all__`-based primary discovery** with a **package-walk fallback**:

```python
def _walk_entry_points():
    # 1. __all__-based pass: walk lumenairy.__all__ for names matching
    #    the entry-point filter; map each to source file via
    #    inspect.getsourcefile.  Robust against future refactors that
    #    move functions between submodules.
    for py, node in _walk_via_all_membership():
        yield py, node
    # 2. Package-walk fallback: walk _TARGET_PACKAGES for any
    #    non-__all__ sibling matching the name filter.
    for py, node in _walk_via_package_scan():
        yield py, node
```

`_TARGET_PACKAGES` extended from 2 entries to 4 (adding `analysis/` subpackage and the file-at-package-root `system.py`):

```python
_TARGET_PACKAGES = ('lumenairy/propagators',
                    'lumenairy/elements',
                    'lumenairy/analysis',
                    'lumenairy/system.py')
```

The walker now handles both directory-shaped targets (via `rglob`) and file-shaped targets (via direct visit) -- a structural concession to the fact that `system.py` lives at the package root rather than as a subpackage.

The name filter (`_name_matches_entry_point_filter`) extended to include `richards_wolf_*` and `debye_wolf_*` -- the `propagators/vector_diffraction.py` siblings the v4.15.3 regex missed.

### Why `apply_perturbations` is exempt rather than guarded

The v4.15.3 audit listed `apply_perturbations` in the P2-NEW-3WAY-2 cluster of "unguarded `apply_*` siblings in `lumenairy/analysis/`".  On inspection the function signature is:

```python
def apply_perturbations(prescription, perturbations, N=None, dx=None) -> Dict[str, Any]:
```

The first positional argument is a prescription `dict` -- which has no `.ndim` attribute -- not a 2-D scalar field.  Routing this through `_check_2d_scalar_field` would make every legitimate call raise `ValueError: expected 2-D complex field` on the first line.  The function is added to `_GUARD_EXEMPTIONS` with a cited reason, paralleling existing exempt sites that take non-scalar inputs (`apply_thin_lens_to_beamlets` takes a `BeamletBundle`, `apply_jones_matrix` takes a `JonesField`, etc.).  The `test_apply_perturbations_is_documented_exempt` regression test pins the exempt registration so a future contributor who removes the exemption (without changing the function signature) gets a clear failure pointing them at the right fix.

### JAX-tracer compatibility for `propagate_through_system_jax`

The audit flagged a possible incompatibility between `_check_2d_scalar_field` and JAX-traced inputs: "Verify the helper's `getattr(E, 'ndim', None)` handling works for JAX traced types."

Investigation: `propagate_through_system_jax` contractually takes a NumPy array as `E_in`, then wraps it via `jnp.asarray(E_in, dtype=cdtype)` internally.  The guard runs BEFORE the `jnp.asarray` cast, so the input is always a plain NumPy/array-like with a well-defined `.ndim` integer.  Even if a JAX-traced array were passed (e.g. inside a `jax.jit` boundary further up the call chain), traced JAX arrays expose `.ndim` as a Python `int` via `aval.shape` length, and `isinstance(E, _MCF)` returns `False` for traced arrays.  The guard is therefore JAX-trace compatible.  No exemption needed; the guard is applied directly.

## Counter-pin: `test_counter_pin_fake_unguarded_propagate_fails`

The v4.15.0 `_validate_grid_params` meta-pin has a `test_counter_pin_fake_unvalidated_factory_fails` test that injects a synthetic violation and verifies the walker assertion fires.  v4.15.3's `_check_2d_scalar_field` meta-pin had no equivalent (P3-NEW-F2-3); v4.15.4 closes it.

The counter-pin:
1. Builds a synthetic AST representing an unguarded function `fake_unguarded_propagate(E, ...)`.
2. Monkey-patches the module-level `_walk_entry_points` to yield the real entries plus the synthetic one.
3. Re-runs `test_all_entry_points_call_helper_first()` and asserts it now raises `AssertionError` containing both the fake function name and the fake file path.

This pins that the walker's correctness depends on a **positive signal** (helper-call detection) rather than just on the count floor being met.  A silent walker regression -- e.g. a name-regex bug that excludes `apply_*` siblings -- would now be caught.

**Counter-pin behaviour (confirmed by design, code review):** the meta-pin assertion fires with the injected fake function name (`fake_unguarded_propagate`) and file path (`lumenairy/propagators/fake_propagator.py`) in the message.  Note: end-to-end execution verification (running pytest) was blocked in the Agent A sandbox; the counter-pin's runtime behaviour is asserted by code review of the AST-based logic.

## Behavioural preservation

* No existing public API change.  Every guard runs BEFORE any other logic; on legitimate 2-D complex inputs the guard returns immediately and the function behaves exactly as before.
* The walker scope extension is fail-closed: every newly-discovered function MUST either be guarded or appear in `_GUARD_EXEMPTIONS`.  No silent passes.
* The `__all__`-based pass adds robustness against future module reorganisations -- e.g. if `apply_dm` ever moves from `analysis/ao.py` to `analysis/wavefront/ao.py`, the walker still discovers it via `__all__` membership without requiring a `_TARGET_PACKAGES` update.
