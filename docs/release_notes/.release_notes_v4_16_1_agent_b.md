### B.1 -- `propagate_ensemble(...)` helper (audit item 5a / Part 5 P0-1)

New module: `lumenairy/propagators/ensemble.py`.  New top-level
export: `lumenairy.propagate_ensemble`.

Iterates a `(n_realizations, Ny, Nx)` Schell-family ensemble through
any coherent 2-D propagator and returns the partial-coherence
intensity `I_partial = < |E_k|^2 >_k` (the canonical Wolf
coherence-theory result for Schell-model sources -- Goodman,
*Statistical Optics*, Sec 5.5).

Signature::

    propagate_ensemble(
        ensemble: ndarray,             # (n_realizations, Ny, Nx)
        *,
        dx: float,
        wavelength: float,
        propagator: Callable | str = 'asm',
        propagator_kwargs: dict | None = None,
        return_intensity: bool = True,
        return_ensemble: bool = False,
        show_progress: bool = False,
        **kwargs,
    ) -> ndarray | (ndarray, ndarray)

Key design notes:

* **Propagator routing** -- string form looks up the canonical
  propagator (`'asm'` / `'fresnel'` / `'fraunhofer'` / `'rs'` /
  `'sas'`) from `lumenairy.propagators.propagation`.  Callable form
  is invoked as `propagator(E, dx=dx, wavelength=wavelength,
  **kwargs)` per realisation.
* **Memory-efficient by default** -- `return_ensemble=False`
  accumulates `|E_out|^2` into a single `(Ny, Nx)` real array.  The
  full propagated ensemble is only materialised when the caller opts
  in via `return_ensemble=True`.
* **Shape check** -- the helper raises `ValueError` on a 2-D field
  (single realisation) with a pointer at the
  `ensemble[None, ...]` workaround.  Catches the most common usage
  error early.
* **Output-shape pin** -- every realisation must land on the same
  output grid.  A propagator that rescales the grid (e.g. SAS with
  implicit rescale) per realisation raises `ValueError` rather than
  silently averaging mismatched shapes.

Top-level wiring:

* `lumenairy/__init__.py` -- added `propagate_ensemble` to the
  Tier-2 (Propagate) `__all__` block + import line below the
  `propagators.dispatch` block.
* `lumenairy/propagators/__init__.py` -- added to the subpackage
  re-export and `__all__`.

Smoothing factor measured in the new example (256x256 grid, w0 = 50
um, sigma_g = 15 um, n_realizations = 64, z = 10 cm, ASM): **~6.95
(coherent peak / partial-coherence peak)**.  The strong smoothing
matches expectations for sigma_g / w0 = 0.3 (the canonical Wolf-Carter
factor scales as `(1 + (w0/sigma_g)^2)^{-1/2}` for far-field
propagation; the measured ratio is consistent with the partial
intensity spreading across the diffraction limit when each
realisation's phase + amplitude is independently propagated and
averaged).

### B.4 -- `propagate_through_system_jax` JAX-safe dtype probe (item 7)

`lumenairy/system.py::propagate_through_system_jax`:

The dtype probe at lines ~1184-1185 used
`np.iscomplexobj(np.asarray(E_in))` -- this raises
`jax.errors.TracerArrayConversionError` when the function is wrapped
in `jax.jit` or `jax.grad`.  But the function is explicitly named
**`propagate_through_system_jax`** and the docstring touts end-to-end
jit'd caching; users wrapping it in `jax.jit` for autodiff workflows
got the leaked tracer-conversion error instead of a clean
jit'd trace.

Fix: mirror the v4.15.3 `_check_2d_scalar_field` JAX-safe duck-typing
pattern.  Read the dtype via `getattr(E_in, 'dtype', None)` (works
for NumPy arrays, CuPy arrays, JAX arrays, and JAX tracers); when
the dtype is missing or non-complex, fall back to the library
complex default via `_resolve_jax_complex_dtype()`.  Real-input
callers (the common pre-fix path: build a Gaussian envelope as
`np.float64`, let the JAX path autopromote) are unaffected.

### B.5 -- `_transfer_jax` high-NA RuntimeWarning (item 8)

`lumenairy/raytrace/jax_trace.py::_transfer_jax`:

The JAX-path transfer step uses the **paraxial approximation**
`t ~= thickness` (assumes `N = 1`), while the math-correct NumPy
`trace(...)` path uses `t = (thickness - z) / N`.  Per-surface
transverse error scales as `thickness * NA^2 / 2`.

The paraxial approximation is **deliberately retained** -- the
v4.10.0 / v4.10.1 / v4.10.2 / v4.10.3 investigation cycle could not
isolate the NaN-gradient regression that the math-correct form
introduces under `jax.grad(fit_canonical_polynomials_jax)`, even with
full double-where guards.  Re-attempting the math-correct form was
the audit's option (a); v4.16.1 takes option (b) -- preserve the
v4.10.x stability and surface the limitation to high-NA users via
an explicit `RuntimeWarning`.

Implementation:

* New module-level constant `_TRANSFER_JAX_NA_WARN_THRESHOLD = 0.95`
  (default; `min |N| < 0.95` <-> NA > ~0.31).
* New module-level latch `_TRANSFER_JAX_WARNING_EMITTED` so the
  warning fires at most once per Python process -- tight forward-
  loop callers don't see log-spam (the JAX trace cache may invoke
  `_transfer_jax` per-surface per-iteration during a sweep).
* New helper `_maybe_warn_transfer_jax_high_na(direction_n, thickness)`
  reads `np.abs(direction_n).min()`, quantifies the per-surface
  transverse drift `thickness * (1 - min|N|^2) / 2`, and emits the
  `RuntimeWarning` with the drift estimate inline.
* New public helper `_reset_transfer_jax_warning()` clears the latch
  for unit tests and re-arms the warning for users who want to
  surface it again between optimisation sweeps.

**JAX-tracing-time emission approach**: the audit's spec proposed
either (i) `jax.debug.callback`, (ii) JIT-compile-time emission, or
(iii) eager-only `isinstance(state.N, np.ndarray)` check.  The
implementation uses **(iii)** -- eager-only:

* Under `jax.jit` / `jax.grad` / `jax.vmap` the `state.N` leaf is a
  `jax.core.Tracer`, not a `numpy.ndarray`.  The
  `isinstance(direction_n, np.ndarray)` predicate in
  `_maybe_warn_transfer_jax_high_na` returns False for tracers, the
  function returns early, and tracing proceeds cleanly with no
  `ConcretizationTypeError` (the canonical failure mode of
  inspecting tracer values mid-trace).
* In eager mode (a forward `trace_jax(...)` call from a Python REPL
  or notebook) the `state.N` leaf is a NumPy array (the prescription
  builder stores it as such), the warning fires the first time, and
  the latch suppresses subsequent emissions.

The eager-only path is the targeted user-onboarding moment -- the
user typically runs a forward trace first, sees the warning, and
either switches to the NumPy `trace(...)` path or accepts the
paraxial bias for autodiff workflows.  The
`jax.debug.callback` alternative was considered but rejected: it
adds an `_HostCallback` to every traced step and survives the XLA
compile (paying a per-call host-roundtrip cost in tight optimization
loops -- exactly the wrong cost for the targeted low-NA-autodiff
workflow), while providing no incremental value over the eager-mode
check.

### B.6 -- `examples/06_schell_propagation.py` (audit item 5a follow-up)

New runnable example demonstrating the end-to-end Schell workflow:

1. Build a Gaussian-Schell partial-coherence source (256x256 grid,
   w0 = 50 um, sigma_g = 15 um, 64 realisations).
2. Propagate via `propagate_ensemble(..., propagator='asm', z=10cm)`
   to recover the partial-coherence intensity.
3. Run a coherent reference via `Source.gaussian(w0=50um)` +
   `angular_spectrum_propagate` for comparison.
4. Report the smoothing factor
   `I_coh_peak / I_partial_peak`.
5. Demonstrate `return_ensemble=True` for advanced workflows; pin
   that `I_partial == np.mean(|ens_out|^2, axis=0)` to numerical
   precision.

Measured output on the v4.16.1 reference run:

* Input ensemble shape: `(64, 256, 256)`
* Partial-coherence peak intensity (output plane): `5.303e-03`
* Coherent peak intensity: `3.686e-02`
* **Smoothing factor: ~6.95**
* `|I_partial - <|E_out|^2>|` max residual: `0.000e+00` (the
  intensity returned by `propagate_ensemble` equals the manually-
  computed ensemble mean exactly).
