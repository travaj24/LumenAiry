## Why ``propagate_modal_asymptotic`` stays in the shell

``tests/unit/test_audit_fixes_v4_14_1_agent_a.py`` (the v4.15
cold-start invariant pin) does:

```python
from lumenairy.propagators import asymptotic as _asy
monkeypatch.setattr(_asy, '_solve_envelope_stationary_batch', _spy_batch)
_ = propagate_modal_asymptotic(fit, ..., maslov_tracking=tracking)
assert len(batch_calls) >= 1
```

This relies on Python's name resolution: ``propagate_modal_asymptotic``
looks up ``_solve_envelope_stationary_batch`` in its
``__globals__`` (the module it was defined in).  If we move the
function body to ``asymptotic_maslov.py``, its globals become
``asymptotic_maslov``'s globals, and the monkey-patch on the shell
no longer reaches the call site.  The split keeps the function body
in the shell so that the shell-level patch propagates correctly,
while still pushing the supporting batched + Maslov machinery into
``asymptotic_maslov.py`` (where it is consumed via plain imports at
the top of the shell).

## Test-side updates

``tests/unit/test_v4_15_3_dispatcher_pin_2d_scalar_field.py``: added
``_GUARD_EXEMPTIONS`` entries for the new submodule paths of
``propagate_hf_chebyshev_quadrature`` (now in
``asymptotic_canonical_fit.py``), ``propagate_modal_asymptotic_lg00_jax``
(now in ``asymptotic_jax_twin.py``), and ``decompose_lg`` /
``decompose_hg`` (now in ``asymptotic_modes.py``).  The pre-split
``lumenairy/propagators/asymptotic.py`` keys are kept defensively
so an accidental future re-merge stays exempt.

## What did NOT change

* Public API surface (every previously-importable name still
  importable from ``lumenairy.propagators.asymptotic``).
* Top-level ``lumenairy.__all__`` is unchanged -- the parent
  ``__init__.py`` keeps importing from the shell as before.
* Physics: the LG/HG normalisation, Wick-moment recursion, Maslov
  branch-unwrap, canonical fit pipeline, and JAX twin are all
  byte-equal to v5.0.x.
* The module-level caches (``_LG_MODE_STACK_CACHE``,
  ``_HG_MODE_STACK_CACHE``, ``_JAX_IFT_SOLVER_CACHE``) and their
  companion locks remain at the same in-module path and are
  re-exported from the shell -- the v4.14.x cache-lock dispatcher
  pins continue to find them.
* Behaviour of ``aberration_tensor``: still routes to the σ-grid
  path for ℓ ≠ 0 output modes via a lazy ``from .asymptotic import
  propagate_modal_asymptotic`` import (closes the
  asymptotic_aberration_tensor → shell import cycle without moving
  any logic).
