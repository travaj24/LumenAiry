# v4.15.2 -- CLUSTER_B operator-algebra closures (Agent B)

Patch release closing **3 P1s** and **2 P2 items** from
`docs/audits/AUDIT_V4_15_1_2026_05_18.md` -- all in the v4.15.1
CLUSTER_B operator-algebra layer (`lumenairy/algebra/`).

* **P1-NEW-A**: `FourierTransform._apply` ran only 2 stages
  (`ThinLens(f) -> fresnel(f)`), matching the 3-stage ABCD on the
  matrix side but leaving a residual `exp(+i*k/(2f)*r^2)` quadratic
  phase on the output field.  Users composing
  `FourierTransform(f)` with phase-sensitive downstream operators
  got different fields than the literal
  `FreeSpace(f) * ThinLens(f) * FreeSpace(f)` chain.

* **P1-NEW-B**: `from_prescription` flipped `mirror_parity`
  unconditionally on every `is_mirror=True` surface, while
  `raytrace.system_abcd` only flips parity for CURVED mirrors
  (a flat mirror falls into the `R_mat = np.eye(2)` branch with no
  parity flip).  The `<1e-12` ABCD parity pin
  (`test_v4_15_1_agent_g_matches_system_abcd.py`) held only for
  non-folded prescriptions; folded designs with any flat fold
  mirror got an off-sign ABCD from the algebra layer.

* **P1-NEW-C**: `FreeSpace._apply` called `propagate(...)` without
  threading `dy`, so anamorphic chains starting with
  `Magnify(a_x, a_y) * FreeSpace(d)` silently propagated on the
  wrong y-axis grid pitch.  `CylindricalLens` already threaded
  `dy` correctly; only `FreeSpace` had the gap.

* **P2 (Magnify docstring direction)**: the docstring said the
  output extent "scales as `a * (N * dx)`" but the code produces
  `new_dx = dx / a`, i.e. output is SHRUNK by `a` for `a > 1`.
  Docstring rewritten to match the code direction (Nazarathy/
  Shamir `V[a]: (x, y) -> (x/a, y/a)`).

* **P2 (dead `operators.py:556-577` reference)**: the Magnify
  docstring referenced a non-existent external file; removed in
  the docstring rewrite.

## B.1 -- FourierTransform 3-stage rewrite

Before (v4.15.1):

```python
def _apply(self, E, *, dx, dy, wavelength):
    from ..elements.lenses import apply_thin_lens
    from ..propagators.propagation import fresnel_propagate
    E1 = apply_thin_lens(E, f=self.f, wavelength=wavelength, dx=dx, dy=dy)
    E_out, dx_out, dy_out = fresnel_propagate(
        E1, z=self.f, wavelength=wavelength, dx=dx, dy=dy,
    )
    return E_out, float(dx_out), float(dy_out)
```

After (v4.15.2):

```python
def _apply(self, E, *, dx, dy, wavelength):
    fs = FreeSpace(self.f, method=self.method)
    tl = ThinLens(self.f)
    E1, dx1, dy1 = fs._apply(E, dx=dx, dy=dy, wavelength=wavelength)
    E2, dx2, dy2 = tl._apply(E1, dx=dx1, dy=dy1, wavelength=wavelength)
    E3, dx3, dy3 = fs._apply(E2, dx=dx2, dy=dy2, wavelength=wavelength)
    return E3, float(dx3), float(dy3)
```

The 3-stage realisation is the canonical Goodman §5.2 ("Fourier
Transforming Properties of a Thin Lens") geometry: input one
focal length before the lens, output one focal length after.  In
this geometry the output is the pure scaled Fourier transform of
the input with no residual quadratic-phase factor.  The v4.15.1
2-stage shortcut placed the input AT the lens and propagated by
`f` after, which produces the FT magnitude correctly but leaves
the output-plane residual phase that the 3-stage geometry
eliminates.

### Performance impact

The 3-stage path runs **one extra Fresnel-equivalent propagation**
compared to the v4.15.1 2-stage shortcut: roughly 2 FFTs (the two
FreeSpace legs) plus one phase multiply (the ThinLens stage),
versus the v4.15.1 cost of 1 FFT plus one phase multiply.  The
constant-factor cost increase is ~2x for a single
`FourierTransform(f)(src)` call.  For typical optical scales the
two FreeSpace legs auto-select ASM (for `Q < 1` and `N_F > 0.1`),
each costing one forward + one inverse FFT.  In the algebra layer
where users compose multi-stage chains, the relative cost is
absorbed into the larger chain.

Users who want the v4.15.1 "lens then propagate" 2-stage hardware
semantics (with the output-plane quadratic phase still attached)
can compose directly as `ThinLens(f) * FreeSpace(f)`.  This is a
genuine 2-stage chain whose ABCD is `[[1, f], [-1/f, 0]]` (not
`[[0, f], [-1/f, 0]]`) and whose field carries the expected
output-plane quadratic phase.

## B.2 -- from_prescription flat-mirror parity drop

The diff in `from_prescription.py` is small: the `else` branch
(reached when `R` is non-finite, i.e. any flat surface) no longer
toggles `mirror_parity` for flat mirrors.  The curved-mirror
branch (`elif surf.is_mirror and np.isfinite(R)`) is unchanged
and still flips parity correctly.

This exactly mirrors the structure of
`raytrace/core.py::system_abcd` (lines 2275-2291): the curved-
mirror branch flips parity; the flat-mirror case falls into the
generic `R_mat = np.eye(2)` branch with no parity change.

## B.3 -- FreeSpace dy threading

`FreeSpace._apply` now forwards `dy` to the dispatcher's
`**method_kwargs` when `dy != dx`:

```python
kw = {}
if dy is not None and float(dy) != float(dx):
    kw['dy'] = float(dy)
out = propagate(E, z=self.distance, wavelength=wavelength,
                dx=dx, method=self.method, **kw)
```

The conditional forwarding (only when `dy != dx`) is deliberate:
the ASM / Fresnel / Fraunhofer / RS kernels all accept `dy` as a
keyword, but the SAS kernel (`scalable_angular_spectrum_propagate`)
is a square-grid kernel that does not accept `dy`.  Forwarding
only when `dy` differs from `dx` means the common isotropic case
continues to work with any auto-selected method, including SAS,
while anamorphic chains properly thread `dy` to the (ASM /
Fresnel / Fraunhofer / RS) kernels that handle it.

`ThinLens._apply` was already correct -- it explicitly passes
`dy=dy` to `apply_thin_lens`, and `apply_thin_lens` builds the
quadratic phase from the per-axis grids.  Verified by the
regression test `test_thinlens_apply_threads_dy` in the new agent-B
test file.

## B.4 -- Magnify docstring direction

The v4.15.1 docstring stated "physical extent scales as
`a * (N * dx)`", which is the inverse of the actual code (the
code produces `new_dx = dx / a`, i.e. output extent `N*dx/a`).
The v4.15.2 docstring rewrite makes the direction explicit:

- For `a > 1`: output is **shrunk by `a`** (demagnifier in
  optical-system terms).  Pitch `dx/a` (finer); extent `N*dx/a`
  (smaller).
- For `0 < a < 1`: output is **magnified by `1/a`**.  Pitch
  `dx/a` (coarser); extent `N*dx/a` (larger).

The amplitude prefactor `sqrt(a_x * a_y)` preserves energy:
`|E_out|^2 * dx_out * dy_out == |E_in|^2 * dx_in * dy_in`.  The
ABCD `diag(1/a, a)` is unchanged from v4.15.1 -- the math was
self-consistent; only the docstring's direction-of-action claim
was inverted.

## B.5 -- Dead operators.py:556-577 reference removed

The v4.15.1 Magnify docstring referenced an external file
`operators.py:556-577` from the lens-designer source repo, which
isn't part of the LumenAiry codebase.  The reference is removed
in the v4.15.2 docstring rewrite.

## Backward compatibility

* **Field-level**: callers of `FourierTransform(f)(src)` see a
  different output field on phase-sensitive computations (the
  v4.15.2 output no longer carries the residual
  `exp(+i*k/(2f)*r^2)` quadratic phase).  The change brings the
  field into agreement with the operator's already-correct ABCD,
  so users composing `FourierTransform(f)` with downstream
  operators get more correct results.  Output **grid pitch** also
  changes for the same call: the v4.15.1 path returned the
  Fresnel-FT natural pitch `lambda*f/(N*dx_in)`; the v4.15.2
  3-stage path returns whatever pitch the auto-selected propagator
  gives the two `FreeSpace(f)` legs (typically the input pitch
  for ASM, or the Fresnel pitch if the dispatcher routes to
  Fresnel).  This is the price of fixing the field-vs-ABCD
  inconsistency; the audit-recommended "rename to
  `BackFocalPlaneFT`" alternative was rejected in favour of the
  rewrite per the user's confirmed option (a) in the dispatch
  brief.

* **ABCD-level**: no change.  `FourierTransform(f).abcd` is
  `[[0, f], [-1/f, 0]]` in both v4.15.1 and v4.15.2 (this was
  already correct in v4.15.1).

* **from_prescription**: callers of `from_prescription` on
  prescriptions with flat fold mirrors now get the same ABCD as
  `system_abcd` (to within 1e-12).  Non-folded prescriptions
  (singlet, doublet, telephoto, close-pair, flat-window) get the
  same ABCD as before; only folded prescriptions with at least
  one flat mirror change behaviour.

* **FreeSpace**: anamorphic chains (`dy != dx`) now propagate
  with the correct y-axis grid pitch.  Isotropic chains (`dy ==
  dx`, including the default Source path where `dy` is `None` or
  set equal to `dx`) are byte-identical to v4.15.1.

* **Magnify**: docstring-only change.  No code-path change; the
  v4.15.1 math was correct.
