# v4.16.3 Agent A release notes

**Scope:** V11 walker hardening + extension (audit `AUDIT_V4_16_2_2026_05_20.md`).

The v4.16.2 audit identified that V11 -- the very walker designed to retire the documentation-surface sibling-gap meta-pattern -- contained exactly that pattern itself.  Agent A's scope retires V11's own internal structural issues and extends V11 to cover the CHANGELOG <-> Migration-Guide drift surface.

## P1 closure

### P1-NEW-F1-2 -- V11 walker pyproject regex mis-parses nested brackets

`tests/unit/test_v4_16_2_dispatcher_pin_doc_consistency.py`: replaced the non-greedy regex parser (`r'^([a-zA-Z_]...)\s*=\s*\[(.*?)\]'`) with `tomllib` (Python 3.11+) and falls back to `tomli` on 3.9/3.10 per the library's `requires-python = ">=3.9"`.  Tomli is not a hard dev dep; if neither is importable the walker `pytest.skip`s with a clear "install tomli" message.

The v4.16.2 regex silently mis-parsed two canonical pyproject.toml patterns:

* `jax-gpu = ["jax[cuda12]>=0.4.20"]` -- the extras qualifier's `]` terminated the capture early; the group either dropped or held a malformed `"jax[cuda12` string.
* `all = [..., # ...lumenairy[all]..., "refractiveindex>=1.0"]` -- the comment's `lumenairy[all]` bracket terminated the capture before subsequent entries were reached.

Both failure modes are exercised by synthetic-pyproject regression tests in `tests/unit/test_v4_16_3_agent_a.py`; the live pyproject.toml is also pinned through both code paths.

## P2 closures (2)

### P2-NEW-F2-MED-1 -- V11 hardcoded breaking-version list -> CHANGELOG-driven

`tests/unit/test_v4_16_2_dispatcher_pin_doc_consistency.py`: replaced the hardcoded tuple `('4.13.0', '4.15.1', '4.16.1', '4.16.2')` (which would silently pass when v4.17.0+ shipped a breaking change) with a `_versions_with_breaking_changes_from_changelog` helper that scans CHANGELOG.md per `## [X.Y.Z]` block.

Heuristic precision/recall calibration (the bare `breaking` / `DeprecationWarning` / `FutureWarning` markers from the audit pseudo-code were too noisy; many release blocks incidentally mention prior versions' deprecation cycles):

* High-precision body markers: `silent semantics change`, `silent behavior change`, `silent behaviour change`, `SUM->AVG`, `SUM -> AVG`.
* Plus: per-release-block `### Breaking changes` heading NOT annotated `-- none` / `-- none` (em-dash variant).
* Restricted to versions >= 4.13.0 (Migration-Guide starts there).

A documented `_MIGRATION_GUIDE_SIBLING_COVERED = frozenset({'4.15.2'})` allowlist tracks versions whose migration is bundled under a sibling version's Migration-Guide entry (v4.15.2 is documented under v4.15.1's section).  The allowlist itself is a sibling-gap surface; the regression test `test_sibling_covered_allowlist_minimal` pins it to a known baseline.

### P2-NEW-F2-MED-2 -- CHANGELOG <-> Migration-Guide drift coverage

New test `test_migration_guide_sections_are_non_trivial` asserts each `## X.Y.Z` Migration-Guide section contains >= 200 chars of non-whitespace content between its heading and the next.  A future stub-only section (heading without recipe) now fails V11.

Plus: `test_migration_guide_has_known_version_sections` extended -- previously asserted only that the four hardcoded versions had sections; now asserts that EVERY CHANGELOG-flagged breaking version has either a Migration-Guide section or is in the documented sibling-covered allowlist.

## Sibling-gap discipline findings (audit Part 3 lesson)

The audit warns: "the walker designed to retire a meta-pattern often contains the pattern itself".  Sweep for other regex-based pyproject parsing in the repository:

* `tests/unit/test_v4_16_1_agent_d.py:151` (`_extract_extras_block`) -- ALSO does manual pyproject parsing, but already grapples with the nested-bracket case (line-by-line bracket-counting + single-line fast path).  Not perfect but handles the canonical patterns.  Out of scope for v4.16.3 Agent A (it lives in a different agent's audit closure); flagged here as a candidate for v4.17.0+ unification with the V11 tomllib helper.
* No other tests parse pyproject.toml via regex.

Two new sibling-gap pin tests (`test_v11_walker_does_not_use_nongreedy_pyproject_regex` + `test_v11_walker_does_not_hardcode_breaking_version_tuple`) explicitly fail if a future maintainer re-introduces either of the v4.16.2 anti-patterns into V11's own source.
