# v4.16.0 -- Agent A release notes

Agent A scope (per dispatch): land the four remaining V4 meta-pin
candidates that the AUDIT_V4_14_2 Part 3.5 onward report identified
as standing recommendations.  Each is implemented as an AST-based
walker test with a documented exemption frozenset and a
counter-pin that injects a synthetic violation to verify the
walker's positive signal.

## Headline

* 4 NEW AST walker pins, each modeled on the v4.15.4 / v4.15.5
  V6 walker pattern (lru_cache file-to-AST helper, exemption
  frozenset with cited rationale, counter-pin via monkeypatch
  injection).
* 30 NEW unit tests across the four walker files (8 sentinel +
  6 dy-threading + 10 xp-dispatch + 6 __all__-symmetry).
* 4 inline xp-dispatch fixes in `lumenairy/elements/elements.py`
  (the highest-traffic public-API patterns flagged by the
  xp-dispatch walker on first landing).
* 2 inline __all__-symmetry fixes in `lumenairy/__init__.py`
  and `lumenairy/optimize/__init__.py` (re-exporting the
  backend-array-namespace helpers and the pymoo availability
  flag).
* 1 inline xp-dispatch fix in the shared `zernike` helper to
  match the xp-dispatched caller.

All 30 walker tests pass; counter-pin behaviour verified for each
walker.  34/34 validation passes.

## Walker A.1 -- sentinel-aware branch propagation

`_ZERO_APERTURE_MASK` callsite walker.  The audit recommendation
(v4.14.2 Part 3.5) is to STRUCTURALLY pin the v4.14.1 P1-NEW-1
fix: every `_get_wrapper_merit_cache(...)` caller must branch on
`mask is _ZERO_APERTURE_MASK` within the same function body.

Discovered callsites (3, all under `lumenairy/optimize/core.py`):

* `MultiWavelengthMerit.evaluate` (line ~2417) -- GUARDED at
  line ~2431.
* `MultiFieldMerit.evaluate` (line ~2571) -- GUARDED at
  line ~2604.
* `ToleranceAwareMerit.evaluate` (line ~2936) -- GUARDED at
  line ~2938.

Exempt: 0
Deferred: 0
Inline fixes shipped: 0 (all three callsites already carry the
sentinel branch per the v4.14.1 / v4.14.2 audit closure; the
walker pins the invariant going forward).

Counter-pin: `test_counter_pin_fake_missing_sentinel_branch_fails`
injects a synthetic caller without the sentinel branch and
asserts the main pin's assertion fires; the sibling
`test_counter_pin_fake_with_sentinel_branch_does_not_trip`
verifies the positive signal.

## Walker A.2 -- cross-backend `_xp_of` dispatch

V6 first-positional-name walker (E / E_in / field / pupil /
object_field / psf) plus a body-level scan for an
`xp = _xp_of(...)` lookup.  Functions opted-into dispatch are
checked for backend-breaking `np.*` calls:

* Discovered candidates: 94 field-domain top-level functions
  across `elements/`, `analysis/`, `propagators/`.
* Guarded (clean dispatch OR documented exempt): all candidates
  post-fix (the walker's main pin passes; any `no-dispatch`
  diagnostic entries are flagged via the SEPARATE
  ``test_diagnostic_field_functions_without_dispatch`` listing,
  not via the main assertion).
* Inline-fixed (this release): 4 + 1 helper -- see below.
* Deferred to v4.16.x: 0 (the discovered violations were
  fixable inline; the walker's deferral set is currently
  empty).

### Inline fixes (5 functions, `lumenairy/elements/elements.py`)

1. `apply_zernike_aberration` -- coordinate grid +
   phase accumulator now routed via `xp = _xp_of(E_in)`; per-pixel
   Zernike polynomial summation lives on the dispatched backend so
   CuPy / JAX inputs stay on their backend through the whole
   ``apply`` call.
2. `apply_lyot_focal_plane_mask` -- coordinate grid + mask
   transmission tensor routed via `xp = _xp_of(E_in)`; the three
   profile branches (hard / gaussian / sin2) all use the
   dispatched namespace.
3. `apply_vortex_phase_mask` -- coordinate grid + arctan2 +
   centre-pixel mask routed via `xp = _xp_of(E_in)`.
4. `apply_apodized_pupil` -- coordinate grid + transmission
   tensor + per-profile branches (cos2 / cos_power / gaussian /
   sonine) all routed via `xp = _xp_of(E_in)`.
5. `zernike` helper (called from `apply_zernike_aberration` and
   other Zernike-machinery callers) -- coordinate-array work
   routed via `xp = _xp_of(rho)`.  Scalar `np.sqrt(n+1)`
   normalisation factor left as host scalar (legitimately
   NumPy-side because the argument is a Python int).

All five fixes preserve bit-for-bit NumPy behaviour (verified via
the existing `test_elements_lens.py` suite, 17/17 PASS).

### Walker exemption registry

`_KNOWN_XP_DISPATCH_EXEMPTIONS` documents 56 legitimate non-
dispatch sites with cited rationale per entry.  Highlights:

* `apply_mirror`, `apply_aperture`, `apply_gaussian_aperture` --
  already xp-dispatched; the lingering `np.inf` / `np.pi` /
  `np.isinf` references are scalar constants / branch decisions
  (NOT array constructors).
* `apply_thin_lens` / `apply_real_lens` and the wider lens
  family -- mixed dispatch for the legacy numba-accelerated
  `_surface_sag_general` NumPy path (preserved for speed).
* `polarization.*` family -- consumes `JonesField`, which is
  intentionally NumPy-only for the v4.15.5 scope.
* `analysis/*` analyzers -- post-processing surface; dispatch
  is at the caller's discretion (already to_numpy'd by the
  caller in typical pipelines).
* `init_paths_stratified` -- xp-dispatched for the field-side
  work; the 4-D stratification index mesh uses `np.indices`
  intentionally (small host-side integer mesh; serialising to
  device would be slower than the build itself).
* `sparrow_resolution` / `fwhm_resolution` /
  `rayleigh_resolution` -- xp-dispatch probe but body uses
  scipy CubicSpline / brentq, both NumPy-host-only.

### Counter-pins

* `test_counter_pin_fake_hardcoded_np_fails`: injects a synthetic
  function with `xp = _xp_of(E)` followed by `np.zeros(...)` and
  asserts the main pin fires.
* `test_counter_pin_fake_dispatched_clean_does_not_trip`:
  positive-signal counter-pin verifying clean dispatched
  functions pass through unflagged.
* `test_apply_zernike_aberration_uses_xp_dispatch` (and three
  siblings): direct name-anchored regression pins on each
  inline-fixed function.

## Walker A.3 -- `dy` parameter threading

Walks `lumenairy.__all__` for every `apply_*` name and verifies
the function signature carries a `dy` parameter.

* Discovered apply_* entries: 36.
* Already threading dy: 26.
* Exempt (10 entries listed in `_KNOWN_DY_THREADING_EXEMPTIONS`):
  * `apply_perturbations` (prescription dict input)
  * `apply_mask` (pure elementwise multiply)
  * `apply_globals` (settings-snapshot dict)
  * `apply_jones_matrix` / `apply_polarizer` / `apply_waveplate`
    / `apply_half_wave_plate` / `apply_quarter_wave_plate` /
    `apply_rotator` (JonesField input carries dx/dy)
  * `apply_thin_lens_to_beamlets` /
    `apply_abcd_to_beamlets` / `apply_aperture_diffraction` /
    `apply_vector_aperture_diffraction` /
    `apply_doe_phase_traced` (bundle inputs, no pixel raster)
  * `apply_detector` (square-only contract for v4.16.0)
  * `apply_dm` (DM geometry intrinsically square via mirror
    actuator pitch)

Inline-fixes shipped: 0 (the 26 + 10 = 36 sites partition the
walker's discovered surface bit-for-bit; every apply_* either
already threads `dy` from a prior audit cycle or is in the
documented exemption set).
Deferred: 0.

### Counter-pins

* `test_counter_pin_fake_missing_dy_threading_fails`: synthetic
  `apply_fake_missing_dy(E, dx, wavelength)` without `dy` --
  walker fires.
* `test_counter_pin_fake_apply_with_dy_does_not_trip`: synthetic
  `apply_fake_with_dy(E, dx, wavelength, dy=None)` -- walker
  passes.
* Cross-check: `test_ast_dy_matches_inspect_signature`
  reconciles AST-discovered `dy` with `inspect.signature`'s
  view -- catches a future decorator that strips kwargs.

## Walker A.4 -- `__all__` symmetry

Walks every submodule's `__all__` and asserts every name is
either re-exported at top-level `lumenairy.__all__` or appears
in `_KNOWN_ALL_SYMMETRY_EXEMPTIONS` with a cited rationale.

* Submodule `__all__` entries discovered: 752.
* Re-exported at top level: 717.
* Documented exempt (35 entries -- all
  `lumenairy.backend.*`-namespaced helpers, `from_prescription`
  classmethod, `BundleProtocol` typing alias, JAX-only raytrace
  helpers).
* Inline-fixed (added to top-level `__all__` this release):
  9 names -- see below.

### Inline fixes

1. `lumenairy/__init__.py` top-level `__all__`: added the 8
   backend-dispatch helpers that were imported but missing from
   `__all__` since v3.4.0 --
   `array_namespace`, `is_numpy_array`, `is_cupy_array`,
   `is_jax_array`, `backend_name`, `to_numpy`, `to_backend`,
   `RandomState`.  Each is a high-traffic public-API helper for
   user code; `from lumenairy import *` will now include them.
2. `lumenairy/optimize/__init__.py`: added `PYMOO_AVAILABLE` to
   the multi_objective re-export block and to the package
   `__all__`.
3. `lumenairy/__init__.py` top-level `__all__`: added
   `PYMOO_AVAILABLE` (sibling to `CUPY_AVAILABLE` /
   `JAX_AVAILABLE` / `NUMEXPR_AVAILABLE` /
   `PYFFTW_AVAILABLE`).

### Counter-pins

* `test_counter_pin_fake_missing_reexport_fails`: synthetic
  `(submod, name)` pair where the name is NOT in top-level
  `__all__` -- walker fires.
* `test_counter_pin_fake_with_reexport_does_not_trip`:
  positive-signal counter-pin using `apply_real_lens` (a known
  re-exported name) -- walker does NOT flag it.
* Cross-check: `test_all_top_level_attrs_are_resolvable`
  reverse-direction check that every name in
  `lumenairy.__all__` resolves via `hasattr(la, name)` --
  catches a name listed in `__all__` but missing from the
  import chain (the v4.14.0 P1-NEW-4 failure mode).
