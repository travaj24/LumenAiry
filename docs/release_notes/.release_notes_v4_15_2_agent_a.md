## A.1 — P0-NEW-1: Schell silent contract break

The v4.15.0 → v4.15.1 transition changed the default return shape of
`create_gaussian_schell_source`, `create_schell_model_source`, and
`create_annular_incoherent_source` from `(E_2d, x, y)` (3-tuple of a
collapsed 2-D field + 1-D coordinate vectors) to
`(ensemble_3d, dx, dy, wavelength)` (4-tuple of a 3-D ensemble +
scalar pitches + wavelength).  v4.15.1 shipped this change WITHOUT
emitting a `DeprecationWarning` on the default path, so pre-v4.15.0
callers doing `E, x, y = create_gaussian_schell_source(...)` would
silently bind `E.ndim == 3` and `x` to the scalar `dx` — a wrong-
shape physics bug that propagates downstream through broadcasting
until something diverges from physical reality.

**Fix:**

- Added a per-module sentinel `_RETURN_KIND_UNSET` (a
  `_deprecation._Sentinel` instance) and a helper
  `_warn_schell_return_kind_default(fn_name)` near the top of the
  Schell block in `lumenairy/sources/core.py`.
- Changed each of the 3 factories' `return_kind` parameter default
  from `return_kind: str = 'ensemble'` to
  `return_kind: Any = _RETURN_KIND_UNSET`.  When the caller leaves
  the kwarg unset, the factory body sees the sentinel and dispatches
  the deprecation helper before falling through to
  `return_kind = 'ensemble'`.
- Explicit `return_kind='ensemble'` and `return_kind='mcf'` calls
  are silent — that's the user's escape hatch once they acknowledge
  the v4.15.1 contract.
- The `DeprecationWarning` is routed through the existing
  `_deprecation.warn_deprecated_signature` helper (NOT raw
  `warnings.warn`) so the message format is consistent with the
  library's other deprecations and silenceable via a single
  `warnings.filterwarnings` incantation.  The message references
  both `v4.15.0` and `v4.15.1` (so users can grep for either change
  horizon) and documents `version_removed='5.0'`.

## A.2 — P1-NEW-G: CHANGELOG `### Breaking changes` subhead

Added a `### Breaking changes` subhead at the top of the v4.15.1
entry (right after the lead paragraph, before `### P0 closures`),
listing the 3 confirmed breaking items the audit flagged:

1. **Schell-family return shape** — the 3 Schell factories' default
   contract (the same change Agent A's P0 closure addresses with a
   one-release `DeprecationWarning`).
2. **`strehl_vector` default reference removed** — caller must now
   pass `reference=` explicitly; the buggy v4.15.0 default produced
   unity Strehl for any uniform field of equal power AND Strehl > 1
   on focused PSFs.
3. **`system.evaluate` mixed-shape prescription raises `ValueError`** —
   callers handing raw Zemax-loader output need to filter the
   surfaces keys, with the recommended pattern documented inline:
   `{k:v for k,v in rx.items() if k not in ('surfaces','thicknesses')}`.

## A.3 — P2: `energy_threshold` kwarg forwarding

The v4.15.1 audit's V4 finding noted that `energy_threshold` is
exposed on `PartialCoherenceMCF.from_ensemble` but NOT forwarded
through the 3 factory entry points.  Callers wanting a tighter or
looser modal-storage truncation threshold had to invoke
`from_ensemble` manually after the factory call, defeating the
factory's purpose.

**Fix:**

- Added `energy_threshold: float = 0.99` to each of the 3 factories'
  signatures.
- Forwarded the kwarg to `PartialCoherenceMCF.from_ensemble(...)` on
  the `return_kind='mcf'` path.
- On the `return_kind='ensemble'` path the kwarg is a no-op (no
  modal truncation occurs); accepted for signature symmetry and
  documented as such.

## Sentinel approach: why a `_deprecation._Sentinel` subclass?

The audit's `Tier 0 v4.15.2 recommendation` text describes detecting
the default-`return_kind` call via a sentinel.  We chose to subclass
the existing `_deprecation._Sentinel` so the sentinel inherits the
v4.15.1 pickle-safe `__reduce__` + `_SENTINEL_REGISTRY` machinery.
This matches the pattern already in use in the codebase
(`_ZeroApertureMaskSentinel`, `_AngleUnsetSentinel`,
`_NO_DEFAULT`) and means the sentinel round-trips cleanly through
joblib / distributed merit evaluation if the factory is ever called
inside a multiprocessing worker.
