## B.1 -- Source.* size-arg normalisation (ROADMAP v4.15 #2)

The 5 `Source.method` classmethod factories had inconsistent positional
order in v4.14.x:

| Factory | Pre-v4.15 positional order | v4.15 canonical |
|---|---|---|
| `Source.gaussian` | `(w0, N, dx, wavelength)` -- size first | `(*, N, dx, wavelength, w0)` |
| `Source.plane_wave` | `(N, dx, wavelength)` | `(*, N, dx, wavelength)` |
| `Source.point_source` | `(N, dx, wavelength)` | `(*, N, dx, wavelength)` |
| `Source.top_hat` | `(diameter, N, dx, wavelength)` -- size first | `(*, N, dx, wavelength, diameter)` |
| `Source.fiber_mode` | `(mode_field_diameter, N, dx, wavelength)` -- size first | `(*, N, dx, wavelength, mode_field_diameter)` |

v4.15 picks the canonical order `Source.method(*, N, dx, wavelength,
<size_kwargs>)` (kwarg-only with the `*` separator).  The legacy
positional form is still accepted for one release with a
`DeprecationWarning` routed through
`_deprecation.warn_deprecated_signature` (NEW helper) with
`version_removed='5.0'`.

Mechanics: each factory is now `def factory(cls, *args, <kwarg_only_table>,
**factory_kwargs)`.  When `*args` is non-empty the shim:

1. Emits the DeprecationWarning via `warn_deprecated_signature`.
2. Maps the positional surplus onto the canonical kwarg slots.
3. Detects overlap between the positional-mapping and an explicit kwarg
   of the same name (raises `TypeError`).
4. Otherwise proceeds with the canonical body.

The existing `TestP1CSourceFactoryDispatcherPin` test (which already
used the kwarg-only `factory(N=N, dx=dx, wavelength=wavelength,
dy=dy, **extra_kwargs)` form) continues to pass without modification --
confirms that the kwarg-only canonical form is fully accepted.

## B.2 -- `lumenairy.system.evaluate` (ROADMAP v4.15 #3)

New ergonomic one-call entry: `lumenairy.system.evaluate(prescription,
source, *, output_grid=None, output_dx=None, method='asm', use_gpu=False,
verbose=False, progress=None)`.

Routing pipeline:

1. Decompose the prescription dict into a
   `propagate_through_system`-compatible element list.  Two
   prescription shapes accepted:
   - Zemax-loader shape (`elements` + `all_thicknesses` keys) ->
     routed through `io.codegen._decompose_prescription` (the same
     helper `generate_simulation_script` already uses).
   - Factory shape (`surfaces` + `thicknesses` keys, what
     `make_singlet`/`make_doublet`/etc. return) -> wrapped as a single
     `{'type': 'real_lens', ...}` element.
2. Pull `E`, `dx`, `dy`, `wavelength` off the `Source` instance.  No
   `source.to_source()` is needed -- the dataclass already bundles
   everything.
3. Call `propagate_through_system(..., return_result=True)`.

Exposed as `lumenairy.system.evaluate` (canonical), `lumenairy.evaluate`
(top-level convenience), and added to `__all__`.  Cross-reference: the
existing `propagate_through_system` takes an element-list, not a
prescription dict.  Users loading a `.zmx` file had to build the
element list manually pre-v4.15; `evaluate` closes that gap.

`output_grid` / `output_dx` are reserved kwargs for future resampling
work.  v4.15 accepts them but emits a `RuntimeWarning` if they
mismatch the source grid and would otherwise force a resample.

## B.3 -- Schell-model + Gaussian-Schell sources (ROADMAP v4.16 #9)

Two new top-level factories in `lumenairy/sources/core.py`:

- `create_gaussian_schell_source(*, N, dx, wavelength, w0, sigma_g,
  n_realizations=16, dy=None, seed=None, dtype=None)`.  Returns the
  ensemble-averaged amplitude envelope of `n_realizations` independent
  random-phase Gaussian beams with Gaussian intensity profile (1/e^2
  radius `w0`) and Gaussian coherence kernel of width `sigma_g`.
- `create_schell_model_source(*, N, dx, wavelength, intensity_profile,
  coherence_length, n_realizations=16, dy=None, seed=None, dtype=None)`.
  Generic Schell-model variant where the caller supplies the intensity
  profile directly.

Matching `Source` classmethods: `Source.gaussian_schell(...)` and
`Source.schell_model(...)`.

Implementation: random-phase ensemble.  Each realization multiplies the
deterministic amplitude `sqrt(I_target)` by a unit-modulus random phase
whose spatial correlation is set by the coherence-length kernel applied
in Fourier space.  The returned `E` is
`sqrt(<|E_realization|**2>) * exp(i <arg(E_realization)>)` so the
caller gets a complex field with the correct ensemble-averaged
intensity envelope and a well-defined coherent-mean phase for
type-uniformity.

Both factories call `_validate_grid_params(N, dx, wavelength, dy=dy,
fn_name=...)` in their first 10 lines (per the v4.14.2 audit's
input-validation entry-point meta-pin candidate).

## B.4 -- Ring / annular incoherent source (ROADMAP v4.16 #11)

`create_annular_incoherent_source(*, N, dx, wavelength, inner_radius,
outer_radius, n_realizations=16, dy=None, seed=None, dtype=None)`.

Distinct from the existing `create_annular_beam` (which is
monochromatic-coherent).  Builds an ensemble of `n_realizations`
random-phase realizations of an annular indicator function and returns
the amplitude envelope of the ensemble-averaged intensity.  The
underlying use case is partial-coherence integration where the source
has finite extent and the realizations sweep the source-plane phase
distribution.

Also calls `_validate_grid_params` in its first 10 lines.

## B.5 -- Three P2 carryover items (from v4.14.2 audit Part 2)

### B.5.a -- P2-VAL-1: `_validate_grid_params` bool rejection

Pre-v4.15: `isinstance(True, (int, np.integer))` returns True, so
`N=True` silently produced a 1x1 grid and `N=False` hit the
`int(N) <= 0` guard with a confusing "N=0" error.

v4.15: explicit `isinstance(N, bool)` short-circuit raises
`TypeError` with a message that points at the common bug source
(`N=flag and grid_size` -> `N=False` when flag is truthy).  Applied
to both scalar-N and tuple-N entry points so a bool-in-tuple (e.g.
`(True, 32)`) is also rejected.

### B.5.b -- P2-FAC-1: factory-validation dispatcher pin expansion

The existing v4.13.0 `TestP1CSourceFactoryDispatcherPin` covered exactly
5 Source classmethod factories.  v4.14.2 audit P2-FAC-1 flagged that:

- `create_multi_field_sources` was only transitively validated via
  `create_tilted_plane_wave` -- and the internal-name leak in the
  error message had been silently masked by that.

v4.15 adds:

- `create_multi_field_sources` to the dispatcher-pin parametrize list.
- The 4 new factories (`create_gaussian_schell_source`,
  `create_schell_model_source`, `create_annular_incoherent_source`,
  plus the size-arg-normalised 5 above for the classmethod pin).

The `TestP2FacFactoryValidationMetaPin` class in
`test_v4_15_agent_b.py` carries the expanded pin.  The original
`TestP1CSourceFactoryDispatcherPin` test continues to pass without
modification (confirmed against the live module: 5/5 still PASS).

### B.5.c -- P2-DEP-1: `_deprecation.py` migration of two inline shims

Migrated two inline `warnings.warn(... DeprecationWarning, ...)` sites
to route through `_deprecation.warn_deprecated_signature` (a new helper
added in this release):

- `lumenairy/sources/core.py::create_led_source` -- legacy
  positional-form shim (`(N, dx, diameter, divergence_angle, wavelength,
  ...)`).  The new message text includes `version_removed='5.0'`.
- `lumenairy/elements/doe.py::makedammann2d` -- legacy
  micrometre-units shim (auto-detect heuristic).  The new message
  text includes `version_removed='5.0'`.

The shared helper guarantees a consistent message format across the
library and makes future API tightening (e.g. raising the warning to
an error at v5.0) a one-line change.

The new `_deprecation.warn_deprecated_signature(*, function,
old_signature, new_signature, version_added, version_removed,
stacklevel)` helper is added to the module's `__all__`.

## Judgment calls

- **`Source.gaussian` signature shape**: chose `def gaussian(cls,
  *args, **kwargs)` with explicit `*args` collector rather than PEP
  570 positional-only `/`.  Rationale: the task spec explicitly asked
  for the canonical form `Source.method(*, N, dx, wavelength,
  <size_kwargs>)`, and the `*args` collector is what lets the
  back-compat shim detect legacy callers; PEP 570 `/` would force
  every existing kwarg-based caller to drop `N/dx/wavelength` out of
  kwargs.  This mirrors the precedent set by v4.14.3's
  `create_led_source` shim design.

- **`Source.gaussian_schell` + `Source.schell_model` placement**:
  added next to the 5 existing classmethod factories so they share
  the docstring umbrella ("Factories that wrap the existing create_X
  functions") and the `cls(...)` dy-thread-through pattern.  The
  factory-validation pin parametrize entries are kept on the
  top-level free function variants (`create_*` form) rather than
  duplicating onto the classmethods because the underlying
  implementations are shared.

- **`evaluate` prescription shape acceptance**: accepted both the
  Zemax-loader shape (`elements` + `all_thicknesses`) and the
  factory shape (`surfaces` + `thicknesses`) so the function is a
  Tier-1 entry that works with both the load-from-file workflow and
  the make_singlet/make_doublet workflow.  The Zemax shape routes
  through `_decompose_prescription`; the factory shape wraps as a
  single `real_lens` element.  Future versions can add propagation
  gap inference (currently the caller threads those gaps via
  successive `propagate_through_system` calls or via a richer
  prescription).

- **`evaluate` `output_grid` / `output_dx` deferred**: accepted the
  kwargs but did not implement the resample.  Rationale: the task
  spec called out the kwargs as part of the signature but didn't
  pin the behaviour, and `Source.propagate` already supports
  `output_dx`-driven resampling via `propagate_through_system`'s
  Fresnel/SAS paths.  The kwarg is wired up so callers can
  future-proof their code; a soft `RuntimeWarning` fires if the
  caller asks for a resample that the v4.15 implementation can't
  honour.

- **`makedammann2d` shim narrowness**: edited only the
  `warnings.warn(...)` call site, not the rest of the function.
  The other inline `warnings.warn(... RuntimeWarning, ...)` sites in
  the same module are not shim-style deprecations -- they are
  runtime sampling warnings -- so they stay as-is per the
  "narrow edit" task constraint.

- **`_deprecation.py` `warn_deprecated_signature` API**: the existing
  helpers (`warn_deprecated_kwarg`, `warn_deprecated_alias`,
  `warn_deprecated_default`) all handle a specific deprecation
  pattern.  Signature-shape deprecation (legacy positional form
  re-routed via `*args`) is a new pattern, distinct enough to deserve
  its own helper.  Took the `old_signature` / `new_signature` strings
  as explicit kwargs rather than inferring them so the call site
  documents the migration directly.
