# Lumenairy v4.14.0 — Audit Report

**Date:** 2026-05-17
**Library state:** v4.14.0 tagged in git AND published on PyPI (also: v4.13.2 on PyPI).
**Scope:** Two-part audit covering both v4.13.2 (Tier-0 closure of `AUDIT_V4_13_1_2026_05_17.md`) and v4.14.0 (Tier-1 Phase B: 7 perf wins, 6 new public API functions, 80 parametrized dispatcher pins, 3 newly-discovered complex64 sibling-gap fixes).

**Methodology:** 8 parallel single-domain audit agents:
- **V1-V5** (verification): 12 P1 closures, 7 perf wins, new API + 80 dispatcher pins + 3 dtype fixes, PyPI artifact, v4.13.2 cross-survey + thin-lens sweep
- **F1-F3** (forward-looking): new-code bug hunt, cross-cutting cache hygiene + integration, modal asymptotic "wrong-saddle-basin" physics finding deep-dive

---

## TL;DR

**v4.13.2 + v4.14.0 deliver a substantial release** — 12 P1 closures from the prior audit, 7 perf wins (most notably 24.6× coating wavelength batch, 77× LG/HG mode-stack cache warm, 6.17×/4.16×/3.17× meshgrid cache for Multi*Merit), 6 new public API functions (encircled-energy, MTF cutoff, beam diameter, depth-of-focus, wavefront plot), **80 parametrized dispatcher pins across 3 sibling families** (the audit-meta-finding closure pattern), and 3 newly-discovered complex64 sibling-gaps caught by the new pins. 858 unit tests pass; 34/34 validation files pass. Both versions are on PyPI.

**However, this audit identifies one P0 silent-wrong-physics bug** in the v4.14.0 LG/HG mode-stack cache (the 77× perf win). The cache key includes `(p_max, ell_max, Ny, Nx, w, cx, cy, dtype_str)` but **NOT pixel pitch `dx, dy`**. Two calls with the same shape but different physical extent collide — the second call gets the FIRST grid's modes evaluated against the second call's field. **Silently wrong overlaps on any sweep that holds (N, w, cx, cy, p_max, ell_max) constant while changing pixel pitch.** Triggers: wavelength-adaptive grid, multi-resolution analysis, debugging at coarse vs fine.

**Plus 4 new P1s, 8 new P2s, and 4 doc/code drifts:**
- Aperture=0 semantics flipped in Multi*Merit (v4.14.0 regression): now means "no aperture" instead of "block all light"
- Brewster-angle phase aggregation bug in `coatings.py:237` (carried verbatim into wavelength batch)
- `_solve_envelope_stationary_batch` returns `converged=True` for failed pixels (contract violation; dead code so latent)
- `clear_lg_mode_stack_cache` not in top-level `__all__` (sibling-gap recurrence on the very release that closed sibling-gaps — **independently confirmed by V2, V4, F2**)
- Doc/code drift: CHANGELOG claims `_LG_MODE_STACK_CACHE` wired into `clear_asm_caches()` (FALSE — only `lumenairy_context(...)`); the 6 batched helpers are described as "consumed by the 77× warm win" but have **zero production consumers** (**independently confirmed by V2, F1, F3**); "16 tests at 1e-10 rel" is actually 3 tests in the cited class (**3-way confirmed**)

**P0 (silently-wrong physics) findings on the default path: 1** (the LG/HG cache-key collision).

**Verdict:** v4.14.0 should NOT be considered stable until the P0 cache-key bug is fixed (1-line fix: add `dx, dy` to the key tuple). The 1 P0 + 4 P1s + supporting CHANGELOG drift items justify a v4.14.1 patch release. The fundamental engineering remains sound; the perf wins, dispatcher-pin pattern, and 3 dtype sibling-gap closures are excellent work. The bugs found are all in adjacent areas the dispatcher pins did NOT cover.

## Part 2 — New findings (P0/P1/P2/P3)

### P0 — Silently-wrong physics (NEW in v4.14.0, fix before any further work)

#### P0-NEW-1 — `_lg_mode_conj_stack` / `_hg_mode_conj_stack` cache-key collision on different pixel pitch

**File:** `lumenairy/propagators/asymptotic.py:328-377` (LG), `:380-418` (HG)

**The 77× perf win is the bug surface.** Cache key is `(p_max, ell_max, Ny, Nx, w, cx, cy, dtype_str)`. It captures the **shape** `(Ny, Nx)` but NOT the **physical extent**. Two calls with same shape but different physical pitch (e.g., `dx=1e-6` then `dx=2e-6`, both at N=256) collide on this key.

**Failure mode:** the second call's `decompose_lg` / `decompose_hg` returns the FIRST grid's modes (built with the first call's `X, Y`) evaluated against the second call's field. **Silently wrong overlaps.** No error, no warning — just incorrect values.

**Triggering scenarios:**
- Wavelength-adaptive grid sweeps (re-pitch the grid per wavelength to keep `λ/dx` constant)
- Multi-resolution analysis (debug at coarse `dx`, then fine `dx` with same N)
- Optimization loops where `dx` is a free variable

**Fix:** Add `dx, dy` to the cache key tuple. ~2 LOC at the key-construction site. Or, more robust: include content hashes of `X[0,:]` and `Y[:,0]` (handles non-uniform grids too).

**Correctness pin recommendation:**
```python
def test_lg_mode_stack_cache_key_includes_pitch():
    # Build mode stack at dx=1e-6, then at dx=2e-6 (same N, same w, same cx, cy)
    # Confirm the second call returns DIFFERENT modes (i.e., didn't hit the stale cache)
```

### P1 — Latent bugs under specific input

#### P1-NEW-1 — Aperture=0 semantics flipped in Multi*Merit (v4.14.0 regression)

**File:** `lumenairy/optimize/core.py:2069-2072` (cache builder), `:2263-2266` (MultiWavelengthMerit), `:2427-2431` (MultiFieldMerit)

Pre-v4.14.0: `prescription['aperture_diameter']=0` produced an all-False (or single-pixel-True) mask → essentially zero field through `apply_real_lens`. Deliberate aperture=0 meant "block all light."

v4.14.0: `_get_wrapper_merit_cache` maps `ap <= 0` → `mask=None`; both callers route `mask is None` to "no clipping, full grid plane wave." **Semantics flipped 180°.**

**Triggering input:** optimization sweep over aperture diameter that includes 0, or a debug stub.

**Fix:** Return a sentinel from `_get_wrapper_merit_cache` that callers distinguish from `aperture is None`, OR keep the historical all-False mask for `ap == 0`.

#### P1-NEW-2 — Brewster-angle phase aggregation bug carried into wavelength batch

**File:** `lumenairy/elements/coatings.py:237`

```python
phase_r[:] = 0.5 * (np.angle(r_s) + np.angle(r_p))
```

`r_p` sign-flips through zero at Brewster (~56° for fused silica at visible). The unwrapped arithmetic average of two angles separated by ~π is off by π/2 (or π at the singularity).

The v4.13.1 audit Stream C flagged this. **v4.14.0's wavelength-batch rewrite inherited the bug verbatim.**

**Trigger:** any AOI within ~5° of Brewster.

**Fix:** Aggregate as `np.angle(0.5*(r_s + r_p))`, or compute s/p phases separately and return both.

#### P1-NEW-3 — `_solve_envelope_stationary_batch` returns `converged=True` for failed pixels

**File:** `lumenairy/propagators/asymptotic.py:2271-2376`

Docstring says: *"Pixels that fail (singular Hessian or non-finite update) carry the last finite iterate and `converged_mask=False`."*

But at line 2375 the code does `converged[idx[done & ~is_conv]] = True` to drop stalled/singular pixels from the active set — **violating the API contract**.

The function is currently dead code (no production callers — see F1+F3 finding below), so the impact is latent. Any future caller that trusts `converged_mask` will silently absorb failed iterates as successes.

#### P1-NEW-4 — `clear_lg_mode_stack_cache` not in top-level `__all__`

**File:** `lumenairy/__init__.py` (missing entry)

**Independently confirmed by V2, V4, F2** (3-way convergence — high-confidence finding).

CHANGELOG line 52: *"Public `clear_lg_mode_stack_cache()` for explicit flushes."*

Reality: present in `lumenairy/propagators/asymptotic.__all__` (line 125) but NOT imported into top-level `lumenairy/__init__.py`. The other 7 sibling cache-clears ARE all re-exported at top-level (lines 1345-1351). The CHANGELOG describes it as "Public" but `la.clear_lg_mode_stack_cache()` raises `AttributeError`.

Reachable via `from lumenairy.propagators.asymptotic import clear_lg_mode_stack_cache` (the agent_1 test uses this path), so it's technically public — but the discoverability story is broken.

**This is the v4.14.0 release's own sibling-gap recurrence** — the exact "fix N sites, miss N+1" meta-pattern the release was supposed to close with 80 dispatcher pins.

**Fix:** 2-line addition to `lumenairy/__init__.py`:
```python
from .propagators.asymptotic import clear_lg_mode_stack_cache
# ... and one entry in __all__
```

#### P1-NEW-5 — `maslov_tracking='row_reset'` doesn't reset `last_v_star`

**File:** `lumenairy/propagators/asymptotic.py:2539-2542`

The `row_reset` block resets `last_arg_detM` and `maslov_branch` at the start of each raster row but does NOT reset `last_v_star`. So even in `row_reset` mode, the warm-start chain crosses the raster row-wrap — which is the most plausible place to fall into a wrong basin (largest jump in `s2`, from `(s2x_max, s2y_n)` to `(s2x_min, s2y_{n+1})`).

This is the specific mechanism behind the v4.14.0 "wrong-saddle-basin" finding the team deferred to v4.15+. Either reset `last_v_star` at row wrap too, or document this explicitly. **Not mentioned in CHANGELOG.**

#### P1-NEW-6 — `encircled_energy_radius` docstring claim `ee[0] = 0 always` is false

**File:** `lumenairy/analysis/core.py:1145-1153`

`encircled_energy_curve` at line 1133-1145 returns `ee[0] = p_cum[0]` (intensity at the center pixel) when `radii_out[0]=0` collides with `r_sorted[0]=0`. The caller's `idx <= 0` short-circuit at lines 1228-1230 returns `radii[0]` (=0) when `threshold <= ee[0]` — physically reasonable, but the documented invariant is wrong.

**Trigger:** small thresholds with a hot center pixel.

### P2 — Code smells / fragile patterns

1. **3 new mutable caches without locks** — `_LG_MODE_STACK_CACHE` / `_HG_MODE_STACK_CACHE` (`asymptotic.py:303-304`); `_WRAPPER_MERIT_CACHE` (`optimize/core.py:1975`). Concurrent design_optimize threads can race on `OrderedDict.get` / `move_to_end` / `popitem(last=False)`. `_ASM_CACHE_LOCK` pattern in `propagation.py:792` is the right precedent.

2. **Memory-pressure ceiling on `_LG_MODE_STACK_CACHE`** — At p_max=3, ell_max=3, N=256, complex128: 28 modes × 256² × 16B ≈ 28 MB/entry × 32 = ~900 MB ceiling. At N=512: ~3.6 GB. At N=4096 (caching all wrapper-merit components): ~28 GB. Risk on optimizers that vary aperture as a free variable.

3. **Import-time monkey-patch fragility for `clear_asm_caches`** — `optimize/core.py:2117-2152` mutates `propagation.clear_asm_caches` to chain in `_clear_wrapper_merit_cache`. (a) If `optimize.core` is ever re-imported (test runner reload, `importlib.reload`), `_orig_clear_asm_caches` would grab the already-patched function — recursion risk. (b) `from lumenairy.propagators.propagation import clear_asm_caches` without importing `lumenairy.optimize` leaves the wrapper-merit cache resident.

4. **CHANGELOG says LG/HG mode-stack cache wired into `clear_asm_caches()` — FALSE.** README line 37-38 makes the same misclaim. Actual: only wired into `lumenairy_context(clear_caches_on_exit=True)` at `_context.py:286-293`. **Independently confirmed by V2, V4, F2.**

5. **6 batched helpers in `asymptotic.py` are dead production code** — `_solve_envelope_stationary_batch`, `_compute_M_b_batch`, `_phi_v2_hessian_batch`, `_gaussian_moment_table_2d_batch`, `_batched_polynomial_substitute_linear_2d`, `_batched_polynomial_under_affine_shift`. CHANGELOG line 87 + in-code comment at `asymptotic.py:2533` claim they're "consumed by the LG/HG mode-stack cache (the 77× warm win)." **FALSE.** `_lg_mode_conj_stack` / `_hg_mode_conj_stack` consume only `lg_polynomial`, `hg_polynomial`, `_evaluate_poly2d`. **Independently confirmed by V2, F1, F3.**

6. **5 of v4.13.2's `0.0+0.0j` sites NOT fully swept** — `lenses_maslov.py:448` (`sample_E_bilinear`) and `_lens_thin.py:173` (aplanatic branch) still have the literal. Output dtype contract is honored via final cast, but `precision='single'` perf intent is broken on intermediates.

7. **`_evaluate_polynomial_4d_and_grad34` lost the zero-coefficient skip** — `lenses.py:879-900`. Pre-v4.14 did `if c == 0.0: continue`; new `tensordot` form computes all terms unconditionally. Different rounding pathway than `_phi_v2_hessian_batch` (which explicitly preserves scalar order to keep the 1e-12 saddle-point pin). Probably fine here (eval site, not saddle) but the asymmetry is worth annotating.

8. **6 new analysis functions silently convert JAX arrays via `np.asarray(E)`.** `encircled_energy_curve` / `_radius` / `beam_diameter` / `mtf_cutoff` / `plot_wavefront` all use `np.arange` / `np.meshgrid`. JAX inputs get silent host transfer. Either document as NumPy-only or raise on non-NumPy input.

9. **TestP1CSourceFactoryDispatcherPin still excludes `fiber_mode`** with stale comment — v4.13.2 fixed `create_fiber_mode` to accept `dy=` but the parametrize list wasn't updated. CHANGELOG v4.13.2 lines 386-388 incorrectly claim "covers all 6 factories" — actually 4 of 5. **Independently confirmed by V5 and F2.**

10. **Tournament-reduction ULP divergence** in coating wavelength batch — pre-v4.13.0 had sequential `M @= Mj` accumulation; v4.13.0 introduced tournament reduction (~ULP × matmul fan-out); v4.14.0 multiplies the divergence by `n_wv`. For 50-layer HR coatings the difference can reach a few ULP. Not a regression (tournament was in v4.13.0) but the new path amplifies it.

### P3 — Minor

1. **CHANGELOG "16 tests at 1e-10 rel" overstated** (actual 3 in the cited class, 16 in the file). **Independently confirmed by V2, F3, F2.**
2. **HG cache key documented as `w[s]` shorthand**; actual implementation has 9-element key with both `wx` AND `wy`. Cosmetic.
3. **Scalar vs 0-D ndarray aperture cache fragmentation** — `optimize/core.py:1992-2000`. `np.array(1e-3)` (0-D ndarray) lands in ndarray branch with `tobytes()` hash; Python `float(1e-3)` lands in scalar branch. Two cache buckets for identical numerics.
4. **`MultiFieldMerit._scalar_warning_issued` is class-level** — blocks per-test isolation (intentional "fire once per process").
5. **`mtf_cutoff` returns `f_arr[0]` when MTF[0] < threshold** — unreachable in clean inputs (MTF(0)==1 by convention) but documented as `+inf`. Edge-case intent vs implementation drift.
6. **`encircled_energy_curve` Python loop at `analysis/core.py:1136-1145`** does per-radius interpolation in Python; for `n_radii=64` (default) dominates over `O(N log N)` sort. `np.interp(radii_out, r_sorted, p_cum)` one-liner is faster.
7. **CHANGELOG cites lines 562, 663, 828, 970 in `lenses_maslov.py`**; actual lines are 566, 624, 733, 880, 989 (4-10 line drift from comment additions during landing).
8. **`apply_real_lens` calls inside Multi*Merit omit `dy`** — pre-existing limitation. The cache builder accepts `dy=dx` implicitly but the wrapper merits still assume square grids end-to-end.

## Part 3 — Modal asymptotic deferral physics finding (Stream F3 deep dive)

The v4.14.0 CHANGELOG defers the public modal asymptotic per-pixel vectorisation to v4.15+, citing a "wrong-saddle-basin" finding. F3's targeted physics audit found:

### What's correct

- ✅ Multi-saddle integrand: physically real (5th-degree polynomial system in `(v2x, v2y)`; up to 25 complex roots)
- ✅ Warm-start can land in wrong basin: physically real (Newton domain-of-attraction is initial-guess-dependent)
- ✅ Overflow guard `|b_quad.real| > 700` is the right magnitude (`exp(700) ≈ 1e304`, just below float64 realmax)
- ✅ Deferring the public switch is the right call

### What's over-stated in the CHANGELOG

- ❌ **"Cold-start finds the physical saddle uniformly"** — over-stated. Cold-start from `(v_cx, v_cy)` selects the basin containing the **pupil centre**. For pixels well off the chief-ray landing, the physical saddle may NOT lie in that basin. Newton can then converge to: (a) the physical saddle, **(b) a different saddle yielding finite-but-wrong `b_quad` (NOT triggering the `>700` guard) — silent-wrong-physics**, or (c) stalls. Outcome (b) is the dangerous one. Neither path has Hessian-eigenvalue saddle classification.

- ❌ **"Helpers consumed by the LG/HG mode-stack cache (77× warm win)"** — FALSE. The 6 helpers have **zero production consumers**. Dead code shipped privately. **3-way confirmed (V2 + F1 + F3).**

- ❌ **"16 tests at 1e-10 rel"** — actual 3 tests in the cited class, 16 in the file. **3-way confirmed.**

### NEW physics findings from F3

- **`row_reset` doesn't reset `v_star`** (now P1-NEW-5 in Part 2)
- **Existing pins are interior-pixel only** — grids `L*0.3` from center, well inside source box. The "wrong-saddle at grid-edge" behaviour by definition is NOT exercised. So the existing pin **would not be broken by switching to cold-start at all** on these grids. The v4.15 fix can probably ship with only a tolerance loosen rather than the "coordinated test-pin update" the CHANGELOG implies.
- **Sibling propagators inherit the issue silently** — `propagate_subaperture_asymptotic`, `propagate_hf_*` with `method='asymptotic'`, and JAX paths (`solve_envelope_stationary_jax_ift`, `propagate_modal_asymptotic_lg00_jax`) all route through `propagate_modal_asymptotic`. **Not mentioned in CHANGELOG.**

### Recommended for v4.15

1. Write a deliberate edge-pixel test against direct-quadrature ground truth (`propagate_hf_chebyshev_quadrature` with `method='direct'`); the path that agrees wins
2. Add saddle classification to `_solve_envelope_stationary_batch` (Hessian positive-definite check at convergence)
3. Consider multi-start or homotopy continuation for off-axis pixels
4. Propagate the fix to siblings (subaperture, hf_chebyshev asymptotic mode, JAX paths)
5. Either wire the 6 helpers into production OR remove them until v4.15
6. Fix CHANGELOG: 3 tests not 16; helpers NOT consumed by mode-stack cache

## Final verdict

**v4.14.0 ships substantial perf wins, a major API expansion, and the right structural pattern (parametrized dispatcher pins) to close the historic "fix swept N sites, missed N+1" meta-finding within three named sibling families.** 858 unit tests + 314 validation tests pass. v4.14.0 is on PyPI. Zero breaking changes.

**However, the 77× LG/HG mode-stack cache has a silent-wrong-physics bug** in the cache key (missing `dx, dy`). This is a P0 finding — the only P0 across 8 audit streams, but it affects a perf-win path users will actively exercise. Users running multi-resolution analysis or wavelength-adaptive grids will silently get wrong answers.

**v4.14.1 is warranted** to close P0-NEW-1 (cache key), P1-NEW-1 (aperture=0 regression), P1-NEW-2 (Brewster bug), P1-NEW-4 (`clear_lg_mode_stack_cache` top-level export), and the supporting CHANGELOG corrections. Total fix surface: ~15 LOC code + ~5 LOC docs + ~5 short tests.

The fundamental engineering remains sound; v4.14.0's 80 dispatcher pins are a genuine improvement that caught 3 sibling-gaps before ship. The remaining work is well-scoped and small.
